## 0. 总览

一句话:服务端把「一个域的节点 + 域内边 + 别名」一次算成白名单 DTO;前端把 DTO 画成 canvas 力导向图,收敛即停,交互(悬停/点选/平移/缩放)全部在 canvas 世界坐标上做,DOM 只负责详情卡、图例、域选择器与降级文案。

```
┌─ 前端 ──────────────────────────────────────────────┐
│ #/graph (app.js ROUTES)                             │
│   ├─ assets/views/graph.js        DOM 壳 + canvas + 交互 + dispose │
│   └─ assets/views/graph-layout.js 纯力学模块(零 DOM,node 可 import)│
│               ↑ ctx.api.graph(q)  ← app.js get() 自动注入 ?db=      │
└──────────────┬──────────────────────────────────────┘
               │ GET /api/graph?domain=&limit=
┌─ 服务端 ─────▼──────────────────────────────────────┐
│ routes.ts getGraph(只读 SQL,§16.6 先例)             │
│   └→ serialize.ts GraphDTO 白名单转换器              │
└─────────────────────────────────────────────────────┘
```

设计原则(全部有出处,不新造):

| 原则 | 出处 |
|---|---|
| DTO 必须显式 `to*DTO`,禁止透传 | 00-context §1;serialize.ts:8-10(冻结规则 2) |
| 读路径可直接查库(routes 层内联只读 SQL) | routes.ts:5-8 文件头;先例 `getMeta`(routes.ts:205-240)、`getAudit`(routes.ts:549-556) |
| 不往 store 层写业务 | 00-context §4;本文 0 条写 SQL |
| 未知 domain 是合法空结果而非 404 | getTree 先例 routes.ts:257-262 |
| store 异常只在 dispatch 一处被捕获 | routes.ts:113-122 注释;库锁→409 已有映射 routes.ts:139-142 |
| 视图 `mount(el, params, ctx) → dispose` 契约 | app.js:462-463(mountRoute)、databases.js:262-313、audit.js:214-224 |
| 纯模块不得有顶层 DOM 副作用 | 00-context §2.6;url.js 判据 `node -e import`(multi-db-url.test.js:7-11) |
| 收敛即停、dispose 全清 | 00-context §4;rAF 纪律见本文 §3.5/§3.9 |

## 1. 现状与依据

### 1.1 服务端

- **路由表**:`ROUTES: RouteDef[]`(routes.ts:1319-1345),精确路径匹配,`GET` 11 行 + `POST` 10 行;管理路由**追加在表尾**并有注释钉住「git diff 只显示 +3 -0」(routes.ts:1341-1342)——本设计新增的 `/api/graph` 行**插在 GET 块内**(`/api/events` 行之后),不碰表尾,保持该注释语义成立(diff 变为 +2 -0:一行路由 + 一个 handler)。

- **错误码闭集**:七个,routes.ts:47-55。图谱不引入新码(见 §2.6 错误路径)。
- **数据表**:
  - `nodes`:schema.ts:24-45(`uri TEXT NOT NULL UNIQUE`,L31;`importance INTEGER NOT NULL DEFAULT 5`,L33;`is_stub INTEGER NOT NULL DEFAULT 0`,L43;`idx_nodes_domain`,L47)。
  - `edges`:schema.ts:71-75,`PRIMARY KEY (node_id, target_uri)`,`kind TEXT` 可空,`disclosure TEXT`;`idx_edges_target ON edges(target_uri)`(schema.ts:76)。**没有** domain 列——边的域 = 源节点的域。
  - `aliases`:schema.ts:78-82,`alias_uri TEXT PRIMARY KEY, target_node_id TEXT NOT NULL, disclosure TEXT`。
- **可复用的 store 只读方法**(store.ts):
  - `listNodes({domain})`(store.ts:1438-1445):`SELECT * FROM nodes [WHERE domain = ?] ORDER BY created_at` → 图谱模式的节点来源,**零新 SQL**。
  - `listDomains()`(store.ts:1459-1463):`SELECT DISTINCT domain … ORDER BY domain` → 域清单骨架。
  - `resolveUri(uri)`(store.ts:218-226):**nodes.uri 优先、aliases 次之**的解析语义——图谱的边解析必须复制这个优先级(见 §2.4),不能只查 nodes。
  - `getWorldTime()`(store.ts:1355-1357)。
  - `aliasListStmt`(store.ts:193-203):`dead` 的权威谓词 = `LEFT JOIN nodes shadow ON shadow.uri = a.alias_uri … shadow.node_id IS NOT NULL AS dead`。**逐节点**,不能直接复用于全图;但其谓词语义被 §2.4 的集合版查询逐字继承。
  - `listRelated(nodeId)`(store.ts:932 起)是**逐节点**的邻接查询,N 个节点要 N 次查询,图谱禁用(N+1 同款禁忌);全量边读取的先例是 `export()`(store.ts:1485-1487):`SELECT node_id, target_uri, kind, disclosure FROM edges ORDER BY node_id, target_uri`。
- **`visibilityFor` / shadowed**(runtime.ts:38-51,visibility.ts):图谱**刻意不接**。契约的 GraphNodeDTO(00-context §4)没有 `shadowed` 字段;树视图也不排除 shadowed 节点而只是打标(tree.js `shadowedChip`,tree.js:55-58)。图谱是结构视图,排除节点会画出一张「看起来完整但被静默过滤过」的图,违反「从不静默过滤」纪律(tree.js:526 `renderStatus` 注释)。
- **`meta` 已有的全库计数**(routes.ts:226-240)证明 routes 层内联 `COUNT(*)` 是既定做法。

## 2. 服务端设计

### 2.1 端点与两种模式

```
GET /api/graph                 → 域清单模式(契约 §4:无 domain 返回域清单 + 每域节点数)
GET /api/graph?domain=&limit=  → 图谱模式(一个域的节点/边/别名)
```

- `domain`:`string | null`。`null` 或 `""` → 域清单模式;非空 → 图谱模式。**不做** `domain=*` 全库模式(§8 非目标,含理由与未来扩展位)。
- `limit`:`intOrThrow(sp, "limit", { min: 1, max: 500, def: 200 })`(routes.ts:190-200 同款)。**默认 200**,理由:
  - elias 实测库 125 节点/5 域 ⇒ 单域中位数 ≈ 25,200 的默认值意味着**默认从不截断**正常库;
  - 500 上限同时是前端力学的性能预算上界(O(N²) 斥力在 N=500 时 125k 对/帧,§3.3 证明可行);
  - 500 与 `getTree` 的 limit 上限(routes.ts:247)同量级,不给用户「有的页 500 有的页 5000」的不一致感。
- 两种模式都带 `world_time`(状态栏通用件,MetaDTO 先例)。

### 2.2 DTO 定义(serialize.ts,白名单)

契约骨架字段**逐字保留**,细化点用 ⚠︎ 标出并在 §2.8 对照。

```ts
// ── Graph(plan/memory-web-redesign/00-context.md §4)──────────────────────

/** 域清单模式的一行:选域卡片的数据。 */
export interface GraphDomainDTO {
	domain: string;
	/** 域内节点总数(stub 含在内——stub 也是图上的节点)。 */
	node_count: number;
	/** ⚠︎ 细化:以该域节点为**源**的边数。选域时「哪个域有内容」的第二判据。 */
	edge_count: number;
}

/** 域清单模式响应(无 domain)。 */
export interface GraphDomainsDTO {
	mode: "domains"; // ⚠︎ 细化:判别字段,两模式共/response 一个稳定判别式
	world_time: string | null;
	domains: GraphDomainDTO[];
}

/** 图谱节点。字段集 = 契约 §4 骨架,一个不多一个不少。 */
export interface GraphNodeDTO {
	node_id: string;
	uri: string;
	domain: string;
	importance: number;
	is_stub: boolean;
	/** = uri 末段。服务端算(§2.5),语义 = tree.js:64-67 的 lastSegment。 */
	label: string;
	/** 域根为 null。来自 parent_id → uri 的解析,**不是**表列。 */
	parent_uri: string | null;
}

/** 图谱边。契约骨架 4 字段 + ⚠︎ target_uri 一个细化字段。 */
export interface GraphEdgeDTO {
	source_id: string;
	/** dangling(解析不到任何活节点/活别名)时为 null。 */
	target_id: string | null;
	kind: string | null;
	dangling: boolean;
	/** ⚠︎ 细化:原始 `edges.target_uri`(可能是别名 uri)。悬停提示与详情卡需要「指向哪」。 */
	target_uri: string;
}

/** 图谱别名(挂在本域节点上的别名地址)。字段集 = 契约 §4 骨架。 */
export interface GraphAliasDTO {
	alias_uri: string;
	target_node_id: string;
	/** 语义同 AliasDTO.dead(serialize.ts:117-130):alias_uri 同时是活 nodes.uri。 */
	dead: boolean;
}

/** 图谱模式响应(带 domain)。 */
export interface GraphDataDTO {
	mode: "graph";
	world_time: string | null;
	/** 回显请求的域,前端状态确认用。 */
	domain: string;
	/** 域内节点总数(limit 之前)——截断提示的分母。 */
	total_nodes: number;
	/** total_nodes > nodes.length 时 true,前端必须显式提示(大库保护)。 */
	truncated: boolean;
	nodes: GraphNodeDTO[];
	edges: GraphEdgeDTO[];
	aliases: GraphAliasDTO[];
}

export type GraphResponseDTO = GraphDomainsDTO | GraphDataDTO;
```

转换器(同文件,纯函数,行数极短但**必须存在**——冻结规则 2「禁止 `{...node}` 透传」,serialize.ts:8-10):

```ts
/** 语义 = tree.js lastSegment(tree.js:64-67):末段,尾空段回退整串。 */
export function graphLabel(uri: string): string {
	const s = String(uri ?? "");
	const i = s.lastIndexOf("/");
	return i === -1 ? s : s.slice(i + 1) || s;
}

export function toGraphNodeDTO(n: MemoryNode, parentUri: string | null): GraphNodeDTO {
	return {
		node_id: n.node_id,
		uri: n.uri,
		domain: n.domain,
		importance: n.importance,
		is_stub: n.is_stub === 1, // ⭐ 0/1 列 → boolean,口径同 toNodeDTO(serialize.ts:358)
		label: graphLabel(n.uri),
		parent_uri: parentUri,
	};
}

export function toGraphEdgeDTO(
	row: { node_id: string; target_uri: string; kind: string | null },
	targetId: string | null,
): GraphEdgeDTO {
	return { source_id: row.node_id, target_id: targetId, kind: row.kind, dangling: targetId === null, target_uri: row.target_uri };
}

export function toGraphAliasDTO(row: { alias_uri: string; target_node_id: string }, dead: boolean): GraphAliasDTO {
	return { alias_uri: row.alias_uri, target_node_id: row.target_node_id, dead };
}
```

`parentUri` 由调用方**传入**而非转换器内查库——与 `toTreeNodeDTO` 的 `disclosure` 同款哲学(serialize.ts:588-593 注释:「把『每页数据来自同一来源』做成结构事实而不是约定」),也顺手避免了 `parentUriOf`(serialize.ts:373-377)每节点一次 `getNode` 的 N+1。

### 2.3 getGraph handler(实现级设计)

落点:routes.ts,`GET handlers` 区(`getEvents` 之后,routes.ts:319 附近的区尾)。签名与全部 GET handler 一致:`function getGraph(rc: RequestCtx): HandlerResult`。

```ts
const GRAPH_LIMIT = { min: 1, max: 500, def: 200 };

function getGraph(rc: RequestCtx): HandlerResult {
	const { store } = rc.ctx;
	const sp = rc.url.searchParams;
	const worldTime = store.getWorldTime();

	// ── 模式一:域清单(无 domain)───────────────────────────────────────
	const domain = sp.get("domain");
	if (domain === null || domain === "") {
		// 每域节点数。listDomains() 只有 DISTINCT(store.ts:1459-1463),不带计数,
		// 这里一条 GROUP BY 直接拿全(getMeta 的 countOf 同款 routes 层内联先例)。
		const nodeRows = store.db
			.prepare("SELECT domain, COUNT(*) AS c FROM nodes GROUP BY domain ORDER BY domain")
			.all() as Array<{ domain: string; c: number }>;
		// 每域「以本域节点为源」的边数。edges 无 domain 列,JOIN 源节点取域。
		const edgeRows = store.db
			.prepare(
				"SELECT n.domain AS domain, COUNT(*) AS c FROM edges e JOIN nodes n ON n.node_id = e.node_id GROUP BY n.domain",
			)
			.all() as Array<{ domain: string; c: number }>;
		const edgeByDomain = new Map(edgeRows.map((r) => [r.domain, r.c]));
		const body: GraphDomainsDTO = {
			mode: "domains",
			world_time: worldTime,
			domains: nodeRows.map((r) => ({
				domain: r.domain,
				node_count: r.c,
				edge_count: edgeByDomain.get(r.domain) ?? 0,
			})),
		};
		return { status: 200, body };
	}

	// ── 模式二:图谱(带 domain)────────────────────────────────────────
	const limit = intOrThrow(sp, "limit", GRAPH_LIMIT);

	// ① 一次轻量全表索引:uri/node_id/parent_id。三条用途:
	//    a) parent_id → uri(parent_uri,取代逐节点 parentUriOf 的 N+1);
	//    b) 全库 uri 集合(dead 别名谓词,= aliasListStmt 的 shadow JOIN,store.ts:193-203);
	//    c) uri → node_id 的**规范**解析表(边解析第一优先级,= resolveUri 的 byUriStmt,store.ts:219)。
	//    只取三个瘦列,不拖 content——content 是 fat 列,全表拖它在万节点库上是浪费。
	const indexRows = store.db.prepare("SELECT node_id, uri, parent_id FROM nodes").all() as Array<{
		node_id: string;
		uri: string;
		parent_id: string | null;
	}>;
	const uriOf = new Map(indexRows.map((r) => [r.node_id, r.uri])); // node_id → uri
	const nodeIdOf = new Map(indexRows.map((r) => [r.uri, r.node_id])); // uri → node_id(规范)

	// ② 本域节点,按 importance DESC、uri ASC 排序后截断。
	//    理由:截断(若有)应该先丢最不重要的(半径∝importance,画出来的是最重要的);
	//    uri ASC 是确定性 tiebreak——同 importance 的截断边界在两次请求间稳定,
	//    前端 memory:changed 热更新时「哪些点在场」才不会抖动。
	const domainNodes = store.listNodes({ domain }); // 复用 store 只读方法(store.ts:1438-1445)
	domainNodes.sort((a, b) => b.importance - a.importance || (a.uri < b.uri ? -1 : a.uri > b.uri ? 1 : 0));
	const nodes = domainNodes.slice(0, limit);
	const inSet = new Set(nodes.map((n) => n.node_id));

	// ③ 别名全表(瘦列),建 uri → target 的**别名**解析表(第二优先级)。
	const aliasRows = store.db.prepare("SELECT alias_uri, target_node_id FROM aliases").all() as Array<{
		alias_uri: string;
		target_node_id: string;
	}>;
	const aliasIdOf = new Map(aliasRows.map((r) => [r.alias_uri, r.target_node_id]));

	// ④ 边全表(= export() 同款 SQL,store.ts:1486),集合内分类。
	const edgeRows = store.db
		.prepare("SELECT node_id, target_uri, kind FROM edges ORDER BY node_id, target_uri")
		.all() as Array<{ node_id: string; target_uri: string; kind: string | null }>;
	const edges: GraphEdgeDTO[] = [];
	for (const row of edgeRows) {
		if (!inSet.has(row.node_id)) continue; // 源不在本域截断集 → 与本图无关
		// 解析优先级 = resolveUri(store.ts:218-226):先 nodes.uri,后 aliases。
		const target = nodeIdOf.get(row.target_uri) ?? aliasIdOf.get(row.target_uri) ?? null;
		if (target === null) {
			edges.push(toGraphEdgeDTO(row, null)); // dangling:谁也解析不到
		} else if (inSet.has(target)) {
			edges.push(toGraphEdgeDTO(row, target)); // 域内边
		}
		// else:解析到了集合外(跨域节点,或被 limit 截掉的本域节点)→ 不画。
		// 「指向截掉节点」的边若画出来,端点悬空会与 dangling(真悬空)混淆语义。
	}

	// ⑤ 别名:只收目标在本域截断集内的;dead 谓词逐字继承 aliasListStmt
	//    (store.ts:193-203):alias_uri 同时是活 nodes.uri ⇔ nodeIdOf.has(alias_uri)。
	const aliases = aliasRows
		.filter((r) => inSet.has(r.target_node_id))
		.map((r) => toGraphAliasDTO(r, nodeIdOf.has(r.alias_uri)));

	const body: GraphDataDTO = {
		mode: "graph",
		world_time: worldTime,
		domain,
		total_nodes: domainNodes.length,
		truncated: domainNodes.length > nodes.length,
		nodes: nodes.map((n) => toGraphNodeDTO(n, n.parent_id ? (uriOf.get(n.parent_id) ?? null) : null)),
		edges,
		aliases,
	};
	return { status: 200, body };
}
```

设计裁定(为什么是这几条 SQL、为什么这样组织):

1. **`listNodes({domain})` 复用 + 三条瘦列内联 SQL**。契约 §4:「走既有 store 只读方法或新增只读查询,不写 store 层业务」。节点走既有方法;`parent_id→uri` 映射、`dead` 谓词的集合版、边/别名全表在 store 里没有现成方法——为它们各加一个 store 方法是给「一次性读模型」在长期存活的 store API 面上开洞,而 routes.ts 文件头(routes.ts:5-8)明确允许读路径直接查库,`getMeta`(routes.ts:226-240)与 `export()` 的调用方已经这么干。**store.ts 一行不改**。
2. **不用 `listRelated` 循环**。它是逐节点查询(store.ts:932),N 次 prepare+all 正是全站处处防的 N+1(serialize.ts:640-648 `buildChildCounts` 的注释、「多库 N+1 禁令」00-context §2.7 同源)。全表一次 + JS 里 Map 连接,在 500 节点/约 1000-3000 边的量级上是毫秒级。
3. **`total_nodes`/`truncated` 用内存计数**,不额外发 `COUNT(*)`:第②步的 `domainNodes.length` 就是,零成本。
4. **排序与截断在 JS**(`sort` + `slice`),不写 `ORDER BY importance LIMIT ?`:数据已经整域取回(②),再让 SQL 排一次是重复劳动;JS 侧 `b.importance - a.importance || uri 比较` 的复合键也表达得比 SQL 清楚。
5. **自环**(源 = 目标,addEdge 不禁止,schema.ts:73 的 PK 允许):第④步照常输出(`target === source ∈ inSet`),力学里跳过、渲染画小环(§3.6/§3.7)。数据层不做特判——图谱如实反映库。
6. **不带别名 disclosure**:GraphAliasDTO 不带 `disclosure`,这是契约骨架的裁剪——图谱页只回答「这个节点有哪些地址、死活」,想起条件属于节点页(`/api/node` 的 `toAliasEntryDTOs`,serialize.ts:508-516)。详情卡点「打开节点页」后自然看到。

### 2.4 边解析与 dangling 的精确语义(实现者必读)

| `edges.target_uri` 的情况 | 判定 | 输出 |
|---|---|---|
| 是本域截断集内某节点的 uri | 域内边 | `{target_id, dangling:false}` |
| 是**别名**,别名指向截断集内节点 | 域内边(解析落点) | `{target_id: 别名目标, dangling:false}`;`target_uri` 保留原别名 uri |
| 是别名列指向已删节点 / 无中生有的 uri | **dangling** | `{target_id:null, dangling:true}` |
| 是本域节点但被 limit 截掉 | 跳过 | 不输出(端点不存在于图上) |
| 是其他域的节点 | 跳过 | 不输出 |

这个表与 `EdgeDTO.dangling` 的既有定义(serialize.ts:96-99:`dangling ⇔ resolveUri 为 null`)语义一致,只是把「域内截断/跨域」两个新情况显式裁定为「跳过」。测试 §6.1 对每一行各有一条用例。

**为什么 dangling 边要保留在响应里**:它是最有诊断价值的信号之一——「这条边指向一个不存在的地址」,库健康视图(`MEM://diagnostic`)之外最直观的呈现位。前端画成灰色短须(§3.7),不占力学。

### 3.2 graph-layout.js API

```js
// graph-layout.js —— 纯模块。坐标一律世界坐标(px),y 向下,与 canvas 一致。

export const LAYOUT = Object.freeze({
	REPULSION: 24000, // 斥力:F_rep = REPULSION / d²(alpha 已乘);孤立点平衡距 d_eq=(REP/GRAVITY)^(1/3)≈93px
	SPRING_K: 0.06,   // 弹簧:F_s = (d - SPRING_LEN) * SPRING_K
	SPRING_LEN: 90,   // 弹簧自然长度
	GRAVITY: 0.03,    // 向心:F_g = GRAVITY * d(指向当前质心,不是固定画布中心——拖动整图不回弹)
	DAMPING: 0.85,    // 速度衰减(半隐式欧拉)
	MAX_STEP: 14,     // 单迭代位移上限,防近距斥力爆炸
	MIN_DIST: 1,      // 斥力分母下限
	ALPHA0: 1,
	ALPHA_DECAY: 0.99, // 每迭代乘子
	ALPHA_MIN: 0.02,   // 硬冷却下限:ln(0.02)/ln(0.99)≈390 次内必停
	STOP_DISP: 0.5,    // maxDisp < 0.5px 视为「这一步没动」
	STOP_FRAMES: 3,    // 连续 3 步没动 → 收敛(抖动过滤)
	MAX_ITERS: 400,    // 迭代硬上限
});

/** 初始布局:黄金角螺旋(确定性;i=0 在原点)。 */
export function initialPositions(count, width, height) /* → [{x,y}] */;

/** 一次迭代。返回本步 maxDisp(px)。positions 与 nodes 同序。自环边(source===target)被跳过。 */
export function stepLayout(positions, nodes, edges, opts = LAYOUT, alpha = 1) /* → number */;

/**
 * 跑到收敛。initial 传入时从它继续(memory:changed 热更新 / 拖完再收敛),否则螺旋起步。
 * 返回 { positions, iterations, converged }。count===0/1 时 iterations===0 直接返回。
 */
export function runLayout({ nodes, edges, width, height, initial }) /* → { positions, iterations, converged } */;
```

`nodes: [{id}]`,`edges: [{source, target}]`(仅**域内边**;dangling 短须与 alias 别针不进力学,§3.7)。id → 下标的 Map 在 runLayout 内部建一次。

### 3.3 力学与收敛:参数表与预算

每迭代(α 为当前 alpha):

| 力 | 公式 | 量级感(N=125,平衡态) |
|---|---|---|
| 斥力(两两,O(N²)) | `F = REPULSION / max(d, MIN_DIST)² × α`,沿连线推开 | d=90 时 ≈ 3.0 |
| 弹簧(O(E)) | `F = (d - 90) × SPRING_K × α`,拉向自然长 | 伸长 50px 时 ≈ 1.8 |
| 向心(O(N)) | `F = GRAVITY × d_to_centroid × α` | 距心 300px 时 ≈ 2.7 |
| 积分 | `v = (v + F) × DAMPING;Δ = clamp(v, MAX_STEP);p += Δ` | — |

- **孤立分量平衡距** `d_eq = (REPULSION/GRAVITY)^(1/3) ≈ 93px`:断连的孤点/小岛自然排成距质心约一个弹簧长的环带,不会飞出视野,也不需要特判连通分量。
- **收敛判据(三重或)**:`(连续 STOP_FRAMES 步 maxDisp < STOP_DISP)` ∨ `α < ALPHA_MIN` ∨ `iterations ≥ MAX_ITERS`。收敛后 **rAF 循环退出**(§3.5),CPU 归零——这是契约 §4「不空转烧 CPU」的实现点。
- **预算**:N=125 → 7.7k 对(无序对)/帧,每帧斥力 <1ms,收敛典型 120-250 迭代(2-4s @60fps,期间完全可交互);N=500 → 125k 对/帧 ≈ 2-4ms/帧,60fps 仍稳。**Barnes-Hut 四叉树明确不做**(§8):500 上限让它永远是负优化。
- **确定性**:`initialPositions` 黄金角螺旋 + 输入序遍历 + 无随机数 ⇒ 同一 DTO 两次 `runLayout` 产出逐位相同的 positions。这是 §6.2 断言「同输入同输出」与「收敛」的前提,也保证刷新页面图不换样。
- **reduced-motion**:`matchMedia("(prefers-reduced-motion: reduce)")` 命中时,`runLayout` 同步跑完(有 MAX_ITERS 封顶,≤500 节点最坏 <400ms,一次性成本),画一帧,不进动画循环。交互(拖/缩放)照常,只是没有过渡动画。

### 3.5 渲染循环、devicePixelRatio 与 resize

```
requestDraw()   —— 惰性单帧:无在途 rAF 时 requestAnimationFrame(一帧重绘)。
                   收敛后的常态:任何交互/hover/resize 只触发它,循环不复活。
simLoop()       —— sim.running 时:每帧 stepLayout 一次 → 重绘 → 判收敛;
                   收敛 → sim.running=false,补一帧最终画面,循环退出(不空转)。
```

- **DPR**:`resizeCanvas()` 读 `host.clientWidth/Height`(CSS 尺寸)与 `window.devicePixelRatio`(封顶 3,防 4K+浏览器缩放下显存翻倍);`canvas.width = round(cssW×dpr)`、`canvas.height = round(cssH×dpr)`;canvas 用 CSS 铺满容器。绘制前 `ctx.setTransform(dpr, 0, 0, dpr, 0, 0)` 把 DPR 折进变换,之后所有绘制按 CSS 像素思考——这是「125 节点在 2x 屏上不发虚」的唯一要点。
- **世界变换**:屏幕 = `world × scale + (tx, ty)`。绘制:`ctx.translate(tx, ty); ctx.scale(scale, scale)` 后画形状;**文字单独特pass**:重置回 `setTransform(dpr,…)`,用算好的屏幕坐标画标签——标签始终保持 11px 屏幕尺寸,不会缩放时忽大忽小。
- **resize**:`ResizeObserver(host)` → `resizeCanvas()` → 首次(还没有用户视角时)`fitView()`(positions 包围盒 → 居中、`scale = clamp(0.9×min(W/bw, H/bh), 0.15, 1.5)`);之后**保持用户视角**只换画布尺寸 → `requestDraw()`。RO 在 dispose 里 `disconnect()`。
- **主题换色**:取色函数读 `getComputedStyle(document.documentElement)` 的 01 token(含 `--mw-dom-1..10`,读法 01-设计系统.md:251)并缓存;两个失效源:`MutationObserver(documentElement, { attributes:true, attributeFilter:["data-theme"] })`(手动 light/dark,即 01 §5.3 的自持方案,壳不加职责)与 `matchMedia("(prefers-color-scheme: dark)").addEventListener("change", …)`(auto)。两者监听都进 `signal`。取色命中不到变量时回退字面量(canvas 的 fillStyle 容错)。

### 3.8 取数、模式分支与大库保护

```
fetchData():
  gen += 1; const my = gen;
  const dto = await ctx.api.graph(state.domain ? { domain: state.domain, limit: state.limit } : {});
  if (my !== gen || disposed) return;           // ⭐ 在途守卫:慢响应不覆盖新状态(get() 无外部 signal 的补偿,§3.9)
  state.data = dto;
  dto.mode === "domains" ? renderDomainPicker(dto) : buildGraph(dto);
```

**域清单模式**(无 domain,首访默认):渲染选域卡片列表——每行 `域名 · N 节点 · M 边`,点击 → `state.domain = d; fetchData()` + `history.replaceState(null, "", "#/graph?domain=" + encodeURIComponent(d))`(**replaceState 而非 navigate**:不触发 hashchange 重挂、布局不闪;URL 保持可分享。boot 里的 replaceState 先例 app.js:826-827)。卡片渲染走 `el()/textContent`。

**图谱模式**:

1. `edges.filter(两端都在)` → `[{source, target}]` 喂 `runLayout`(自环已被 layout 跳过);
2. `buildAdjacency()`(悬停高亮 + 详情卡度数共用);
3. 首次:`initialPositions` → `simLoop()`;`memory:changed` 热更新:旧 positions 按 node_id 继承,新点质心附近螺旋补位 → `runLayout({initial})` 复热重收敛(图不跳变);
4. **大库保护三件套**(工具条,全 DOM):
   - 域切换 `select`(与侧栏同源数据,切换行为同上);
   - limit `select`(100/200/500,当前值高亮);
   - **截断提示条**:`truncated === true` 时显示「本域共 {total_nodes} 个节点,当前显示前 {nodes.length} 个(按重要度优先)。调大上限或选择更具体的域。」——服务端给了分母,提示是**义务**(「从不静默过滤」,tree.js:526 同纪律);
   - 状态行:`{nodes.length} 节点 · {edges.length} 边 · {aliases.length} 别名 · 世界时间 {world_time}`。

### 3.9 刷新与 dispose 纪律(逐项)

| 生命周期事件 | 处置 |
|---|---|
| `memory:changed`(编辑页改完/别处写入) | `ctx.on("memory:changed", onMemoryChanged)` → `fetchData()`(保位置热收敛,§3.8);dispose 里 `ctx.off`。注意壳在下次挂载前会统一 unbind(app.js:424-428),显式 off 是防御同一 tick 内的迟到事件 |
| 切库 | `reloadAll` → 重挂路由(app.js:559-564)⇒ 走 mount 全新流程,图谱零参与,天然正确 |
| 在途 fetch 时 dispose | `get()` 不支持外部 AbortSignal(app.js:159-186,只有 `timeoutMs`)——**不改共享层**(改动属 D2 的 get() 签名演进,已在 §7 交接),用 generation 守卫:迟到响应落到 `my !== gen` 上被丢弃,无状态写入、无 DOM 挂载,闭包随 dispose 可回收 |
| rAF | sim 收敛即停;dispose `cancelAnimationFrame`;`requestDraw` 的单帧 rAF 用同一个句柄字段,幂等取消 |
| 事件 | 全部 `addEventListener(..., { signal })`(pointerdown/move/up、wheel、dblclick、容器 click)→ `ac.abort()` 一句清;document 级(keydown、memory:changed)走 `ctx.on/off` |
| ResizeObserver | `ro.disconnect()` |
| 详情卡/图例/tooltip | 挂在视图容器内,容器由壳 `clear()`(app.js `clear`),无 document 级残留 |

验收口径:图谱页收敛后,Performance 面板里**零连续 rAF**;切走后无监听残留(`getEventListeners` / DevTools);两次快速进出无报错无幽灵卡。

- **无 NaN/Infinity**:N=0、N=1、两个断连分量、全自环边——positions 全有限(断连是最容易产生 NaN 的路径:斥力分母 MIN_DIST + 向心质心含零除保护)。

**canvas 交互不可 node 测**——分界线:graph.js 一行都不在 node 里 import(它静态引 app.js → `document` 抛)。交互正确性由 §6.3 静态哨兵 + §6.4 手工清单承担。

## 8. 非目标(明确不做,含理由)

1. **`domain=*` 全库模式**:契约 §4 冻结「无 domain → 域清单,前端先选域」。全库一图在 5 域小库上诱人,但它是 limit 语义、着色语义(多域色才有意义)、性能预算(全库可能 >>500)三者的复合放大器;且域卡片已经是「先看概览再下钻」的合格路径。未来若要做:服务端加 `domain=*` 分支复用 §2.3 全套逻辑(nodes 不 filter 即可),前端已按多域色 + 125+ 节点预算设计,**扩展位已留**。
2. **Barnes-Hut / 四叉树斥力**:N≤500 的服务端硬钳制让 O(N²) 永远在预算内;引入四叉树是负优化(常量与代码量都输)。
3. **键盘逐节点导航 / 完整屏幕阅读器图谱等价物**:canvas 图谱对读屏天然不友好,信息等价物已存在(树视图 + 域索引)。做 `tabindex`/aria-label 底线与 DOM 详情卡(§3.6),其余留待真实无障碍需求出现。
4. **触摸双指缩放**:Pointer Events 已铺好路(单指=拖/平移),双指手势是增量,不在本轮验收。
5. **图的写操作**(加边/删节点入口):读路径零 POST(§2.3),写一律去节点页/编辑页——图谱是观察仪,不是操作台。
6. **统计仪表盘 / 表格视图**:00-context §0.3 明文本轮不做。
