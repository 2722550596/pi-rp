## 2. ui.js 总体设计

### 2.1 分层与依赖方向

```
L0 纯模块(零 import、零顶层 DOM/localStorage/window):
     views/url.js · views/tree-cache.js · ui.js(新)
L1 视图(顶层干净、函数体内用 DOM;仅被壳动态 import):
     views/*.js   ← 可 import L0(直接)与 app.js(现状如此,如 edit.js:26 成环但求值期安全)
L2 壳 app.js(顶层副作用:主题/事件/boot):
     import L0;动态 import L1
```

**ui.js 的三条铁律**(比"顶层无 document"更强,逐条给理由):

1. **零 import**。若 ui.js 为了 toast/renderError 去 import app.js,那么 L0/L1 任何模块 import ui.js 都会在求值期拖入 app.js 的 `document` 副作用——tree.js:14-17 注释里 `views.js → tree.js` 反向拖入的坑会原样重演,且这次污染的是公共层本身。代价(ui.js 不能直接调 `navigate`/`ctx`)用两个出口偿还:通知走冻结的事件契约 `mw:toast`(自派发,与 app.js:251-253 同构);导航/取数一律由调用方以参数或回调注入。
2. **零顶层副作用**。判据(可直接抄进 CI 或自查):
   ```
   node -e "import('./src/web/assets/ui.js')"   # cwd = packages/memory/src/web/assets,MUST 不抛
   ```
   对照组(为何 app.js 不必满足):app.js 的顶层副作用是**有意的**(首帧主题防闪白,注释 L88),它的纯函数已经外置在 url.js(L6-11 教训),ui.js 是第二个这样的外置层。
3. **零模块级可变状态**。不持有 `Map`/`Set`/计数器。理由:(a) V11c 哨兵(`multi-db-frontend.test.ts:130`)按文件清单扫 `new Map()`,新文件进了公共层却不在清单里=守卫盲区;(b) 组件重入(同页多次 openModal)天然要求状态收在每次调用的闭包里。modal 的焦点归还值、asyncPage 的并发序号全部是**闭包局部**的。
4. **最小 DOM API 面**(为 disc-badge 式假 DOM 测试留门,§9.1):ui.js 内只用 `document.createElement / createTextNode / createDocumentFragment` 与节点上的 `className / textContent / dataset / setAttribute / append / addEventListener / replaceChildren / remove / close / showModal / focus`。**不用** `innerHTML`(全站硬规则,§2.2)、`querySelector`(ui.js 内)、`document.*` 全局查询。

**谁能 import ui.js**:所有人(L0);ui.js 不 import 任何 in-repo 模块。视图对新代码的取用方式是**直接 `import … from "../ui.js"`**;**不新增 `ctx.ui`**——ctx 已是"视图共享面"(§2.13),再开一个组件命名空间就是同一职责的第二张门面,违反"第二惯例禁令"。

### 2.2 与 app.js 的分工边界

| 归 ui.js | 归 app.js(不动) | 理由 |
|---|---|---|
| 无状态 DOM 工厂、modal、三态、徽章、面包屑、URI 件、列表、表单字段、纯格式化 | HTTP(`get`/`post`/`unwrap`,哨兵 V7c 把 `fetch(withDbParam(` 钉在 app.js)、路由、`?db=` 注入、`buildCtx`、`renderError`(**依赖模块级 `dbUnreachable` 债务状态与 `switchDatabase`**,app.js:375-389)、多库、轮询、`memory:changed`、boot | HTTP 层是 `?db=` 的唯一注入点(§2.3/§2.4),它进 ui.js 就要给 V7b 开洞;`renderError` 的"库不可达"分支读的是壳的模块级债务(app.js:41),不是无状态件 |

### 3.2 `skeleton` + `asyncPage` —— 三态渲染工厂(F 系基础设施)

```js
/**

/**

 *   empty:    () => Node|string                      可选;默认 mw-empty 卡「暂无内容」
 *   onError:  (err, host, retry) => void             可选;默认 ui.errorCard(err, { retry: refresh })
 * @returns {{ refresh(): Promise<void>, dispose(): void }}
 */
export function asyncPage(host, spec) { … }
```

**并发守卫语义**(抄壳的作业,app.js:404/478 的 `mountSeq`/`sidebarSeq` 模式——§1.4 指出视图层至今没有这个守卫):

```js
// 工厂内部(闭包局部,无模块状态):
let seq = 0, disposed = false;
async function refresh() {
  const mine = ++seq;
  host.replaceChildren(spec.skeleton ? spec.skeleton() : skeleton());
  try {
    const data = await spec.load();
    if (disposed || mine !== seq) return;          // 慢响应不得覆盖新状态(慢的那个后落地会覆盖,app.js:476-478 教训)
    if (spec.isEmpty?.(data)) host.replaceChildren(toNode(spec.empty));
    else { const n = spec.render(data, host); if (n) host.replaceChildren(n); }
  } catch (err) {
    if (disposed || mine !== seq) return;
    (spec.onError ?? defaultError)(err, host, refresh);
  }
}
function dispose() { disposed = true; seq++; }
```

**用法示例**(替代 raw.js:345-347 / views.js:311-315 的手写三态):

```js
import { asyncPage, uriLine } from "../ui.js";
export async function mount(host, params, ctx) {
  const q = params.get("domain") ?? "";
  const page = asyncPage(host, {
    load: () => ctx.api.raw({ domain: q }),
    isEmpty: (d) => !Array.isArray(d.items) || d.items.length === 0,
    render: (d, h) => { for (const it of d.items) h.append(uriLine(it.uri, { href: `#/node?uri=${encodeURIComponent(it.uri)}` })); },
    onError: (err, h, retry) => ctx.renderError(h, err),   // 要库不可达专属卡时注入壳版
  });
  return () => page.dispose();
}
```

**边界**:asyncPage 只管"载入一次"的读视图。edit.js 那种 busy/notice/乐观锁交织的状态机**不套**它(§6.1 理由);写路径零涉及。

## 6. mountEditor 巨函拆解验收(905 行 → 受控函数群)

### 6.1 拆解原则

- **闭合闭包是病根**:905 行共享 `state/el/ctx/load/render` 五个闭包变量,任何函数都无法单独阅读。拆法 = 把闭包变量显式化为一个**控制器对象 C**,所有 runner/render 提升为模块级函数、以 `C` 为首参:

```js
// mountEditor 体内(≈20 行组装):
const C = {
  state, ctx, host: el,
  load: () => editorLoad(C), render: () => editorRender(C),
  field: (name) => editorField(el, name),
  toast: (m, t) => toast(ctx, m, t), navigate: (h) => navigate(ctx, h),
  withBusy: (fn) => withBusy(C, fn),
};
```

- **渲染与动作分类是现成的**:onClick 的 data-action 分支(≈514-543)与 render 的区块列表(≈980-992)就是天然的函数边界,拆解是"提升"不是"重写"——**行为逐字保持**,这条 PR 不混入任何文案/交互变更。
- **否决的替代**:状态机 class/发布订阅——引入新抽象形状,违背"prefer boring";外部框架——契约 §2.1 禁。
- **为何不套 asyncPage**:编辑器的 loading/error/busy/notice 四态交织 + 乐观锁在途写(§3.2 边界),硬套会把状态塞回闭包。
