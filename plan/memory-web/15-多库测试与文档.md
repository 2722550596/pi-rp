### 3.3 ⚠️ V5 的测试陷阱（MUST 写进测试注释）

`security.test.ts:49` 已点明关键约束：**用 `node:http` 而非 `fetch`，因为 undici 拒绝调用方设 `Host` 头，而伪造 `Host` 正是被测对象**。V5 沿用同款 `call()` harness。

⚠️ **更隐蔽的一层**：`bindHost: "0.0.0.0"` 时 S2（`checkHost`）**仍要求** `Host` 头是回环 —— 白名单是**字面量** `localhost|127.0.0.1|[::1]`（`security.ts:22-23` 的 `HOST_RE`，`security.ts:33-36` 的 `checkHost`），与 `bindHost` **无关**。因此：

- 若测试发 `Host: 0.0.0.0:port` → 拿到 403，但那是 **S2 的 403**，**不是**库管理闸门的 403 ⇒ **V5 会假绿。**
- ⇒ `V5a` **MUST** 发回环 `Host`（与 `security.test.ts` 同款），**且 MUST** 配 `V5b`（同 bindHost 下数据路由非 403）作对照。
- ⇒ `V5d`（回环 bindHost 下同 3 条路由非 403）是**第三重**保险：它证明闸门确实**读**了 `bindHost`。三者缺一，V5 都可能假绿或假红。

⚠️ 实现侧约束（D3 亲口确认，D5 原样登记）：闸门依据 **MUST 是 `ctx.bindHost`（CLI `--host`）**，**MUST NOT 用 `req.headers.host`** —— S2 已保证 header host 恒为回环，用它得到的是**永假死代码**，V5a 会假绿。故 D5 的测试**只能**通过 `startServer(..., { host })` / `ctx.bindHost` 注入非回环，**伪造不出来**。

⭐ **R4 的地位（Main + D2 裁定，已进契约 §5.5）**：非回环禁用多库**不是纵深防御，是主控制**。理由：

> `--host 0.0.0.0` 下，**S2 的 `Host` 检查可被伪造头绕过**（检查的是 header 值，而攻击者就是发 header 的人），**S3 对无 `Origin` 的请求放行**（curl/脚本语义）。两者合起来，对**会伪造头**的网络主机**等于不存在**。⇒ 多库若不在非回环下整体禁用，就是**网络上的任何人可读写任意 SQLite 文件**。

⇒ 对 D5 的直接影响：`V5` **不能只断 403**，还必须断**「没做事」**（`V5e`：不扫描）与**「文件没被动」**（`V5c`：指纹不变）。403 是"说了不"，`V5c`/`V5e` 是"确实没做" —— 只有两者齐全，才排除"403 之前已经把库打开了"这类顺序错误。

## 4. V1/V2 深挖：先证明危险，再证明挡住

### 4.1 危险侧：`openMemoryStore` 对陌生库灌表（实跑复现）

**实跑脚本** `/tmp/final-exp.mjs`（最小复现，非全量测试）：

```
plain journal_mode: delete
PLAIN before: md5 0424e44b6c | tables 1 | users | files plain.db
CONTROL openMemoryStore: md5 changed? true | tables 1 -> 24 | memory_* tables: 22 | wal/shm: ctrl.db-shm,ctrl.db-wal
SAFE probe err: no such table: memory_kv
SAFE readonly: md5 same? true | tables same? true
```

**两行结论**：

1. **正控制成立**：普通 `users` 库经 `openMemoryStore` → 表数 **1 → 24**（`sqlite_sequence` + **22 张 `memory_*`** + `users`）、`md5` 变、并生成 `-wal`/`-shm`。独立复现了契约 §2.3 的 22 张表数字。
2. **安全路径成立**：`new DatabaseSync(p, { readOnly: true })` 读 `memory_kv` → 抛 `no such table: memory_kv`（**可识别**），且主文件 `md5` / 表集合**都不变**（`journal_mode=delete` 下连附属文件都不产生）。

### 4.2 为什么 `V2c`（正控制）是必需的

没有正控制的 `V2a`（「调用注册入口后文件不变」）有一个致命退化模式：**如果注册入口因任何原因提前抛错/短路，文件当然不变，测试照样绿。** 一个只测"没发生坏事"的测试，会奖励"什么都没做"。

⇒ `V2c` 直接调 `openMemoryStore`（**不经过任何新代码**）断言它**确实**把文件改成 24 表。两者合起来才表达完整命题：

> 「这个破坏真实可能（V2c）**且** 新入口挡住了它（V2a）」 —— 缺任何一半，命题不成立。

**这是本矩阵里唯一直接断言"既有实现有破坏性"的用例**，故它 MUST 带注释说明**这是被冻结的既有行为（契约 Q1：不修）**，不是待修 bug —— 否则下一位维护者会去"修" `openMemoryStore`，而那会动到 pi 主流程。

### 6.6 ⭐ `db` 的值 MUST 用 `encodeURIComponent`（契约 §7.7 第二条实测规则）

契约 §7.7 实测定位了一个**静默改路径**的机制：**`URLSearchParams` 在解析时把 `+` 当空格**。

⚠️ **口径更正（评审 B + Main 自纠）**：本节的正确口径是「**不要把库路径拼进 query 串再交给 `URLSearchParams` 解析**」+「**不要手拼追加 `db=`**」，**不是**「`URLSearchParams` 与 `encodeURIComponent` 的产物逐字节相同」—— 实测：`URLSearchParams` 把值里的空格编成 `+`，`encodeURIComponent` 编成 `%20`（加号两侧都是 `%2B`），**产物不同**，但**都能正确 roundtrip**。

```
new URLSearchParams('db=/a+b/x.db')      → 读出 '/a b/x.db'    ← '+' 永久变空格，不可逆
'db=' + encodeURIComponent('/a+b/x.db')  → 读出 '/a+b/x.db' ✅
```

⇒ **库路径含 `+` 时会被静默改成一个不存在的路径**（打到别的库，或 404）。这在 WSL/Windows 路径里并不罕见。

**两侧分工（契约 §7.7 冻结）**：

| 侧 | 谁 | 做法 |
|---|---|---|
| 前端**编码** | D4 | **推荐 `.set()` / 对象构造**（`url.searchParams.set(DB_PARAM, path)`）；等价方案是 `encodeURIComponent`。**MUST NOT** 手拼追加 `db=`；**MUST NOT** 把库路径拼进 query 串再交给 `URLSearchParams` **解析** |
| 服务端**解码** | D3 | 用 `new URL(req.url).searchParams` 解（服务端只能这样解）⇒ **前端编码正确是唯一防线** |

**对 D5 的影响**：`V13b` 的怪路径集合**MUST 含 `+`**（不只是 `&`/`?`/`#`/空格/中文）。这是契约 §7.7 与 D4 的两处提醒合并后的口径，现在的集合是 **6 种**：`+` / 空格 / `&` / `?` / `#` / 中文。

⚠️ **这是一条"前端编码错 → 服务端无法补救"的单边契约** —— 也是本矩阵里**唯一**靠纯函数测试就能完整覆盖的**数据损坏**类 bug（`V13b`）。不要把它降级成"边界情况"。

````markdown
### 2.5 记忆库选择器(多库)

一个 world 下往往有**几十个**记忆库 —— **world 级一个、每个角色各一个**,其中
绝大多数还是空的。浏览器可以**同时连着它们**:页面顶部的下拉框选中哪个库,当前
页面的**全部读视图与写操作**就作用于哪个库,不需要重启、也不需要换端口。

#### 怎么用

```bash
# 起服务时告诉它「去哪找库」(可重复 --roots)
pi-memory-web --db ~/projects/hackathon/worlds/fpal/.pi/memory.db \
              --roots ~/projects/hackathon/worlds

# 之后在浏览器顶部选择器里切换,无需重启
```

选择器显示**每个库的节点数**(如 `fpal/elias · 73 条`)—— 库一多、且大多数为空,
不显示节点数根本认不出哪个是有内容的。选中状态记在浏览器里,刷新后保持。

#### roots 怎么配

| 手段 | 说明 |
|---|---|
| `--roots <dir>` | 允许被选择的目录,可重复。缺省 `[当前目录]` |
| `--allow-any-path` | 跳过 roots 限制(显式开启后 stderr 打醒目警告) |
| `--db <path>` | 启动时的**进程库**;它**不受** roots 约束(你显式指定的,可信) |

**缺省不含 `$HOME` 或 `/`** —— 否则"默认就能读整机"。想让选择器看到哪些库,
就把那个世界的根目录 `--roots` 进去。

#### 安全边界(重要)

- **非回环绑定 ⇒ 多库整体禁用。** 用 `--host 0.0.0.0` 启动时,库管理功能一律 `403`,
  发现扫描**不执行**,`?db=` 只接受进程库。原因:无认证的服务对网络可达时,
  "能注册任意路径"等于**网络上的任何人都能读写你机器上任意 SQLite 文件**。
  单库(进程库)仍然可读写 —— 即退化成当前行为。
- **只有通过校验的路径能被打开。** 进入可写列表前必须:归一化 → 落在 roots 内
  (**逐段真实解析**,并核验「你写的路径」与「实际解析到的文件」是同一个,故
  `..` 与符号链接都绕不出去) → 是**已存在的普通文件** → **只读探测**能读到
  记忆库的 schema 版本。探测失败或版本不兼容一律拒绝,**绝不注册**。
- **探测不改动库文件本身**:只读连接打开,主文件逐字节不变。对 WAL 模式的库,
  读它可能留下 `-wal`/`-shm` 附属文件(任何只读客户端读 WAL 库的正常行为,删除安全)。
- 选错路径的代价被挡住了:填一个**不是记忆库**的文件(笔记、别的应用的数据文件)
  会被探测拒绝,而不是被写进一整套记忆库表。
- **库正被另一个进程写入时会报「稍后重试」**,不是"服务挂了":同一个库被 pi 会话
  与浏览器同时写时,SQLite 会短暂报锁;界面显示的是一条中文提示,等几秒重试即可
  (冲突是暂时的,不是永久错误)。

#### ⚠️ 首次列库可能卡一下(扫描是同步的)

发现扫描用的是**同步目录遍历** —— `--roots` 给得越宽,首次打开选择器(或缓存
过期后)越可能停顿一下,期间页面无响应。实测:扫 1 万多个目录要几百毫秒到几秒
(取决于磁盘与负载)。

建议:把 `--roots` 指到**世界根目录**即可,不必给整个 `~/projects`。

#### 新建空库

选择器旁可以**新建一个空记忆库**,但**必须显式确认**(前端会弹一个说明"将新建空
记忆库"的确认框)。理由:路径不存在时静默新建,会把一个笔误变成一个莫名其妙的文件。

#### 不做的事

- **不做跨库内容迁移 / 合并 / 复制节点**。多库是"同时看多个库",不是"库之间搬东西"。
- **不做库级别的删除 / 重命名 / 移动**。要删就删文件;注册表随进程消亡。
- 库边界仍 = 进程边界,世界钟仍各库自存(见 §16)。
````

### 9.1 ⚠️⚠️ roots 包含性曾有一个**真实逃逸**（已修；我原来的分析**不够深**）

**我第一版的分析（只到这一步）**：`path.relative(roots, path.resolve(候选))` 挡得住 `..`，挡不住**单纯**的目录 symlink（`roots/link/secret.db`）。我把它报给 D2，建议"加一次 `realpath` 即可"（= 双重包含性）。

**实测**（Node，本机，我的第一版复现）：

```
roots  = /tmp/symtest/roots
候选   = /tmp/symtest/roots/link/secret.db     # link -> /tmp/symtest/outside
path.relative(roots, path.resolve(候选))  = "link/secret.db"   → 判定「通过」✅（错的）
fs.realpathSync(候选)                     = /tmp/symtest/outside/secret.db
                                           → 判定「拒绝」❌（对的）
```

**但我漏掉了一个更糟的形态 —— `..` 与 symlink 的歧义组合**。D2 实测、Main 独立复核确认：

候选串: roots/link/../outside/secret.db

### 9.3 打开（可写）一个陌生库仍会**灌表** —— 探测是**唯一**防线

`openMemoryStore` 的破坏性行为**未被修复**（契约 Q1：不修，改它会动 pi 主流程）。所以：

- 一个**通过了探测**（有合法 `memory_kv.schema_version`）但**结构不全**的库，仍会在打开时被 `CREATE TABLE IF NOT EXISTS` 补齐缺失的表。
- 探测只能回答「这是不是一个记忆库」，**不能**回答「这是不是我想要的记忆库」。
- ⇒ 「用户填了**另一个记忆库**的路径」这种误操作**没有**护栏（那本来也是合法输入，无可靠判据可区分）。

### 9.4 不做的事（契约 §1.3，再列一次以便使用者查）

- 不做跨库合并 / 迁移 / 复制节点。
- 不做库级别的删除 / 重命名 / 移动。
- 不做 schema 迁移（无就地迁移立场不变，`schema.ts:131-138`）。
- 不做跨库事务（两个库是两份独立 SQLite，没有跨库事务这个概念）。
- 不做远程 / 网络多用户（非回环下整体禁用）。
- 不做 token / session / 登录（M5）。

### 9.5 库"消失"不会被静默忽略，但也**不会被清理**

- 契约 §3.2#5：已注册库文件被外部删除 → 请求报 **409 `invalid_db`**（D3 确认口径，§11-U7），**MUST NOT** 静默从注册表移除。
- 副作用：注册表里的**死条目会一直留着**，直到进程重启。这是刻意的（用户需要知道库不见了），但 UI 上会出现永远 `reachable: false` 的项。README **未**承诺自动清理。
- ⚠️ 关联实测事实：`openMemoryStore(不存在的路径)` **会静默建出一个空库**（本 agent 实跑：删掉库文件后重新打开 → 文件重新出现）。这正是注册表必须先 `stat` 的理由 —— 我实测到 D1 的 `resolve` 会 `stat`，故 `V1b`/`V2a` 的"文件不变"断言依赖它。

### 9.6 进程库不受 roots 约束（**是设计，不是缺陷**）

`--db <path>` 指定的进程库**跳过** roots 检查（契约 §5.4）。理由：它是用户在命令行显式给出的、可信的。⇒ **`--db /etc/somewhere/x.db` 不会因为不在 roots 里被拒**。值得用户知道：roots 管的是"**选择器里能点开什么**"，不是"这个进程能碰什么"。

### 9.7 symlink 的 TOCTOU 残留（契约 §11-U5，**本期防不住**）

`checkPathAllowed` 通过后、`openMemoryStore` 之前，路径**可被换链**（TOCTOU）：`node:sqlite` 不暴露 `O_NOFOLLOW`，故无法在打开那一刻锁定 inode。

- 契约 §11-U5 已登记：「本期**防不住**，如实记录」。
- 影响面：与 §9.1 同量级（本地单用户；能换链者已有该目录写权限），但**性质不同** —— §9.1 是**判定逻辑**缺陷（已修），本条是**内核 API 能力**限制（修不了）。
- ⇒ **MUST NOT** 把 D2 的「一致性判定」读作"symlink 问题已彻底解决"。README **未**承诺这一点（§7.2 只写"落在 roots 内（逐段真实解析 + 原始串与归一化串指向同一文件）"，未写"不可绕过"）。

### 9.8 ⚠️ 发现扫描是**同步**的，宽泛 roots 会卡住事件循环（契约 §5.2 末，实测）

`discoverMemoryDbs` 用**同步 `readdirSync`** 遍历目录 ⇒ 一次扫描**阻塞事件循环**。实测（评审 + D2 各一次，机器负载不同）：

| 来源 | 目录数 | 耗时 |
|---|---|---|
| 安全评审 | `~/projects` **11345** 个目录 | **2699 ms** |
| D2 复测 | **14871** 个目录 | **331 ms** |

⭐ **5s 的 TTL 缓存只摊薄频率，不消除单次阻塞** —— 首次列库（或缓存过期后）会卡住这一下。

- **对用户的影响**：`--roots` 给得越宽，首次 `/api/databases` 越可能卡一下（同时那个进程内的其它请求也在等）。
- **README 已如实写**（§7.2）：让 `--roots` 宽泛的用户知道首次列库会卡一下。
- ⚠️ **MUST NOT** 把它写成"无影响"；也 **MUST NOT** 断言具体毫秒（机器负载差异达 8×，见上表）。

### 9.9 平台限制（本机未验证的路径形态）

所有路径测试在本机（WSL2 / Linux）跑。以下**未覆盖**（展开见 §10.3；另见 §9.7 的 TOCTOU）：大小写不敏感文件系统、Windows 路径分隔符/盘符、Unicode 归一化（NFC/NFD）。

## 10. 这些测试**测不到**什么（7 条，逐条诚实）

### 10.1 测不到：多库与 pi 会话**并发写同一个库**的竞态

所有新测试都是**单进程、单客户端**（harness 自己起 `startServer`，自己发请求）。真实格局是（`README.md:114`）：Web 界面与 pi 会话**各持一条 SQLite 连接**，靠 `PRAGMA data_version` 感知对方写入。

- `V3`/`V6` 断言的是**进程内**引用同一性；对**跨进程**的写-写竞态**零覆盖**。
- 该竞态**既有**（上一轮就存在），多库没有新增它，也**没有**修它。
- `[INFERENCE]` 缓解靠 `driver.ts:30` 的 `PRAGMA busy_timeout = 5000`；这条**没有**被测过，只是读到了它。
- ⇒ 若将来要覆盖，需要**两个真实进程**的测试（成本高，本期不做）。**不要**把 `V3` 读成并发安全证明。

### 10.2 测不到：前端切库的**真实浏览器行为**（本节**包含** treeCache 串味）

`V7`/`V11a`/`V11d`/`V12` 与 D4 提供的稳定符号断言，是**静态源码断言**（沿用 `views-parity.test.ts` 的既有做法：读文件 + 正则/字符串断言，不跑 DOM）；`V11b`（`tree-cache.js`）与 `V13`（`buildQuery`/`withDbParam`）是**纯函数**断言（可跑、但仍在 Node 里，无浏览器）。

⚠️ **分界线（契约 §7.10 实测）**：`node -e "import('./src/web/assets/app.js')"` → **`ReferenceError: document is not defined`**（`app.js:31-32` 顶层 `applyTheme`、`:432` `document.addEventListener`、`:562` `boot()` 都是**求值期副作用**；`tree.js:12` 静态 import `app.js` ⇒ 导入 `tree.js` 必然先求值 `app.js`）。⇒ **凡测试 import 的模块 MUST 无求值期副作用**；靠 DOM shim 会引入 jsdom，**与 M4 冲突**。

- ✅ 能抓：`edit.js` 又有裸 `fetch`、`?db=` 注入口被删、`mw:db` 键改名、`treeCache` 的库归属守卫被删、`switchDatabase` 漏 `clear`。
- ⚠️ **矩阵自身的缺口（V13 暴露的）**：我原先的 `V7` 系列只断言"注入点**存在**"，**没有**断言"注入**结果**是合法 URL"。⇒ **`V13a-f` 是补上这一半**（先拼完整 URL 再注入；`?` 恰一次；`db` 值不含 `?`；原参数逐个 roundtrip）。教训：**"注入口存在"与"拼接结果正确"是两件事，缺一不可**（§6.5）。
- ❌ **抓不到**（全部是"最可能把用户带到错误库"的路径）：
  1. **切库后侧栏是否真的重载**（`switchDatabase` 的三个副作用：重载侧栏 / 重挂路由 / 清 `uri`）；
  2. localStorage 有值但该库**不在** `/api/databases` 里时，首屏是否回落到 `current`（契约 §6.3）；
  3. 切到**已消失**的库（`reachable: false`）是否**显示错误而非静默回落到 `current`**（契约 §6.5）；
  4. ~~treeCache 真实串味~~ → ✅ **已不在测不到之列**：D2 把 `ensureCacheFor(db)` 抽成模块级函数后，`V11b` 可在 Node 里直接驱动它（见 §3.6）；仅剩「在真实浏览器里切库后 UI 是否重挂」这一层仍未覆盖；
  5. `renderSidebar` 的**并发覆盖**（`sidebarSeq` 序号守卫）—— 需要两个交错的异步 render，静态断言证明不了交错顺序。
- ⭐ **诚实结论**：本设计的**前端回归主要靠人工浏览器验证**（上一轮的提交信息里就有「Verified in a real TUI session」的做法）。若要自动化，需引入 DOM 环境（**违反 M4 的零依赖**）或 vendored 一个最小 DOM —— 不属本期。

### 10.3 测不到：`checkPathAllowed` 的**平台差异**

所有路径测试在本机（WSL2 / Linux）跑。以下都**未覆盖**：

- **大小写不敏感文件系统**（macOS APFS 默认、Windows NTFS）下，同一文件的两个拼写会得到**两个库 id**（id = `path.resolve` 后的字符串，§3.5 确认 id 仍是词法）⇒ 「同库同连接」在语义上被打破（两条连接指向同一文件）。
- **Windows 路径分隔符 / 盘符**：`path.relative` 跨盘符时返回绝对路径（然后被 `path.isAbsolute` 判出拒绝）—— 行为**可能是对的**，但**没有测试钉住**它。
- **Unicode 归一化**（NFC/NFD）在 macOS 上会使"同一个名字"两次输入不等。
- ⇒ `V3a` 只在 Linux 上证明了"同字符串 → 同连接"，**不是**"同文件 → 同连接"。

### 10.4 测不到：发现扫描（discovery）的**真实目录树**

契约 §7.5 强令「测试 MUST 用 `mkdtemp` 自建，MUST NOT 断言真机库的任何路径」；§7.9 又冻结「**不作任何数字断言**」。遵守它们的代价是：

- 测试里的目录树是**测试自己造的**（浅、小、无权限陷阱）。
- ⇒ **MUST NOT** 把测试通过读作"扫描在真实 `~/projects/hackathon/worlds` 下是对的"。真实树有：深度 > 测试树、`.git`/`node_modules`、规模（几十个库）。
- ⭐ 具体未覆盖：**扫描深度上限**（契约 §11-U2 未定）、**跳过目录清单**、**遇到无读权限目录时的行为**。
- ⇒ 真机验证只能人工做一次（起服务 `--roots ~/projects/hackathon/worlds` 看选择器列出多少项），**不写进自动化**。

### 10.5 测不到：`V6` 的 LRU 驱逐在**真实负载**下的正确性

`V6a-c` 用 `limit: 2` + 3 个库，是**最小规模**。它证明不了：

- 驱逐时**正被另一个在途请求使用**的库不会被关掉（契约 §3.2#3 说「不是当前请求目标」—— **并发**下有两个目标）；
- `db.close()` 抛错时驱逐**不拖垮请求**（契约 §3.2#4「关闭失败不致命」）；
- 驱逐**同时**从 `runtime.ts` 的 detector `WeakMap` 中失效（契约 §3.2#3 的 `weakMap.delete(store)`）—— 这条**无法**从公开面观测；`V3c` 的 `changed` 断言只是**间接**证据，且**时序相关**（需一次真实写 + 一次轮询）。
- ⇒ `V6` 覆盖的是**计数不变量**，不是**并发安全**。

### 10.6 测不到：锁冲突的**真实时序**与 TOCTOU 窗口

`V14` 能证明「锁冲突时返回 409 而不是 500」这一**映射**正确（`V14c` 是纯函数，最可靠）。它**证明不了**：

- **5011ms 这个数字**（契约 §2.8 实测）在别的机器/负载下是否相同 —— 测试若断言具体毫秒即在断言 SQLite 内部实现；
- **两个真实进程**（web + pi 会话）交错写的时序 —— `V14a` 用的是**测试自己开的两条连接**，不是两个进程（同 §10.1）；
- ⭐ **TOCTOU 窗口**（§9.7）：`checkPathAllowed` 与 `openMemoryStore` 之间的换链，**无法**在单进程测试里稳定构造（需要精密竞态）。⇒ 这条**只能**靠 §9.7 的诚实声明覆盖，**没有任何测试**。
- ⇒ **MUST NOT** 把 `V14` 的绿色读作"并发写已安全"。

### 10.7 测不到：`V1`/`V2` 的**攻击者视角**

`V1a-d`/`V2a-c` 都是"**服务端行为**"测试：证明给定一个未注册 `?db=`，服务端拒绝且不碰文件。

- ❌ **抓不到**：浏览器侧是否**真的**只发已注册的值。真正的 CSRF 攻击面是「任意本机网页让浏览器发 `?db=/etc/passwd`」—— 而服务的防线是 §4.2#1 的注册表全等，不是浏览器。
- ❌ **抓不到**：DNS rebinding 的**时序**（先通过 Host 检查、再换解析）。S2 的单元测试（`security.test.ts:85-133`）只测 `checkHost` 本身。
- ⇒ 正确读法：这些用例证明**"服务端不会因 `?db=` 而读写任意文件"**，**不**证明"攻击不可能"。
