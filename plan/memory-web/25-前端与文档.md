### M3 `node.js` 改口径 + 入口维度区块

**改动**：
1. `node.js:298-301` 的 `section("想起条件", …)`：数据源仍是 `node.disclosure`，但**服务端已改口径**（§8.2）→ 语义变成「你从这个入口进来看到的条件」。文案改为：
   `满足这个条件时，这条记忆会被想起（当前入口：<请求进来的 uri>）。`
2. **新增 `renderEntryDisclosures(el_, dto, entryUri)`**（`NEW`）：列出规范入口 + `dto.aliases[]` 每个入口及其 `disclosure`。
   - 只在 **入口数 ≥ 2** 时渲染（1 个入口 = 规范入口，上面的段已覆盖；重复展示是噪声）。
   - 每行：`<code>alias_uri</code>` + `discBadge(disclosure, {label:"想起条件"})`；`disclosure === null` → `el("span",{class:"mw-muted", text:"（继承节点级）"})`。
   - 当前入口（`alias_uri === entryUri`）加 `aria-current="true"` + 「当前入口」chip。
   - **死别名**（契约 §5 X6）：`alias.dead === true` → `.mw-disc--dead` + `title` 说明（M4 的文案纪律）；**不渲染琥珀徽章**。
3. `node.js:342` 的 `renderAliases(el_, dto.aliases)` 保留（它渲染的是「旧地址」列表）——与 `renderEntryDisclosures` **是两个语义**：前者是寻址历史，后者是条件归属。**合并会把「这个地址存在」与「这个地址有自己的条件」混为一谈。**

**为什么分区块而不是合并成一个列表**：`node.disclosure` 是「当前入口的」，`aliases[].disclosure` 是「其它入口的」——两者**不是同一集合的成员**（前者常来自 `nodes`，后者可能继承同一 `nodes` 值）。混在一起会让「共 N 个入口」的计数说谎。

> **漏了会怎样**：同一节点的多入口在 UI 上**完全相同**，用户无法知道「换入口进来会看到不同条件」——本次改动的核心承诺（契约 §3.1「同一节点经不同入口进入，可以有不同想起条件」）在 UI 上不可见。

### M4 死别名（契约 §5 X6）的 UI 处置

`consolidate(link)`（`tools.ts:915-919`）产出的别名 `alias_uri` 同时仍是 `nodes.uri` → `resolveUri` 永远命中节点（`store.ts:181-189`）→ **入口永不生效**。主 agent 裁定后（镜像 `resolveUri`），`effectiveDisclosure` 也返回节点条件 ⇒ **不会条件错乱**，但**用户设的 `aliases.disclosure` 永远看不到效果**。

**D5 处置**（UI 侧的最小诚实）：
1. **列出但标记为无效入口**（与 D1 的结论对齐：D1 明说「别把死别名当有效入口展示」）。**不是**「照常列出、不加区分」——那正是 D1 禁止的。
   - 有 `dead` 时：`.mw-disc--dead`（点线边框 + `opacity: 0.65`）+ `title="被遮蔽（同名节点优先）：该地址同时是另一条记忆的地址，此入口的条件不会生效"`，且**不渲染琥珀徽章**。
   - 文案纪律：**MUST NOT** 写「已失效」——那会误导用户以为数据坏了。准确语义是「**该入口被同名的规范节点遮蔽**」（主 agent 裁定，§3.2）。
   - **不隐藏**：隐藏 = 信息丢失（该行确实占用 `aliases` 表，且 D1 说存量死别名「不静默删」，说明它们是**可见状态**）。
2. 该区块底部固定一行说明（仅当存在入口时）：
   > 入口条件按「该地址解析到什么」生效；若某地址同时是另一条记忆的地址，它不构成入口（引擎已知缺陷，见 `plan/memory-web/00-共同上下文.md` §12 X6）。
3. `edit.js` 的 `renderMetaBlock`（`:1055-1090`）在**别名入口**下多一行：`你正在编辑入口 <uri> 的条件。`（若 `alias.dead === true`，改为 `此入口被同名节点遮蔽，条件不会生效`）
4. 逐行标记依赖 `AliasDTO.dead`（✅ 已批准，见 §12-U1）；无该字段时降级为区块级豁免说明。

> ⚠️ **与 D1 的 `resolveEntry` 的口径关系（主 agent 广播，已核实）**：D1 定稿 `resolveEntry(uri)` 在**死别名**下返回 `kind: "canonical"`（因为它同样镜像 `resolveUri`）。⇒ **UI MUST NOT 用 `resolveEntry(uri)?.kind === "alias"` 判断「这是不是一个入口行」**——它在死别名上是 `false`，会把死别名误判成普通节点。

### M5 `search.js` / `views.js` 视觉升级

| 位置 | 现状 | 改为 |

**`discBadge` 实现（唯一视觉真相源，放 `views.js` 并 export）**：
```js
// ⚠️ views.js 用的是本文件内的 h()（:50-71），**不是** app.js 的 el()/append()：
//    views.js 零 import（已读 :1-25 确认）。两者都有「null → 跳过」的守卫，
//    h() 在 :64 显式 skip null；app.js 的 append 在 :116 判 null。此处 MUST 用 h()。
export function discBadge(text, opts = {}) {
  const t = foldWs(text);
  if (!t) return null;                        // 空 = 不渲染（M2 降级）
  const kind = opts.kind || "entry";
  const kids = [h("span", { class: "mw-disc__icon", "aria-hidden": "true" })];
  if (opts.label) kids.push(h("span", { class: "mw-disc__label", text: opts.label }));
  kids.push(h("span", { class: "mw-disc__text", text: t }));
  return h("span", { class: `mw-disc mw-disc--${kind}`, title: `${opts.label || "想起条件"}：${t}` }, kids);
}
export function discChip(text, opts = {}) { return discBadge(text, { ...opts, label: "" }); }
```
> ⚠️ **返回 `null` 时调用方 MUST 判空**：`views.js` 的 `h()`（`:64`）与 `app.js` 的 `append`（`:116`）**都**显式跳过 `null`（已读源码确认），故 `h("p", {}, [discBadge(...)])` 与 `append(parent, discBadge(...))` 两种写法都安全——**不产生字面量 `"null"`**。§10-C 用阳性对照把这条守卫钉进测试。

## §7 错误边界与降级

| 场景 | 行为 | 理由 |
|---|---|---|
| `TreeNodeDTO.disclosure === undefined`（旧服务端 / 缓存里的旧 DTO） | 不渲染任何徽章 | 空徽章会让人误以为条件被清空（M2 降级） |
| `disclosure === null` | 同上（不渲染） | `null` = 无条件，UI 无需表达「无」 |
| `disclosure === ""` | **不渲染**（`foldWs("")` → `""` → `discBadge` 返回 `null`） | ✅ **F4 裁定已落**（主 agent：以 D1 为准，`""` → 归一为 `NULL`）。D5 侧**不动**——前端把空串当「无值」与「空 = 清除」的既有语义（`edit.js:695`）一致 |
| 值极长（跨多行） | `foldWs` 折成单行 + CSS `text-overflow: ellipsis` + `title` 全文 | P16：不折叠则条件可伪造成员行（`views.js:78-80` 既有缓解）；且会撑破 28px 树行 |
| 值含 HTML | 全部走 `textContent`（`el()`/`h()` 的 `text` 通道） | 既有纪律；XSS 面 `00-共同上下文.md` §17.5 已实测 |
| 别名悬空（target 已删） | 服务端返回 `null`，前端不渲染 | D1 §2.8 伪码：不抛错 |
| 死别名（X6） | 逐行标记为「被遮蔽（同名节点优先）」，**不隐藏**（M4） | 隐藏 = 信息丢失；谎报 = 更坏 |
| `AliasDTO.disclosure` 缺字段（渐进部署） | `discBadge(undefined)` → `null` → 行只显示 uri | 不谎报 |
| `AliasDTO.dead === true` | 不渲染琥珀；渲染 `.mw-disc--dead` + 「被遮蔽（同名节点优先）」 | 不把无效入口画成有效 |
| `discBadge` 返回 `null` 被 append | **安全**：`app.js:115-117` 的 `append` 首行即 `if (kids === undefined \|\| kids === null) return node`；`views.js:63-64` 的 `h()` 亦跳过 `null` | 已实测源码，**不产生字面量 `"null"`** |

**无控制台错误的硬要求**（契约 §7.6）：`discBadge` 返回 `null` 是**正常路径**（不是异常），因此**不得**为它 `throw`；调用方判空或依赖上面两个 helper 的守卫。
