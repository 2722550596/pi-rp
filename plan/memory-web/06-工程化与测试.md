### 2.3 逐字段理由与证据

**`bin`**：契约 §4.1 冻结。命名 `pi-memory-web`（不是 `pi-memory`——`pi` 已被 `packages/coding-agent/package.json:10` 占用；`pi-ai` 被 `packages/ai/package.json` 占用，实跑确认 `npx` npm 11.19.0 下 workspace bin 冲突会静默覆盖，必须避免重名）。

**`files` 加 `README.md`**：这是**跟随既有约定**，不是必需。实跑确认 npm 即使 `files: ["dist"]` 也会自动打包 `README.md`（`/tmp` 探针：tarball 含 README.md + LICENSE）。`packages/ai/package.json` 与 `packages/telemetry/package.json` 都写 `["dist","README.md"]`，故跟随。**memory 包当前没有 `LICENSE` 文件**（实跑 `ls packages/memory/LICENSE` → 不存在），所以 `files` 不写 LICENSE。

**`build` 追加 `shx chmod +x dist/web/cli.js`**：
- 依据先例 `packages/coding-agent/package.json:37`：`"build": "tsgo -p tsconfig.build.json && shx chmod +x dist/cli.js dist/rpc-entry.js && npm run copy-assets"`。
- **实跑确认这条不是可选的**：npm 11.19.0 下 `npm pack` **不会**因 `bin` 字段而给 tarball 里的文件加执行位——探针 `/tmp/chtest`（有 `bin`，磁盘 644）打包后 `tar -tvf` 显示 `-rw-r--r--`；`/tmp/chtest2`（无 `bin`）同样 644。反证：`packages/coding-agent/dist/cli.js` 在磁盘上是 `-rwxr-xr-x`（实跑 `ls -la`），说明它的 x 位来自 build 里的显式 `shx chmod`，不是 npm 给的。
- chmod 必须在 `tsgo` **之后**（文件得先存在）。`&&` 链顺序即为此。

**`copy-assets` 用 `shx cp -r src/web/assets/. dist/web/assets/`**：
- `.` 后缀拷贝**目录内容**（含嵌套的 `views/`、`vendor/`），这是 GNU `cp -r src/. dst/` 语义；**实跑确认**：`/tmp/shxtest` 里 `src/web/assets/{index.html,app.js,vendor/pico.min.css,vendor/pico.LICENSE}` 经此配方后 `dist/web/assets/**` 四文件齐全且嵌套结构保持。
- `shx mkdir -p dist/web/assets/vendor` 在 cp 之前是冗余的（`cp -r` 会建目录），但**保留**它作为"目标根存在"的显式保证，并与 `packages/coding-agent/package.json:39` 的写法一致（那里也是先 mkdir 再 cp）。它对空 assets 目录场景也安全。
- **为什么不逐文件 `shx cp src/web/assets/*`**：`shx` 基于 shelljs，glob 语义在跨平台上有差异；`cp -r dir/.` 只依赖目录拷贝，最稳。这也是 coding-agent 在 `copy-assets` 里对 theme/assets 用 `cp -r` 的原因（`package.json:39` 末段）。

**`clean` 不动**：`shx rm -rf dist` 已经覆盖 `dist/web`。

**`prepublishOnly` 不动**：`npm run build` 已含 `copy-assets`（因为 build 链了它）。契约 §4.1 的口径正确。

**`tsconfig.build.json` 零改动**：`include: ["src/**/*.ts"]`（`tsconfig.build.json:10`）+ `rootDir: "./src"`（`:5`）自动覆盖 `src/web/*.ts` → 产出 `dist/web/*.js`。**实跑确认**：在 `/tmp/tsgotest2` 用 `extends` 该 base 配置编译 `src/web/cli.ts` + `src/web/server.ts`，产物 `dist/web/cli.js` 与 `dist/web/server.js` 均在，`rootDir` 未被 assets 破坏（assets 是 `.js/.css/.html`，不在 `include`）。

## 3. bin 入口 `cli.ts` 的工程契约

### 3.1 shebang

`src/web/cli.ts` **首行 MUST** 是 `#!/usr/bin/env node`。
- 先例：`packages/coding-agent/src/cli.ts:1`、`packages/ai/src/cli.ts:1` 都是首行 shebang。
- **实跑确认 shebang 会被 tsgo 原样保留**：`/tmp/tsgotest2` 编译后 `dist/web/cli.js` 首行即 `#!/usr/bin/env node`，第二行是 `import ...`。

### 3.2 模块形态（关键：ESM，不是 CJS）

**实跑确认**：因为 `packages/memory/package.json:5` 有 `"type": "module"`，`tsgo` 产出**纯 ESM**——`/tmp/tsgotest2/dist/web/cli.js` 是 `import { a } from "./server.js";`，**不是** `require`。

反例警示（实跑）：`/tmp/tsgotest` 里**没有** `package.json`/`type:module`，同样的源编译出 CJS（`"use strict"; Object.defineProperty(exports,...); require("./server.js")`）。所以**不要**在 `src/web/` 下再放一个 `package.json`；跟随包级 `type: module` 即可得到 ESM。

### 3.3 相对 import MUST 用 `.ts` 后缀

`src/web/*.ts` 之间互相 import 一律写 `.ts`（如 `import { startServer } from "./server.ts"`），**禁止**写 `./server.js`：
- `scripts/check-ts-relative-imports.mjs:23-25` 的正则 `/^\.\.?\//` + `/\.js(?:[?#].*)?$/` 会捕获任何相对 `.js` specifier；该脚本扫全部非 `.d.ts` 的 `.ts`（`:17`、`:35`），include 在 `npm run check` 里（root `package.json:23`）。
- 编译后 `tsgo` 会把它改写成 `.js`（实跑：`./server.ts` → `./server.js`）。这是 `tsconfig.base.json:19` `rewriteRelativeImportExtensions: true` 的作用。

契约 §3「命名硬规则」与此一致。

### 3.4 资源路径解析

`cli.ts` 与 `server.ts` 定位 `dist/web/assets/` MUST 基于**自身文件位置**，不得用 `process.cwd()`：

```ts
// NEW: src/web/paths.ts
import { dirname, join } from "node:path";
import { fileURLToPath } from "node:url";
export function getWebAssetsDir(): string {
	return join(dirname(fileURLToPath(import.meta.url)), "assets");
}
```

理由：`dist/web/paths.js` 的 `import.meta.url` 落在 `dist/web/`，`assets/` 是它的兄弟目录 —— 与 `copy-assets` 的目标布局严格对应。
先例：`packages/coding-agent/src/core/export-html/index.ts:4` 从 `config.ts` 取 `getExportTemplateDir()`（而非 cwd），`:151` 用它 `readFileSync(join(templateDir, "template.html"))`。**这是本仓既有的"包内资源定位"范式**。
`[推断]` 直接用 `import.meta.url` 比 coding-agent 那套集中式 config 更简洁；memory 的 web 模块是自包含的，不需要为它扩 `config.ts`。

### 3.5 启动与退出

- `cli.ts` MUST 是 `main()` 的入口：解析 argv → `openMemoryStore(dbPath)` → `startServer(store, opts)` → 打印 URL → 挂 `SIGINT`/`SIGTERM` 优雅关闭（`server.close()` + `db.close()`）。
- **`db.close()` 的接入点是 D1 的 `server.ts` 生命周期**（契约 §14：D1 拥有 `cli.ts`/`server.ts`）。D6 只冻结"`cli.js` 必须是可执行、可定位 assets 的 ESM 入口"这一**工程形状**，不规定其业务参数。
- **不注册任何 npm `postinstall`/`prepare`**：会引入安装期副作用（安全面），且本仓其他包也没有。

### 4.6 客户端内部接口对工程层的两个约束（契约补充 #5，主 agent 批准）

主 agent 批准了两条**客户端内部接口**（非 HTTP 契约），D6 从工程层确认它们不与打包/检查冲突：

1. **视图模块签名**：每个 `assets/views/*.js` MUST `export async function mount(el, params, ctx)` 并返回 `dispose()`。
   - **工程后果**：`views/` 是 `assets/` 的**子目录**，`copy-assets` 的 `cp -r src/web/assets/.` MUST 保留它（§4.4 的集合相等不变量已覆盖此点——`views/*.js` 漏拷会让集合不相等而红）。
   - **无测试义务**：契约 §4.3 明示不做浏览器测试，故该签名不由 vitest 覆盖（无 DOM runner）。`[推断]` 若将来要测，需引 jsdom（**违反零依赖**）→ 不做。
2. **写后刷新事件** `document.dispatchEvent(new CustomEvent("memory:changed", ...))`：由 D5 在写成功后广播、D2 的壳监听重挂。
   - **工程后果**：这是**运行时**契约，不产生构建/打包需求。D6 只登记：它落实契约 §7.4 第②条（服务端自己的写入自己看不见），故 D5 **不得**依赖 `/api/events` 轮询发现本次写入（§7.4 修正后的硬约束）。

1. `render*` 文本把 `disclosure` / 顶层 `content` / `glossary.keyword` **原样插入行内**，未做 `\s+` 折叠 → 内容可**伪造成员行**。
2. 因此**凡从 `render*` 文本反推集合的逻辑（parity 测试、以及将来任何文本解析）MUST 视为不可信输入**，按 **adversarial 假设**处理：正文 / `disclosure` / `keyword` 可任意伪造成员行。
3. 因此 **`/api/view` 的结构化 DTO 是权威源**；`render*` 文本**只作交叉校验**。两侧不一致时**不得**自动判定"以文本为准"（该判定会把注入内容扶正）。
4. ⇒ **反向加强本设计的核心方向**：**正因为引擎文本不可信，UI 才必须走结构化 DTO，而不是解析 `render*` 字符串**（这正是契约 §8.2 的决定，D6 在此补上它的**因果依据**——原 §8.2 只说了"文本给 TUI 用、Web 要结构化"，没说"文本不安全"）。

**对 D1 / D4 的落地点**：
- D4 的 parity 测试 MUST 把文本侧当**不可信**，故断言是"**集合相等**"而非"文本是真相"——两侧不等即 fail，不降级。
- D1 的 `/api/view` MUST 只吐结构化 DTO，**MUST NOT** 提供任何"把 `render*` 原样返回"的端点（否则客户端会依赖不可信文本）。

#### 6.5.4 D6 的裁决（主 agent 给的退路我两条都否掉，用第三条）


主 agent 给的方案是：①直接测 `snippet()`（泄不泄露 `\n`），退路 ②经 `renderForgottenView` 间接断言"无 col0 `- ` 行带该 uri"。

**D6 判定**：
- **方案①不可行**：`snippet` 是模块私有函数（`memory-views.ts:11`，无 `export`；实跑 `grep` 确认 `src/index.ts` 未导出它）。**且**主 agent 自己指出"这不是契约、是实现巧合"——测一个私有实现细节，等于把巧合**升格**为契约，与"守卫上下游真实行为"的意图相反。
- **方案②不够**：它只覆盖 forgotten 一个视图，**漏掉 V1/V2/V3 三条现状漏洞**（那三条里 forgotten 恰恰是安全的）。用它会让测试给出"已守卫"的假信心。

**D6 采用方案③（更宽、测行为、不测实现）**：**「渲染文本的成员可判定性」守卫**——

```
对每个视图 V：
    构造 fixture，使其包含一个"幽灵节点" g：
        · g.uri 真实存在（resolveUri 成功）
        · g 不在 V 的结果集内
        · 经 V1/V2/V3 任一未折叠字段，g.uri 被注入到某节点的正文/disclosure/keyword
    断言：从 render*(...) 文本按 parity 的同一抽取器抽出的 uri 集合
          === V 的结果集 uri 集合
```

**为什么这条比 ①② 都对**：
- 它测的是**渲染文本的可判定性**（我们的抽取器真正依赖的性质），不是 `snippet` 的实现。
- 它**同时**守住 V1/V2/V3 三条现状漏洞与 `snippet()` 的将来漂移——任何一条未折叠路径被打通，抽取集合就会多出 `g.uri`，测试立刻红。
- 它复用 parity 测试**同一的行锚抽取器**（§6.4 的行锚方案 + `resolveUri`），不引入第二套解析。**主 agent 已认定这条与 D4 的 T21 是同一件事**，故无需重复实现（归属见 6.5.5）。

### 7.2 服务端性能（工程口径，不含业务算法）

D6 只约束**工程层**的性能特性：

- **启动**：`openMemoryStore` 是 `node:sqlite` `DatabaseSync`（同步驱动，`driver.ts:28`），无异步连接池。启动成本 = 打开 DB + `createSchema`（幂等）+ 读 assets 目录（不预读文件内容；按需 `fs.readFile`）。`[推断]` 冷启动 < 50ms（不含 node 本身启动）。
- **静态资源**：MUST 每次请求 `fs.readFile`（不缓存到内存），理由：assets 总量小、避免 dev 期改文件不生效。**Cache-Control 策略是契约 §13 U2 的待拍板项**，D6 不越权裁定，但工程建议：dev 期 `no-store`（见 §9）。
- **无监听文件系统**：不做 `fs.watch`；变更检测走 `PRAGMA data_version`（契约 §7.4）。`change-detect.ts` 归 D1。
- **单进程单连接**：契约 §1.3 单机单人，不做 worker/cluster。

### 7.3 客户端体积

无 bundler（§2.1），浏览器直接 `import`（`index.html` 用 `<script type="module">`）。**代价**：多文件 ESM 会产生多个 HTTP 请求（本地 localhost，可忽略）；**收益**：零构建、可直接调试源码。`[推断]` 本地首屏 < 100ms。

### 8.1 ⭐ C1（**已裁决并回写契约**）：§4.2 原稿 #2「`package-lock.json` 零 diff」为假

- **契约原稿**：「`npm install` 后 `package-lock.json` 零 diff（因为没加任何依赖）」（§4.2 第 2 条）。

- **性质**：**契约措辞过强**，不是设计错误。"没加依赖 → 依赖图不变"的**意图**成立；"文件零 diff"**字面**不成立。

### 8.2 ⭐ C2（**已裁决并回写契约**）：§4.2 原稿 #3「`npm-shrinkwrap.json` 零 diff」为假，且漏了 install-lock

### 11.3 每条断言的**可观测事实**要求（防"测了 plumbing"）

- **写路径测试（若 D5 在本矩阵外补）MUST 断言 audit/revision 行事实产生**：即 `store.listAudit()` 出现对应 `event` 且计数 +1、`store.listRevisions(node_id)` 出现新版本。**不得**只断言 HTTP 200。
- **parity 测试 MUST 断言集合双向相等**（`toEqual`），不得 `toContain`。
- **security 测试 MUST 断言状态码 + `error.code` 双条件**，不得只看状态码。
- **visibility 测试 MUST 断言 `shadowed` 布尔值**，不得断言"节点消失"（契约 §6.6：shadowed ≠ 删除）。
- **守卫测试 MUST 用"幽灵节点"fixture**（真实 `uri` + 不在结果集内 + 经未折叠字段注入），MUST NOT 退化为"测 `snippet` 不含 `\n`"（契约变更 #7；见 §6.5.5）。
- **接口字段名一致性 MUST 纳入核验**（契约 §16 跨模块接口 10 条）：`current_version`、`EdgeDTO` 的 `uri`/`resolved_uri`、`parent_uri`、`/assets/` 前缀、`ViewDTO` 等——`api.test.ts` 断言 DTO 字段名与契约 §6.1/§16 逐字一致，不得自造同义字段。
- **T15 形态 MUST NOT 重现**：任何"自己构造坏输入再断言不通过"的用例都是恒真断言（§6.4.1），非空性一律走变异测试。

### 11.4 明确不做的验证

- 不做浏览器 E2E（契约 §4.3：客户端是薄壳，无浏览器测试）。
- 不做全量 `npm run check`（主 agent 统一执行）。
- 不做 `npm publish` 真实发布验证（用 `npm pack --dry-run` 代替）。
