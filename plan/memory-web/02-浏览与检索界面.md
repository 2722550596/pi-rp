# 02 · 浏览与检索界面（D2）

> 范围：`src/web/assets/index.html`、`assets/app.js`、`assets/app.css`、`assets/views/tree.js`、`views/node.js`、`views/search.js`。
> 即：**壳与路由 + 树浏览页 + 单节点详情页 + 搜索页**。
> MUST NOT 触碰：`src/web/*.ts` 服务端路由定义（D1）、原文日志与 TEMP 页（D3）、系统视图页与 `views/views.js`/`audit.js`（D4）、编辑动作与 `views/edit.js`（D5）。
> 契约依据：`00-共同上下文.md`（下称「契约」）。文中「§N」均指该文件章节号（引用本文自身时写「本文 §N」）。
> 事实标注：一切「现状是 X」带 `file:line`（相对 `packages/memory/`）；推断标 `[推断]`。

## 1. 一句话定位

> **本模块是记忆浏览器的「壳」与三个读页：把 `/api/tree`、`/api/node`、`/api/search` 三个 DTO 渲染成可点击、可键盘操作、不写库的 HTML。**

三条不可越界的前提（全部来自契约）：

1. **取数只用契约 §7.1 表里的端点。** 客户端没有任何 store 访问能力（`MemoryStore` 的方法是 Node 侧同步方法，`store.ts:181` `resolveUri`），因此**语义一律由 DTO 承载**，页内不做任何视图重算（§14 末段：D2 MUST 只调 `/api/view`，不得自己重算视图语义）。
2. **读路径不写库**（§9.1 纪律 1）。本模块三页**零 POST**：`views/{tree,node,search}.js` 里不得出现 `method:"POST"`。
3. **零依赖、零构建**（§1.3、§2.1）。三个 `.js` 文件里**不得出现裸模块说明符 import**；只允许相对路径（`./views/tree.js`）与浏览器原生 API。

本模块**不实现**：编辑/删除/恢复/移动/挂词/醒来清单/世界钟（D5）、`raw_log` 时间轴与 TEMP 页（D3）、七个 `MEM://` 视图的渲染（D4）。本模块**只提供侧栏里那 7 个视图的导航链接**与 D3/D4/D5 视图模块的**挂载点**。

## 2. 客户端路由方案

### 2.1 结论：手写 hash 路由，约 40 行，不引 router 库

```
#/tree?domain=core&uri=core://identity          ← 树浏览（默认页）
#/node?uri=core://identity/habits               ← 单节点详情（可深链、可复制）
#/search?q=薇拉&domain=core&limit=20             ← 搜索结果
#/raw?session=…&from=…&to=…&around=…            ← D3
#/temp                                          ← D3
#/view?name=recent&domain=core                  ← D4
#/audit?limit=50                                ← D4
#/deleted                                       ← D5（恢复入口）
#/edit?uri=…                                    ← D5
```

后 6 条**不在本模块实现**，只是本模块放进导航/链接的 URL 形状。§2.4 的挂载点约定保证它们能插进来。

### 2.2 为什么 hash 优于 history API（三条硬理由）

| # | 理由 | 依据 |
|---|---|---|
| H1 | **无服务端 rewrite。** history API 要求服务端对 `/node/xxx` 这类深路径返回 `index.html`（catch-all rewrite）。契约 §7.1 的静态路由只有 `GET /` 与 `GET /*` 两行、且是**静态资源托管**；为它加 rewrite 就是把冻结的路由表改宽。hash 的 `#` 之后**不进 HTTP 请求**，服务端永远只看到 `/`。⭐ **`GET /index.html` 不服务**（§16.5 只冻结 `/`；同一文件两个 URL 有缓存隐患）—— 与 H2 的 `file://` 直开不冲突。 | 契约 §7.1 静态行、§16.5 |
| H2 | **`file://` 也能跑。** 开发期直接双击 `dist/web/assets/index.html` 调试时，`history.pushState` 在 `file://` 下受限，hash 不受限。`[推断]` 这是「零构建、零工具链」路线的实际收益。 | — |
| H3 | **刷新/前进后退天然正确。** hash 变更即 `hashchange`，不需要把 `popstate` 与服务端深链对齐成两套路径。 | — |

代价（必须写明）：hash 模式下 `?` 是 hash 的一部分（`#/node?uri=…`），**不能用 `location.search` 读参数**，必须自己切分。这是本模块唯一需要手写的解析逻辑。

```js
// NEW: 手写 hash 解析。返回 { path, params: URLSearchParams }；无法解析时回落 "/tree"
function parseHash(hash) { /* … */ }

// NEW: 路由表。value 是动态 import 工厂 —— 浏览器原生按需加载，无需 bundler

  "/node":    () => import("./views/node.js"),    // 本模块

  "/view":    () => import("./views/views.js"),   // D4
```

- **路由表由本模块维护**（契约 §14：`assets/app.js` 归 D2）。兄弟模块要加/改条目 → 找 D2，不自行改 `app.js`。已 IRC 广播给 Main 并获批准（契约补充 #5）。
- 默认路由：hash 为空或无法匹配 → `location.replace("#/tree")`（不留脏历史条目）。
- 动态 `import()` 失败（D3/D4/D5 文件尚未落地）**必须**降级为页面内错误卡，不能白屏：见本文 §7.2。

### 2.4 视图模块契约（跨模块内部接口，本模块定义；已获 Main 批准）

```js
// 每个 assets/views/*.js MUST 导出：
export async function mount(el, params, ctx) { /* 渲染进 el */ return dispose; }
// el     : HTMLElement      —— 主区容器（已清空）
// params : URLSearchParams  —— 已解析的 hash 查询串
// ctx    : { api, toast, navigate, on, off, route } —— 见 §2.5
// 返回   : dispose?: () => void —— 卸载钩子（清 timer / 解绑 document 事件）
```

**用命名导出 `mount` 而不是默认导出**：默认导出在动态 `import()` 下拿到的是 `{default: fn}`，命名导出让 `mod.mount` 与 ROUTES 表一一对应、可读性更好，也避免兄弟模块误用默认导出。

本模块的三个页自身也遵守这个签名。

### 2.5 `ctx` 形状（唯一共享面）

```js
ctx = {
  api: {                                   // 唯一取数入口：只包 §7.1 里的 GET 端点
    meta:   (q) => get("/api/meta", q),
    tree:   (q) => get("/api/tree", q),
    node:   (uri) => get("/api/node", { uri }),
    search: (q) => get("/api/search", q),
    view:   (q) => get("/api/view", q),     // D4
    raw:    (q) => get("/api/raw", q),      // D3
    audit:  (q) => get("/api/audit", q),    // D4
    revs:   (q) => get("/api/revisions", q),// 本模块（deleted 列表归 D5）
    post:   (path, body) => post(path, body),// 只有 D5 用；本模块永不调用
  },
  toast,        // (msg, type) => void
  navigate,     // (hash) => void
  on, off,      // (event, handler) —— document 级事件绑定/解绑
  route: { path, params },
};
```

`ctx.api` 的键**只覆盖 §7.1 表里的路径**。§7.1 末句：「未列入的路由 MUST NOT 存在」。客户端同样自律：`get()` 只接受上述路径，不做任意 URL 拼接。

错误约定：`get()` 在 HTTP 非 2xx 时 **throw** 一个带 `.code`（§7.3 错误码）与 `.message` 的对象，由各视图决定怎么渲染 —— **不静默吞**（§7.3 末句「MUST NOT 静默降级」的精神对客户端同样适用）。

### 2.6 写后刷新：`memory:changed` 事件（跨模块内部接口，已获 Main 批准）

契约 §7.4 第 ② 条：客户端自己写完 MUST **主动刷新**，不得依赖轮询发现自己这次的写入。落地方式：

```js
// D5 在写请求成功后 MUST 广播：
document.dispatchEvent(new CustomEvent("memory:changed",
  { detail: { route: "/node", uri: "core://identity/habits" } }));

// app.js 监听 → 重挂当前视图；
// 树页额外监听 → detail.uri 命中已加载的层时，只失效该层缓存（本文 §4.9）。
```

用 DOM 事件解耦而非互相 import：D2 与 D5 是不同文件、不同作者，`app.js` 不该知道 D5 的实现细节。**本模块只注册监听者，永不派发此事件**（本模块无写路径）。

### 2.7 变更检测轮询的边界（按 §7.4 实测口径）

- 壳每 5s 调 `/api/events`；`document.visibilityState === "hidden"` 时**跳过**（不做无谓轮询）。
- 首次调用 `changed` MUST 为 `false`（§7.4：无基线不谎报）→ 只在 `changed === true` 时显示**横幅**：
  `⚠ 库已被外部会话修改 · [重新载入]`。
- **不自动重载**。用户在读长正文/搜索列表时自动刷新会打断阅读。点「重新载入」才重挂当前视图。
- 该横幅**不承担**「自己写完刷新」的职责 —— 那是 §2.6 的 `memory:changed`。§7.4 明确把 `/api/events` 的职责限定为「发现**外部**改动」，本设计与之完全一致。

## 3. 壳结构

### 3.1 `assets/index.html` 骨架（唯一 HTML 文件）

```html

  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta name="color-scheme" content="light dark">
  <title>记忆浏览器</title>
  <link rel="stylesheet" href="/assets/vendor/pico.min.css">
  <link rel="stylesheet" href="/assets/app.css">
</head>
<body>
  <nav aria-label="主导航">品牌 / 搜索框 / 主题切换 / 重新载入</nav>

  <div id="mw-shell">
    <aside id="mw-sidebar" aria-label="记忆树"></aside>

  <div id="mw-toasts" aria-live="polite" aria-atomic="false"></div>

  <script type="module" src="/assets/app.js"></script>

```

要点：

- **只有一个 HTML 文件**，全站不刷新（hash 路由）。
- **没有内联 `<style>`/`<script>`**。这与 `export-html` 先例**故意不同**：`packages/coding-agent/src/core/export-html/template.html` 靠 `{{CSS}}`/`{{SESSION_DATA}}`/`{{JS}}` 占位符内联（`src/core/export-html/index.ts:151-155` 用 `readFileSync` 读模板再替换），那是**单文件 HTML 导出**的产物；本模块是**多文件静态服务**，不需要内联。
- `#mw-main` 的 `tabindex="-1"`：路由切换后把焦点移过去，供屏幕阅读器播报新页（本文 §7.4）。
- `#mw-drawer` 是 `<dialog>` —— **Esc 关闭是浏览器原生行为**，不是我们写的事件监听。

### 3.2 静态 URL 契约（由契约 §7.1 `/` 与 `/*` 推导）

托管归 D1，但**路径由本模块提出**，D1 MUST 按此服务，否则整页 404。`copy-assets`（契约 §4.1）拷的是 `src/web/assets/.` → `dist/web/assets/`，所以 URL 前缀是 `/assets/`：

| 客户端请求 | 磁盘 |
|---|---|
| `GET /` | `dist/web/assets/index.html` |
| `GET /assets/app.js` | `dist/web/assets/app.js` |
| `GET /assets/app.css` | `dist/web/assets/app.css` |
| `GET /assets/views/tree.js` | `dist/web/assets/views/tree.js` |
| `GET /assets/vendor/pico.min.css` | `dist/web/assets/vendor/pico.min.css` |

`app.js` 里的 `import("./views/tree.js")` 相对本文件解析 → `/assets/views/tree.js`，与上表一致。**无需 import map、无需 bundler。**

> ⚠️ 给 D1 的硬要求：`/assets/*.js` MUST 带 `Content-Type: text/javascript`，否则浏览器拒绝执行 ES module；`/assets/*.css` → `text/css`。`.js` 发成 `text/plain` 是这类零构建服务的经典翻车点。缓存策略见契约 §13-U2（D1 定）。

### 3.3 Pico CSS：**Pico 免费给的 vs 要自己写的**

契约 §2.4 称 `pico.min.css` 为 "classless"。**实测需修正这个描述**：`https://cdn.jsdelivr.net/npm/@picocss/pico@2.1.1/css/pico.min.css`（本机 `fetch` 实跑）**83,319 字节**（与契约 §2.4 记录一致），且**含** `.container` / `.container-fluid` / `.grid` / `.modal-is-open` / `.modal-is-opening` / `.modal-is-closing` / `[role=button]` / `.secondary` / `.outline` / `.contrast` / `.striped` / `[aria-busy]` —— 这是 Pico 的**默认（含 utility class）构建**；真正的 class-less 是另一个文件 `pico.classless.min.css`，官方 modal 文档原文：「These classes are not available in the class-less version」。已写入本文 §9 冲突登记。

**这是好消息**：契约冻结的**文件名**不变，但我们白拿 `.grid` 与 `.modal-is-*`。因此——

### 3.4 布局

```
┌───────────────────────────────────────────────────────────┐
│ <nav>  记忆浏览器   [🔍 搜索…]         [主题][重新载入]     │
├──────────────┬────────────────────────────────────────────┤
```

- **侧栏与主区各自独立滚动**：两者都要 `overflow:auto` 且 `min-height:0` —— CSS grid 子项默认 `min-height:auto`，不显式置 0 就不会滚。属自写规则。
- 窄屏（`max-width:900px`）：侧栏变 `position:fixed` 抽屉 + 汉堡按钮。`[推断]` 记忆浏览以桌面为主，窄屏只需可用。
- **侧栏是持久化的**：切路由不重建树（树状态存在 `app.js` 的模块级状态里，本文 §4.9），避免每次翻页重拉整棵树。

### 3.5 暗色模式策略

三层，零依赖：

1. **默认跟随系统**：`<meta name="color-scheme" content="light dark">` + `<html>` **不带** `data-theme` → 命中 Pico 的 `@media (prefers-color-scheme: dark){ :root:not([data-theme]) }`（已实测该选择器存在于 2.1.1）。
2. **手动覆盖**：主题按钮循环 `auto → light → dark`，写 `<html data-theme="light|dark">`。实现在 `app.js` —— Pico **不提供**主题切换 JS，官方 modal 文档原话「Pico does not include JavaScript code」。
3. **持久化**：`localStorage["mw:theme"]`。键加 `mw:` 前缀。
4. **首帧闪白**：主题在 `app.js` **模块顶层**立即应用（早于任何 `await`）。`<script type="module">` 是 defer 语义，仍有极短窗口；`[推断]` 本地服务下不可见，**不**为此引入内联脚本（会破坏 §3.1 的「无内联」原则）。若评审坚持消除：备选是服务端模板注入 `data-theme`，但那动到 D1，**不建议**。

`app.css` 里的自定义规则**只用 Pico 变量**（`var(--pico-primary)` / `var(--pico-muted-color)` / `var(--pico-card-background-color)` / `var(--pico-del-color)` …）→ 自动跟随暗色，无需两套色值。

## 4. 树浏览页（`assets/views/tree.js` + 常驻侧栏）

树既是**一个路由页**（`#/tree`，主区显示某个 domain 的根层 + 面包屑），也是**常驻侧栏**。二者共用同一个渲染模块与同一份状态。

### 4.1 数据源（只用 §7.1 的两个端点）

| 端点 | 用途 | 频率 |
|---|---|---|
| `GET /api/meta` | ① domain 下拉（`listDomains`，`store.ts:1215`）② 世界钟（`getWorldTime`，`store.ts:1111`）③ 各表计数（侧栏底部概况） | 进页一次 + `memory:changed` 后 |
| `GET /api/tree?domain=&parentUri=&depth=` | 树的每一层 | 每次展开（懒加载） |

### 4.2 树 DTO —— 本模块**消费**的字段（D1 定义；这是 D2 对 D1 的最小字段要求）

```jsonc
// GET /api/tree?domain=core&parentUri=core://identity&depth=1
{
  "items": [{
    "node_id":     "n_mu1w43pp_7_y1m0do",  // 树内部 key（§10.1：不显示）
    "uri":         "core://identity/habits",// 显示与寻址主键
    "parent_uri":  "core://identity",       // §16.3：DTO 层字段名（**不是** parent_id）
    "domain":      "core",
    "importance":  7,                       // 10 = 最重要
    "is_stub":     0,                       // 1 = 占位
    "shadowed":    false,                   // §6.6 冻结字段名
    "content_head":"伊莱每天清晨…",           // 行内摘要，服务端截断 ≤60 字
    "has_children":true,                    // §16.4：画 caret 够用（叶子 → false）
    "child_count": 3                        // §16.4：**同时**要有，用来显示「这层有几条」
  }],
  "total": 3
}
```

**⚠️ 字段名以契约 §16.3 / §16.4 为准**（D1 的 `TreeNodeDTO` / `NodeDTO` 是唯一真相源），本模块消费时**不得使用 `parent_id`**：

| 本模块原先的写法 | 冻结后的正确字段 | 依据 |
|---|---|---|
| `parent_id` | **`parent_uri`** | §16.3：`parent_id` 是**数据层表列名**；DTO 层统一用 `parent_uri`（D1 `01:366,382` 刻意不暴露内码） |
| 只有 `child_count` | **`has_children` + `child_count` 两个都要** | §16.4：`has_children: boolean` 画 caret 够用；`child_count: number` 用来显示「这层有几条」 |
| — | `content_head`（D1 的 `contentHead(content, 60)`） | §16.4 |

**降级方案（若某字段缺失）**：缺 `has_children`/`child_count` → 一律显示可展开 caret，靠「空层响应」兜底；缺 `content_head` → 只显示 URI 末段。降级只改变信息量，不改变结构。

> 本文档原先登记的「冲突 4（tree DTO 缺字段）」**已由契约 §16.4 / P10 裁定**：D1 MUST 在 `/api/tree` DTO 里提供 `uri` / `node_id` / `domain` / `importance` / `is_stub` / `shadowed` / `child_count` / `content_head`，**并含 `has_children` 与 `parent_uri`**。不再是待办。

### 4.3 domain 分组

- 一级分组 = **domain**（来自 `/api/meta` 的 `listDomains`，`store.ts:1215-1219` 已 `ORDER BY domain`）。排序：`TEMP` **置顶**，然后 `core` / `history` / `meta` / `index` 按固定序，其余字母序。理由：`TEMP` 是动态区（§10.1），使用者最常看。
- 层级缩进：**以 DTO 的 `parent_uri` 为准**（§16.3；它是树边的 DTO 投影），缩进深度取 `uri` 的 `/` 段数近似值。二者若不一致（`[推断]` 可能出现在只经 alias 相连的历史数据上）→ 仍以 `parent_uri` 决定父子关系，缩进只作视觉提示，**不声称二者等价**。
- 侧栏底部固定**「系统视图」区**：7 条指向 `#/view?name=<x>` 的链接（`timeline|forgotten|wakeup|glossary|recent|index|diagnostic`，§8.1）。**本模块只渲染链接，不渲染内容**（§14：视图语义归 D4）。

### 4.4 `is_stub` 的视觉表达

`is_stub = 1` 是**占位节点**（`schema.ts:28` 列定义 + §6.1：正文为空、不进 FTS）。它**不是错误、不是垃圾** —— 它是树的骨架（`ensureStubAncestors` 会为层级自动造）。

- 行首图标 `◌`（空心圈）代替 `●`（实心）。
- 行加 `.mw-row--stub`：文字用 `var(--pico-muted-color)`，URI 末段后跟 `<small>占位</small>`。
- **不隐藏、不沉底**：折叠一个父目录不该让层级骨架消失。
- 点开详情页时 `content` 为空 → 详情页显示「占位节点，尚无正文」提示块，而不是一片空白（本文 §5.2）。

### 4.5 ⭐ `shadowed` 的视觉表达（§6.6 冻结语义，最容易做错的一处）

契约 §6.6 经两次修正后的最终口径：**默认按第一步无条件推导**；`shadowed=true` 表示「**原分支已回滚**」。UI 文案被**冻结**为 **「已遮蔽（原分支已回滚）」**，MUST NOT 写成「已隐藏」「当前角色看不到」—— 因为引擎对**别的会话**产生的 auto 节点是 `continue` **跳过**（`module.ts:344`），写成「当前角色看不到」就是错的。

本模块的视觉设计（四条，缺一不可）：

1. **可辨识**：行左侧 2px 虚线竖条（`.mw-row--shadowed::before`），文字 `opacity:.55`，行尾一个 chip：`已遮蔽（原分支已回滚）`。
2. **绝不删除**：`shadowed` 节点**照常出现在树里、照常可点、照常可展开子节点**。它不是 `deleted`（§10.1 禁用词表）。这条写进本文 §12 的断言。
3. **可解释**：`title` 属性与详情页脚注给出同一句解释，并链到 `#/raw`（D3）看那条 `active=0` 的原文行 —— 两个视角不打架（Main 广播 #2 对 D3 的要求）。
4. **过滤必须显式**：侧栏顶部一个复选框「**只看当前分支可见**」（契约 §13-U4 → 本模块拍板**提供**，默认**关闭**）。勾选后客户端按 `shadowed` 字段过滤（**不需要新端点**），并在侧栏底显式回执：`已按分支可见性过滤掉 12 条 [显示全部]`。**从不静默过滤** —— 否则使用者会以为记忆丢了。
   ⚠️ 这句回执**刻意不用「已隐藏」**：§10.1 禁用词表把 `hidden` 列为 `shadowed` 的禁用叫法，且本文 §12.4 有一条静态断言禁止 `assets/` 下出现「已隐藏」。过滤回执描述的是**本视图的显示行为**，措辞与 `shadowed` 的语义定义（「已遮蔽（原分支已回滚）」）分开，避免两个概念被同一句话黏上。

> 「角色视角 = 某 session」的第二步（`foreignSession`，§6.6 末段）**本模块不做**：它需要新 DTO 字段与「当前 session」选择器语义，超出 D2 范围。见本文 §10 待拍板。

### 4.6 `importance` 星级（极性：**数值越大越重要**）

§6.1 与 §10.1 双重强调：`importance` 10 = 最重要，0 = 边角料；**与 nocturne 的 `priority` 极性相反** —— nocturne `PriorityBadge.jsx` 里 `priority===0` 是最高档（rose），`priority>5` 是最低档（slate），正好反过来。**不得照抄语义**，只借「数字 + 小色块」的形态。

- 显示 `★N`（数字芯片 `.mw-imp`）。与 TUI 口径一致 —— `memory-views.ts:17-19` 的 `stars()` 就是 `` ` [★${importance}]` ``，所以 UI 与 `MEM://` 文本视图**读起来是同一个符号**（刻意的：使用者两边都看）。
- **不画 N 颗星**：10 分制画星会到 10 颗，树行会被撑爆；数字更省空间也更精确。
- 色阶（**越大越醒目**，5 档）：

  | importance | 档 | 视觉 |
  |---|---|---|
  | 10–9 | `.mw-imp--5` | `var(--pico-primary)` 实底 + 反色字 |
  | 8–7 | `.mw-imp--4` | primary 描边 |
  | 6–4 | `.mw-imp--3` | 默认中性（**5 = 普通**，`schema.ts:19` DEFAULT 5，必须看起来最不起眼） |
  | 3–1 | `.mw-imp--2` | muted |
  | 0 | `.mw-imp--1` | muted + `opacity:.7` |

- `importance` **不参与树的排序**：树序 = `created_at`（`store.ts:1197-1199` 的 `ORDER BY created_at` 就是这样）。排序是「看到的顺序」，改排序会让树每次刷新都跳动；想按重要度看 → `MEM://recent` / `MEM://diagnostic`（D4）。

### 4.7 大数据量（万级节点）：契约 §13-U3 —— **本模块给方案**

先破题：**万级节点不等于万级 DOM。** 三招叠用，纯 JS，**无虚拟滚动库**。

**第 1 招（主策略，覆盖 99% 场景）：懒展开 = DOM 上界。**
树在任何时刻只有「**已展开的层**」在 DOM 里。默认**只展开当前路由所在的祖先链 + domain 根层**（`#/node?uri=core://a/b/c` → 展开 `core://a`、`core://a/b`）。万节点库里 DOM 行数通常是 **几十**。

- 默认展开深度：**1 层**（domain 根）+ 当前路径祖先前缀。不因为「想看全貌」而默认全开 —— 那是 O(N)。
- **不提供「全部展开」按钮**。理由：万级库全展开 = 万行 DOM，必然卡；提供这个按钮等于提供一个卡死按钮。想纵览 → `MEM://index`（D4）。

**第 2 招（保护）：每层渲染上限 + 分页。**
单层子节点 > **200** 时，只渲染前 200，末尾插一行 `… 还有 1834 个 [载入更多]`。

- 这需要 `/api/tree` 支持 `limit`/`offset`（§7.1 的 tree 行**目前只有** `domain`/`parentUri`/`depth`）。**本模块建议新增 `limit`（默认 200）与 `offset`** → 见本文 §9 冲突 5 / §10，请 D1 + Main 裁。
- 若不新增：客户端只能「拿到全量后只画前 200」（省 DOM 不省网络与内存）。`[推断]` 万级单目录（罕见）网络也会慢，故**推荐新增**。

**第 3 招（保险丝，只在真的超限时启用）：固定行高窗口化。**
触发条件：**扁平化后的可见行数 > 500**（用户手动展开了很多层时）。

- 树内部维护**扁平数组** `visibleRows = [{node, depth, hasChildren, expanded}]`；**这是树的真实模型，DOM 只是它的投影**（键盘导航 §7.4 与窗口化都依赖这一点）。
- 每行固定高 `--mw-row-h: 28px`（CSS 变量，JS 读同一个值，避免两处漂移）。
- 容器 `<div class="mw-vspacer" style="height: N*28px">` + 绝对定位内层 `translateY(startIdx*28px)`，只渲染 `[startIdx, endIdx)`（前后各留 5 行 buffer）。约 40 行代码。
- 滚动用 `requestAnimationFrame` 节流。
- **焦点保护**：键盘移到某行时，若它滚出窗口，必须保证仍在渲染区间内（`ensureVisible(idx)` 在移动前后各调一次）。这是窗口化 + 键盘导航的经典冲突，**必须显式处理**，否则 Tab/↑↓ 会让焦点行消失。

**三招的关系**：第 1 招是**主策略**，第 3 招是**保险丝**。两者不冲突：窗口化作用于「扁平可见行」，与「这一层是否已从服务端取回」正交。

**实测要求（诚实标注）**：以上参数（200 / 500 / 28px / buffer 5）是 `[推断]` 的合理起点，**未实测**。本文 §12 给出实测清单与判据（万级 fixture 下：首屏 < 300ms、展开 < 150ms、滚动 60fps、同时 DOM 行数 ≤ 600）。若实测推翻，改的是**常量**，不是结构。

### 4.8 树行交互

- 单击行：`navigate("#/node?uri=…")` **并且**在 `#mw-drawer` 里打开（peek 模式），树上下文不丢。
- `Ctrl/⌘+点击`，或行尾的「↗」按钮 → 全页 `#/node?uri=…`（可复制的 URL）。
- 单击 caret（`▸/▾`）：只展开/折叠，**不导航**（`stopPropagation`）。caret 是可聚焦的 `<button aria-expanded>`。
- 键盘：见本文 §7.4。

### 4.9 树的缓存与失效（`app.js` 的模块级状态）

```js
// 树的缓存：key = `${domain}|${parentUri ?? ""}`，value = items[]
const treeCache = new Map();

// 失效规则：
//  1. 用户点「重新载入」或 §2.7 横幅确认 → treeCache.clear() + 重挂
//  2. memory:changed（D5 写完）→ 只删 detail.uri 的祖先层与自身层（精确失效，不整树重拉）
//  3. 展开一层后发现 child_count 与服务端返回不符 → 以服务端为准（DTO 是唯一真相）
```

缓存**不设 TTL**：本地单人使用，靠 ②③ 两条足够；加 TTL 只会制造「明明刚改完却看到旧树」的困惑。

## 5. 单节点详情页（`assets/views/node.js`）

一页同时服务两种进入方式：**全页**（`#/node?uri=…`）与**抽屉 peek**（`#mw-drawer`，由树页 §4.8 打开）。同一个渲染函数写进不同容器，不做两套。

### 5.1 数据源与 DTO

`GET /api/node?uri=<uri>` —— §7.1 指名的 store 调用：`resolveUri` `children` `listRevisions` `listAliases` `listRelated`（**另需 `listGlossary`**，见本文 §9 冲突 7）。

**关键事实（决定 §12-P1 的落地位置）**：客户端**没有** `resolveUri`。它是 `MemoryStore` 的方法（`store.ts:181-189`），跑在 Node 侧；浏览器里没有任何东西能解析 alias 或判断一条边是否悬空。因此契约 §12-P1 要求的「UI 展示边 MUST 用 `resolveUri(target_uri)` 而不是裸显示」—— **它的实现位置只能在服务端 `serialize.ts`，不可能在 D2**。这是本模块对 §12-P1 的核心识别，已列入本文 §9 冲突 2。

```jsonc
// GET /api/node?uri=core://identity/habits   （期望形状；D1 定）
{
  "node": { /* §6.1 全列 */, "shadowed": false, "parent_uri": "core://identity",
            "current_version": 3,                        // §16.2（D5 乐观锁用）
            "anchor_entry_id": "e2",                     // §16.14：D1 MUST 暴露
            "anchor_session_id": "s1",                   // §16.14：深链必须同时带它
            /* first_raw_id / last_raw_id：§16.14 裁定本期不暴露 */ },
  "children":  [ { uri, node_id, is_stub, shadowed, importance, content_head } ],
  "revisions": [ { version, created_at, content, editor_source, editor_model, uri } ],
  "aliases":   [ "old://identity/habits" ],            // listAliases → string[]（store.ts:790）
  "edges": {
    "outgoing": [ { direction:"outgoing", node_id, uri, resolved_uri, kind, dangling } ],
    "incoming": [ { direction:"incoming", node_id, uri, resolved_uri, kind, dangling } ]
  },
  "glossary":  [ { keyword } ],
  "path": ["core://", "core://identity"]               // 面包屑祖先链（含自身父链）
}
```

**这是契约 §16.1 冻结的 `EdgeDTO`**（真相源 = D1 的 `01-服务端与API.md:425-431`）。三条必须记住的语义：

1. **`node_id` 是「边的源节点」，两个方向都一样** —— ⭐ 不是我原先假设的「对端」。实测（契约 §16.1）：`listRelated` 两个分支都取 `edges.node_id`（`store.ts:768/773`）。`a→b` 时：`listRelated(a)` 与 `listRelated(b)` **都**回 `node_id === a`。**因此 MUST NOT 用 `node_id` 渲染可点链接** —— 那会把「指向 b 的边」画成指向 a 的链接。
2. **可点链接一律用 `uri`**（= 对端）：outgoing 时它是 `resolveUri(target_uri)` 的结果；incoming 时它是源节点反查出的 uri。`resolved_uri` 是 `uri` 的**同值别名**（D2 原名，为兼容保留）。
3. **`target_uri` 是裸存储值**，relocate 后可能是旧地址（§12-P1/P15）→ **MUST NOT 直接渲染为链接**，只在「悬空边」的降级提示里作为**文字**出现。

`dangling: true` ⇔ `uri === null` ⇔ `resolved_uri === null`。

（原先本模块提的 `source_uri` 命名**已作废** —— 契约 §16.1 明确：`direction` 已表达方向，不需要第二个字段。）

### 5.2 契约 §6.1 **逐列**的 UI 归宿

| 列 | UI 归宿 | 理由 |
|---|---|---|
| `node_id` | **隐藏**（仅 `data-node-id` 属性 + 技术信息折叠区） | §10.1：UI 路由主键是 `uri`，`node_id` 只在 DTO 内传递。排障/对账时仍要看到，故放折叠区 |
| `parent_id`（表列） | **隐藏**（等价信息由面包屑 `path` 与 DTO 的 `parent_uri` 表达） | §16.3：`parent_id` 是**数据层表列名**，DTO 层**故意不暴露**（D1 `01:366,382`）；UI 寻址主键是 `uri`，人看的是 URI 层级 |
| `domain` | **详情**（面包屑首段 + 技术信息区） | 已在 URI 前缀里可读，重复显示浪费空间 |
| `uri` | **主显示**：页面 `<h2>`，可复制、可「在树中定位」 | §10.1 唯一地址叫法 |
| `content` | **主显示**：正文块，`white-space: pre-wrap` | 核心内容 |
| `disclosure` | **主显示**：正文上方的醒目块「想起条件：…」 | 它是 `memorize` 的 `when`，使用者关心的召回条件 |

| `model` | **详情**（技术信息区），`null` 显示 `—` | 引擎侧元数据 |
| `anchor_entry_id` | **详情** + **条件链接**：**仅当同时有 `anchor_session_id`** 时才渲染 `#/raw?session=<anchor_session_id>&around=<entry_id>`（D3）；否则**只显示文字**，不渲染链接 | 契约 §16.14 裁定 D1 **MUST 暴露**这两个字段（D1 原稿说"故意不暴露"已作废）。⭐ **深链 MUST 同时带 `session`** —— `raw_log` 的唯一索引是 `(session_id, entry_id)`，跨 session 重复时服务端按 §16.9 返回 `bad_request`（详见本节末三条约束） |

| `first_raw_id` / `last_raw_id` | **详情：只显示为文字**（如 `概括原文窗口：#12–#38`），**不渲染链接** | ⚠️ 契约 §16.14 裁定 **本期不暴露**这两个字段（它们是库内 INTEGER 主键，与 `around` 的 string 口径不同）→ 本模块原设计的 `#/raw?from=a&to=b` 链接**已降级为不渲染**（若 D1 将来暴露，再补链接） |
| `created_at` | **详情**：页脚「创建于 …」+ 技术信息区 | §10.2：库内时间，次要 |
| `updated_ts` | **详情**：页脚「最后修改 …」 | 同上 |
| `world_ts` | **主显示**：`<h2>` 下的「世界时间 …」 | §10.2 ⭐ 故事语境优先展示 |
| `last_accessed_at` | **详情**：只读展示 + 文案「上次被角色主动想起：…（浏览不会更新此值）」 | §9.1 纪律 1 + 决策 31。**显式写出「浏览不更新」是刻意的**：否则使用者会怀疑这个值不可信 |
| `content_hash` | **隐藏**（技术信息折叠区） | 无人类可读意义，排障用 |
| `is_stub` | **主显示**（仅当 =1）：正文位替换为「占位节点，尚无正文」提示块 | 空正文会渲染成空白页，看起来像 bug |

#### ⭐ anchor 深链的三条硬约束（契约 §16.14）

1. **必须同时带 `session`**：`#/raw?session=<anchor_session_id>&around=<anchor_entry_id>`。缺 `session` 时跨 session 出现同名 `entry_id` 会让服务端按 §16.9 判 `bad_request`（`raw_log` 唯一索引是 `(session_id, entry_id)`）。
2. **只有 `auto` 节点有这两个值**：`manual` / `import` 节点的两列均为 `null` → 渲染 MUST **容错**：两块都不渲染，或显示 `—`，**绝不生成半截链接**（`around=undefined`）。这是 §12.3 #18c 的断言。
3. **`first_raw_id` / `last_raw_id` 本期不暴露** → 该行**只显示文字、不给链接**（见上表）。本模块**不自己把 INTEGER 转成 `around` 期望的 string** —— 口径不同，硬转会制造第二个 bug。

**技术信息折叠区**：一个 `<details><summary>技术信息</summary>`，把上表所有「详情 / 隐藏」项以 `<dl>` 渲染。**不另开页、不另开端点**（避免路由膨胀）。

### 5.3 署名渲染规则（§9.2，冻结）

规则：`editor_model === null && editor_source === "manual"` → 显示 **「用户（Web UI）」**。完整映射：

| `editor_source` | `editor_model` | 显示 |
|---|---|---|
| `manual` | `null` | **用户（Web UI）** ← §9.2 指定 |
| `auto` | `"claude-sonnet-4-5"` | `claude-sonnet-4-5`（模型 id **全等**才是「同款」，`docs/memory-system.md:104`） |
| `auto` | `null` | `自动写入（模型未知）` |
| `import` | `null` | `导入` |
| `null` / 未知 | `null` | `未知来源` |

**该渲染规则是读端 UI 的职责，不进 schema**（§9.2 原文）。实现为**唯一一个纯函数**，只此一处：

```js
// NEW: assets/views/node.js
export function editorLabel({ editor_source, editor_model }) { /* → string | null */ }
```

**⚠️ 曾阻塞，已裁定（契约 P6 / P12）**：`listRevisions`（`store.ts:443-447`）与 `listRevisionsByUri`（`store.ts:455-485`）**返回的字段里都没有** `editor_source`/`editor_model`。**裁定**：不动这两个方法的签名（另有 4 处消费：`tools.ts:572,583` + 3 个测试），由 **D1 在 `serialize.ts` 里另取这两列**。**P12 已补明文**：§9.1 纪律 2 **只约束写路径**，读路径只读取值不禁止（引擎自身先例：`slots.ts:103`、`temp-notify.ts:32`、`memory-views.ts:25`、`store.ts:1286`）。

因此本模块的**消费契约**是：`revisions[]` 元素 MUST 带 `editor_source` 与 `editor_model`（可为 `null`）。若某个实现忘了带，`editorLabel()` 返回 `null`，UI **整块省略署名**而不是显示「未知来源」（避免把「没取到」伪装成「取到了但未知」）。

### 5.4 revisions 列表

- 数据 `revisions[]`，store 侧是 `ORDER BY version`（`store.ts:445`），**UI 倒序显示**（最新在上）—— 使用者常态是看最近改了什么。
- 用 Pico `<table class="striped">`：`版本 | 时间 | 署名 | 长度 | 操作`。
- `操作` 列：「查看」是只读的（本模块）；**「恢复到此版本」是写操作 → 归 D5**。本模块只渲染按钮位并通过 DOM 事件转交（`<button data-action="restore" data-version="N">`，由 D5 在 `edit.js` 里事件委托接管；**本模块不 import D5**）。
- 版本内容预览：折叠 `<details>` 内以 `white-space:pre-wrap` 展示，**用 `textContent` 赋值**（见本文 §7.5）。
- 空状态：`该节点还没有历史版本（首版即 v1 的影子）` —— 依据 §6.3 / `store.ts:213` 注释：`insertNode` 不产生 revision。
- **必写的脚注**：`列表不含当前正文本身`。依据 `store.ts:330-336`：`updateNode` 改 `content` 时把**旧**内容归档为 revision，所以 revisions 是「被覆盖过的历史」，当前内容活在 `nodes.content` 里。不写这句，使用者会以为最新一版丢了。
- **只改 importance/disclosure 不产生 revision**（`store.ts:323-327`）—— 也写成脚注，否则「我改了重要度为什么没新版本」会成为反复出现的疑问。

### 5.5 ⭐ `aliases`（旧地址映射）与 `glossary`（触发词）必须分开显示

§10.1 明确警告：**`aliases` 与 `glossary` 是两张不同的表**（`schema.ts:52-55` vs `schema.ts:88-91`），**UI 文案与字段名 MUST 区分，不可都叫「别名」**。

两块并列，标题与说明都不同：

```
┌ 旧地址（alias）─────────────────────────────────────────────┐
│  old://identity/habits                                      │
│  说明：这个节点曾经住在这里。旧地址仍能解析到本节点。          │
│  （relocate 会写 alias，所以旧 URI 仍可访问 —— §6.4）          │
└─────────────────────────────────────────────────────────────┘

┌ 触发词（glossary）──────────────────────────────────────────┐
│  [清晨] [习惯]   [+ 添加]                                    │
│  说明：这些词进入全文索引，正文里没写也能被召回 —— §6.4。      │
└─────────────────────────────────────────────────────────────┘
```

- 标题用词**冻结**：`旧地址（alias）` / `触发词（glossary）`。**禁止**把任一块叫「别名」。
- `aliases` 来源 `listAliases(node_id)` → `string[]`（`store.ts:790-796`）。
- `glossary` 来源 `listGlossary(nodeId)` → `[{keyword, node_id}]`（`store.ts:813-823`）。
  **⚠️ 见本文 §9 冲突 7**：§7.1 的 `/api/node` store 调用清单列了 `listRelated`，**没列 `listGlossary`**，但同行又承诺 DTO「含 …glossary」。需 D1 补 `listGlossary` 调用；本模块按 §5.1 的 DTO 消费。
- 空状态各写各的：无 alias → `无旧地址（此节点从未被移动）`；无触发词 → `无触发词（正文里的词仍可被检索）`。

- `glossary.keyword` 是**全表唯一主键**（`schema.ts:88-90` `keyword TEXT PRIMARY KEY`）：同一个词不可能挂两个节点。「加词冲突」的错误处理归 D5，本模块只显示既有词。

### 5.6 edges 双向展示（§12-P1 + 契约 §12-P4 双约束）

`listRelated`（`store.ts:764-783`）**同时**返回 outgoing 与 incoming，本模块 MUST 分两块显示（有向图，方向不能丢）。

**§12-P1 的处理（本项目已实测复现的坑）**：`relocateMany` **从不重写 `edges.target_uri`**（`store.ts:598-695` 无 edges 处理；对比 `deleteCascade` 处理了，`store.ts:568`）。所以指向已搬迁节点的边，其 `target_uri` 仍是旧地址。

**⭐ 本模块核出的加重结论（已 IRC 报 Main 并获独立复现）**：坑比契约原稿更重 —— `listRelated` 的 incoming 分支是**裸等值匹配**：

> 证据（形式）：`store.ts:771-780` 的 incoming 侧查询用 `target_uri` 与**当前节点的 `uri`** 做**等值比较**（无 alias 展开、无 `resolveUri` 中转）。


节点 relocate 后，指向它的边其 `target_uri` 仍是旧地址 → **incoming 查询直接匹配不到，这条入边会静默消失**（不只是「显示旧地址」）。UI 侧无法补救（客户端没有 `resolveUri`）。

**DTO 形状已由契约 §16.1 冻结**（不再是"本模块的请求"，而是唯一裁定）：

| 字段 | 语义 | 本模块怎么用 |
|---|---|---|
| `direction` | `"outgoing"` / `"incoming"` | 分区渲染（有向图，方向不能丢） |
| `node_id` | **边的源节点**（两个方向都是它） | 仅作 `data-` 属性与排障；⭐ **不用于渲染链接** |
| `uri` | **对端 uri**：outgoing = `resolveUri(target_uri)?.uri ?? null`；incoming = 源节点反查的 uri | **唯一可点链接的来源** |
| `resolved_uri` | `uri` 的同值别名（兼容 D2 原名） | 与 `uri` 等价；若实现只给一个，优先读 `uri`，回退 `resolved_uri` |
| `kind` | 边类型，可 `null` | chip；`null` 则不渲染 |
| `dangling` | `uri === null` | 悬空边降级（见下） |
| `target_uri` | **裸存储值**，可能是旧地址 | ⭐ **只作「悬空边」提示的文字**，**永不**做链接目标 |

⭐ **incoming 侧的服务端义务**（P1 的正解，已在 §16.1 冻结）：`listRelated` 的 incoming 行原本只回 `node_id`（`store.ts:773` 的返回列是 `direction, node_id, target_uri, kind`）→ 客户端无法渲染入链。**D1 MUST 用该 `node_id`（= 源节点）反查 uri 填进 `uri`**。这就是 P1 缺的那一列。

（本模块原先提的 `source_uri` 命名**作废**，见 §5.1。）

**渲染规则**：

- **outgoing 行**：`<对端 uri 末段> <kind?> —→` + 链接到 `#/node?uri=<uri>`。
- **incoming 行**：链接到 `#/node?uri=<uri>`（= 源节点）+ ` —→ <本节点 uri>`。
- ⭐ **两行都不使用 `node_id` 做链接目标**：`node_id` 在 incoming 行是**源节点**、在 outgoing 行是**本节点**，语义随方向变化，直接拿来渲染必然画错（契约 §16.1 的实测更正）。
- `kind` 为 `null` 时不渲染空 chip（`edges.kind` 可为 NULL，`schema.ts:45-49`）。
- **悬空边降级（§12-P4：`edges` 表无 FK 约束，可以指向不存在的 uri）**：
  - 若 `dangling === true`（`uri === null`）→ 渲染成**不可点**的 chip：`⚠ 悬空边：<target_uri>（目标不存在）`，`.mw-edge--dangling`，用 `var(--pico-del-color)`。此处用 `target_uri` 是**刻意的**：它是唯一的残留线索，且**只作文字、不作链接**。
  - **若 DTO 缺 `uri` 与 `resolved_uri` 两者**（降级路径）：退化为「显示 `target_uri` 但**不加链接**」——不猜、不 404 跳转。**绝不因一条边崩掉整页**。
- 空状态：`无出边` / `无入边`，分开写（不要笼统一句「无边」）。
- **§12-P1 的 UI 警告**：若某条 **outgoing** 的 `target_uri` 与 `uri` 不同（且 `dangling === false`），说明这条边指向的是**旧地址**，UI 在该行后追加 `<small>（旧地址）</small>`。理由：这直接暴露引擎缺陷，且**不隐瞒** —— 使用者看到「旧地址」就知道 relocate 留了 alias，行为可预期。（incoming 侧不适用此判断：其 `uri` 是源节点反查值，与 `target_uri` 天然不同。）

### 5.7 面包屑与树定位

- `<nav aria-label="面包屑">` + `<ol>`，用 Pico 内置的 `--pico-nav-breadcrumb-divider`（默认 `>`）作为分隔符 —— **不写 CSS**。
- 面包屑项来自 DTO 的 `path`（服务端用 `implicitParentUri` 语义算，`store.ts:301-309`），本模块**不自己按 `/` 切**：URI 的 `://` 与 `/` 混用（`core://a/b`），客户端切分容易在 `core://` 这种根上出错。
- 面包屑最后一项是当前节点（`aria-current="page"`，不可点）。
- 「在树中定位」按钮：把 `#/tree?domain=<domain>&uri=<uri>` 推入路由，树页据此展开祖先链（§4.7 第 1 招）。

### 6.3 关键词高亮方案（不引库）

**约束**：`search()` 走纯关键词模式时，候选来自 FTS MATCH（`store.ts:993-1019` `searchNodeFts`，**服务端 jieba 分词**，`tokenize.ts:52` `tokenizeForSearch`）；中文没有空格，客户端**不能**用 `split(/\s+/)` 复现分词。

**方案：客户端只做「整串 + 拉丁词」的字面高亮，不假装自己会分词。**

```js
// NEW: assets/views/search.js
// 规则：把查询串按「连续 CJK 段」与「拉丁/数字词」切成人可读的片段，
//       对每个片段在摘要里做一次 indexOf（含重叠扫描），命中处包 <mark>。
function highlight(text, query) { /* → DocumentFragment */ }
```

具体规则（写在文档里，因为这是「不引库」的代价所在）：

1. **切分**：`query.match(/[\u4e00-\u9fff]+|[a-zA-Z0-9_]+/g)` —— CJK 连续段整体作一个片段，拉丁词各自成片段。**不做 bigram 切分**（`tokenize.ts:22-27` 的 `tokenizeForMatch` 是**打分**用的，其 bigram 是内部表示，直接拿来高亮会得到「薇拉」→「薇」「拉」这种碎片高亮，反而降低可读性）。
2. **匹配**：对每个片段在 `summary` 上做 `indexOf` 循环（允许重叠：`from = idx + 1`），记录区间，合并相交区间，再一次性建 `DocumentFragment`。
3. **大小写**：拉丁片段用 `toLowerCase()` 比较，但**保留原文大小写**。
4. **纯前端 DOM 构建**：**不用 `innerHTML`**（见本文 §7.5）；用 `document.createTextNode` + `document.createElement("mark")`。
5. **诚实边界**：若服务端是因**触发词/glossary** 命中（`recall.ts:1160-1162`：`buildGlossaryTerms` 让挂在节点上的词参与打分），正文里可能**根本没有该词** → 高亮为零命中。**这是正确行为，不报错、不提示「未找到」** —— 卡片照常显示摘要。可在诊断区标一行 `触发词命中`（当 `kw > 0` 且零字面命中时），把「为什么它出现在结果里」讲清楚。

### 6.4 搜索交互

- **入口**：顶栏 `<nav>` 里的 `<input type="search">`（**任何页面都能搜**，Pico 自带放大镜图标）。提交 → `navigate("#/search?q=…")`。
- **防抖**：**350ms**。参数依据 nocturne 的 `MemoryBrowser.jsx:319`（`setTimeout` + `searchSeqRef` 序号防乱序），本模块只借这个模式，不借它的数据层（§11）。
- **竞态防护**：自增序号，回包序号 ≠ 当前序号则丢弃（否则慢请求会覆盖新结果）。nocturne 同款（`MemoryBrowser.jsx:322,325`）。
- **`domain` 过滤**：侧栏当前 domain 作为默认过滤（可切「全部域」）。传 `/api/search?domain=`（§7.1 有该参数）。
- **`limit`**：默认 20，提供 20/50/100 三档。`/api/search` 有 `limit` 参数（§7.1）。
- **空查询**：不请求，显示提示 `输入关键词后回车搜索`。
- **`mode` 回显**：响应带 `mode`（`"keyword"` / `"vector"`，`recall.ts:365,378`）。若为 `"keyword"`，在结果头显示 `<small>关键词模式（未启用向量）</small>` —— 使用者否则不知道**为什么语义相近但用词不同的记忆没出现**。这是零成本的诚实。

### 6.5 空结果文案

分两种，**不同文案**（这是使用者最能感受到「有没有认真做」的地方）：

| 情形 | 文案 |
|---|---|
| `items.length === 0` 且 `q` 非空 | `没有匹配「<q>」的记忆。` + 第二行：`可以试试更短的词、或换个说法；也可以在任务要求里去掉 domain 过滤（当前：core）。` |
| `items.length === 0` 且 `domain` 过滤生效 | 追加按钮 `[在全部域中搜索]` → 重发不带 `domain` 的请求 |
| 请求失败（§7.3 错误） | 显示 `error.message` + `[重试]`，**不谎报为空结果** |

空文案**不含** emoji、不含感叹号（与 `docs/` 风格一致）。

### 6.6 ⭐ 读路径不动 `last_accessed_at`（§9.1 纪律 1）

**本节是纪律声明，不是实现章。** 三条：

1. `search()` 路径**本身不写库**：§9.1 原文已实测确认 `recall()` 不调 `markAccessed`（`store.ts:1146-1173` 无此调用），而 `search()`（`recall.ts:351-379`）只做 `buildPool` / `searchNodeFts` / `rank` —— 全是读。
2. **客户端无权也无意触发** `markAccessed`：`markAccessed`（`store.ts:1181-1185`）是写方法，本模块零 POST，所以不可能碰到它。
3. **UI 上要写出来**：详情页（§5.2 `last_accessed_at` 行）明确标注「浏览不会更新此值」。这一句是纪律的**可见化** —— 否则使用者会以为「我看了这么多次，怎么还说它沉睡」，进而怀疑整个系统的数据。

**反面命题（本模块 MUST NOT 做的事）**：不得为了让「最近搜索」好看而引入任何「访问计数器」「最近浏览」写回。若将来要做「搜索历史」，**只能存在 `localStorage`（`mw:searchHistory`），绝不进 DB**。这一条写进本文 §12 的断言清单。

## 7. 交互约定

### 7.1 加载骨架（三种，按形态选）

| 场景 | 形式 | 实现 |
|---|---|---|
| 首次进页 / 换路由 | 主区骨架（3–5 条灰色横条） | `.mw-skeleton`，`@keyframes` 微弱的 opacity 脉动；**尊重 `prefers-reduced-motion`**（Pico 已全局处理，自写动画必须也加该 media query —— 这是自写 CSS 的唯一无障碍硬要求） |
| 树节点展开 | 行内 caret 换旋转指示器 | 直接用 Pico 的 `[aria-busy="true"]`：给 caret 所在行加该属性即可，**零 CSS** |
| 搜索中 | 输入框尾部指示器 + 结果区**保留旧结果并降透明度** | 保留旧结果避免布局跳动；`aria-busy="true"` 在结果容器上 |

**不用全屏遮罩转圈**（那是 SPA 反模式；本地服务响应 <10ms 时遮罩只会闪烁）。

### 7.2 错误态

统一一个 `renderError(el, err)`：

| `err.code`（§7.3） | 显示 |
|---|---|
| `not_found` | `未找到：<uri>` + `[回到树]`（**不显示原始 message 的英文前缀**） |
| `bad_request` | `请求参数不对：<message>` + `[回到树]` —— 这是客户端 bug，同时 `console.error` 出完整 URL |
| `invalid_db` | 整页横幅：`数据库 schema 版本不匹配，无法读取。请先升级/迁移记忆库。` + **禁用所有导航链接**（继续浏览只会不断报错） |
| `forbidden_origin` | 横幅：`服务器拒绝了本页来源（§5 S2/S3）。若你是通过非 localhost 地址访问，请改用 http://127.0.0.1:<port>` |
| `internal` / 网络失败 | `无法连接记忆服务。` + `[重试]` |

**动态 `import()` 失败**（D3/D4/D5 文件缺失）单独一条：`该页面（<route>）尚未可用。` —— **不显示 stack trace**（本地单人工具，使用者要的是「知道为什么」而不是「知道哪一行」）。

### 7.3 空状态（各页不同，都写出来）

| 页 | 空状态文案 |
|---|---|
| 树：domain 无节点 | `这个域还没有记忆。` |
| 树：某父节点无子节点 | 不显示展开 caret（`child_count === 0`），**不给空状态**（展开空层是无声的失败） |
| 节点详情：无 children | `无子节点。` |
| 节点详情：无 revisions | `该节点还没有历史版本（首版即 v1 的影子）。` |
| 节点详情：无 alias / 无 glossary | 见 §5.5 |
| 节点详情：无出边 / 无入边 | 见 §5.6 |
| 搜索 | 见 §6.5 |

### 7.4 键盘可达性

**硬要求（四条）**：

1. **全部交互元素用原生可聚焦元素**：树行是 `<button>`（不是 `<div onclick>`）、caret 是 `<button aria-expanded>`、面包屑项是 `<a href="#/…">`（**用真实 `href`**，这样中键/右键复制链接都工作）。`<a>` 的样式用 Pico 的 `[role=button]` 或 `.secondary`。
2. **焦点可见**：一律用 Pico 的 `:focus-visible` 焦点环，**不覆盖** `outline`。
3. **焦点管理**：路由切换后 `el.focus()` 到 `#mw-main`（它有 `tabindex="-1"`，§3.1）。抽屉打开时焦点进 `<dialog>`（原生 `showModal()` 自动做焦点陷阱）；关闭后焦点回触发它的树行。
4. **快捷键（全局，注册在 `app.js`）**：

   | 键 | 行为 | 条件 |
   |---|---|---|
   | `/` | 聚焦顶栏搜索框 | 焦点不在输入框内（`e.target` 非 input/textarea/select）。**这不是「快捷键锦上添花」，而是与「不引入 UI 库」对等的必需品** —— 没有它，每次搜索都要用鼠标跨越整屏 |
   | `Esc` | 关抽屉 / 关 toast / 清搜索框 | 抽屉的 Esc 由 `<dialog>` 原生处理（HTMLDialogElement cancel） |
   | `↑` / `↓` | 在树内移动焦点 | 树有焦点时；按**扁平数组** `visibleRows`（§4.7）移动，跨层也连续 |
   | `←` / `→` | 折叠 / 展开（有子节点时）；`←` 在已折叠行上 → 移到父行 | 树有焦点时；需 `preventDefault` 防横向滚动 |
   | `Enter` | 打开聚焦行 | 树有焦点时 |

   **树用 roving tabindex**（整棵树只有一个 `tabindex="0"`，其余 `-1`），这是 WAI-ARIA `tree` 模式的标准做法：否则 Tab 要穿过几百个节点才能离开侧栏。`role="tree"` / `role="treeitem"` / `aria-expanded` / `aria-level` 一并给上。

5. **`aria-live`**：`#mw-toasts` 与 `#mw-banner` 都是 `aria-live="polite"`（§3.1 已给）。**搜索结果数量变化不播报**（连续输入会刷屏）；改为在结果容器上加 `aria-busy` 切换。

### 7.5 唯一的安全硬规则：`textContent` 优先

记忆内容（`content`、`summary`、`disclosure`、`uri`、`keyword`）**全部来自数据库**，且 `content` 可由模型写入。因此：

- **MUST** 用 `document.createTextNode()` / `el.textContent = …` 渲染这些值。
- **MUST NOT** 对它们使用 `innerHTML` / `insertAdjacentHTML` / `outerHTML`。
- 唯一例外是高亮函数（§6.3），它也必须**用 DOM API 构造 `<mark>` 而不拼 HTML 串**。
- 本模块**没有** markdown 渲染（§11 明确不搬 marked；`export-html` 的 `vendor/marked.min.js` 也不在我们的搬运清单里）。

理由不只是 XSS（本地单人、内容来自本机模型，风险有限），更是**正确性**：记忆正文里出现 `<`、`&`、`\`` 是常态（角色对话、代码片段），`innerHTML` 会把它们吃掉或变形。**用 `textContent` 是唯一能保证「看到的就是库里存的」的方式。**

### 7.6 Toast（借 nocturne 的模式，不借它的代码）

nocturne `components/Toast.jsx:20-26` 的模式很干净：`dispatchEvent(CustomEvent)` + 一个挂在壳上的容器监听。本模块照这个模式用 20 行实现（**不搬 JSX，不搬 Tailwind class**）：

```js
// NEW: assets/app.js
export function toast(message, type = "info") { /* dispatch "mw:toast" */ }
// 容器 #mw-toasts 监听；error 不自动消失（需手点），其余 5s 消失
```

**「error 不自动消失」是刻意的**（nocturne 同款，`Toast.jsx:92`）：错误信息被 3 秒吞掉是最常见的「这工具不告诉我出了什么事」。

### 12.1 前提：客户端逻辑**薄**，服务端测试覆盖大头

契约 §4.3 已定：「**不需要浏览器测试**：客户端是薄壳，逻辑都在服务端 DTO 与 views 里。客户端只做渲染。」

本模块的三页里，**没有任何业务语义**（不解析 alias、不判可见性、不算分数、不重算视图）。所以：

- **服务端测试（`test/web/api.test.ts`，D1 写）覆盖**：三页所需的**所有 DTO 契约**。
- **本模块的自动化测试：无。** 这不是偷懒 —— 加浏览器测试需要引入 headless browser（npm 依赖，§1.3 禁）或手写 DOM shim（测的是 shim 而不是浏览器）。
- **本模块的验证方式：人工浏览器实测**（§12.3），由主 agent 在落地后执行。

**⚠️ 但有一条例外，值得一个纯函数单测。** 见 §12.2。

### 12.2 值得单测的部分：四个纯函数（无 DOM、无依赖）

这四个函数（`editorLabel` / `splitQuery` / `highlight` / `parseHash`）是**客户端唯一可能写错的纯逻辑**，且都不需要 DOM。放 `test/web/client-logic.test.ts`（`[推断]` 归属：目录归 D1/D6，测试内容归 D2；请 Main 指定）。

| 用例 | 断言 | 为什么它必须存在 |
|---|---|---|
| `editorLabel({editor_source:"manual", editor_model:null})` | `=== "用户（Web UI）"` | §9.2 的**唯一**冻结渲染规则。回归它的代价是「使用者以为 Web 编辑是模型写的」 |
| `editorLabel({editor_source:"auto", editor_model:"m"})` | `=== "m"`（不是「自动写入（m）」） | §9.2：模型 id **全等**才判同款（`docs/memory-system.md:104`），显示必须就是 id |
| `editorLabel({editor_source:undefined, editor_model:undefined})` | `=== null`（省略整块，**不是**「未知来源」） | 区分「没取到」与「取到了但未知」（§5.3） |
| `splitQuery("薇拉 vera")` | `=== ["薇拉", "vera"]` | §6.3 规则 1；若退化成 bigram，高亮会碎成单字 |
| `splitQuery("core://identity")` | 含 `["core", "identity"]`，**不含** `"://"` | 用户常直接把 URI 贴进搜索框 |
| `highlight("薇拉是向导","薇拉")` | 返回的 fragment 里 `<mark>` 的 `textContent === "薇拉"`，且**总文本 === 原文** | ① 高亮正确 ② **不丢字符**（区间合并写错会吞字） |
| `highlight("aaa","aa")` | `<mark>` 覆盖重叠区间后文本仍 `=== "aaa"` | 重叠扫描（`from = idx+1`）的正确性 |
| `highlight("<b>hi</b>","hi")` | fragment 的 `textContent === "<b>hi</b>"`（**字面**） | §7.5：内容必须字面呈现，不得被当 HTML |
| `parseHash("#/node?uri=core://a/b")` | `{path:"/node", params:{uri:"core://a/b"}}` —— **`uri` 完整无损** | URI 里含 `://` 与 `/`，是 hash 解析最容易错的地方 |
| `parseHash("")` / `parseHash("#/nope")` | 都回落 `"/tree"` | §2.3 默认路由 |

**这些用例不需要 SQLite**（纯字符串进、纯结构出）。任务要求「写路径的测试 MUST 用真实 SQLite」—— 本模块**没有写路径**，故不适用；与之对等的是：**这些纯函数测试 MUST NOT 假装覆盖了 DTO 契约**（DTO 由 D1 的 SQLite 测试覆盖）。

### 12.3 人工浏览器实测清单（落地后由主 agent 执行）

**M1 · 壳与路由**
1. `http://127.0.0.1:<port>/` 打开 → 树页出现，无 console error。
2. 手改 hash 为 `#/node?uri=<真实 uri>` 回车 → 详情页正确渲染（**不刷新页面**）。
3. 浏览器后退/前进 → 页面正确切换。
4. `F5` 刷新 → 停在**同一页**（hash 被保留）。
5. 点侧栏 7 个视图链接 → 跳到 `#/view?name=…`（内容由 D4 渲染；若 D4 未落地，显示 §7.2 的「尚未可用」卡而**不是白屏**）。

**M2 · 树**
6. 万级 fixture（`[推断]` 由 D6 造）下：首屏可见行数 **≤ 600**，展开一层 **< 150ms**。
7. 同一层 > 200 个子节点 → 出现「载入更多」。
8. 勾选「只看当前分支可见」→ `shadowed` 行消失，且**底部出现「已按分支可见性过滤掉 N 条」回执**（**不是**「已隐藏 N 条」，见 §4.5 第 4 条的措辞说明）。
9. 取消勾选 → 行回来。**全程 `shadowed` 行从未被删过**（用 DevTools 确认它在 DOM 里只是被过滤）。
10. 键盘：Tab 进树（**只停一次**，roving tabindex），`↓↑` 连续移动跨层，`→` 展开，`←` 折叠，`Enter` 打开。
11. 键盘移到第 400 行（触发窗口化）→ 焦点行**始终可见**，不消失。

**M3 · 详情页**
12. 打开一个有 alias 的节点 → 「旧地址（alias）」与「触发词（glossary）」**两块标题不同**（§5.5），不会都叫「别名」。
13. 打开一个 relocate 过的节点 → outgoing 边显示 **`uri`（新地址）** 且行尾有「（旧地址）」标记；入边有 `uri` 时也渲染成可点链接（D1 按 §16.1 补了源 uri 后就该有）。
13b. ⭐ **`node_id` 语义验证**：造 `a→b`，分别打开 a 与 b —— **两边渲染出的链接都必须指向对方**。若任一方向点到了自己，说明实现误用了 `node_id`（契约 §16.1 的实测更正点）。这是本模块最容易被 D1 的错误注释带偏的地方。
14. 手工造一条指向不存在 uri 的边（D6 fixture）→ 显示 `⚠ 悬空边`（`dangling === true`），**页面其余部分正常**。
15. 打开一个 `is_stub=1` 的节点 → 显示「占位节点，尚无正文」，不是空白页。
16. 打开一个 `shadowed=true` 的节点 → 页面上出现 **「已遮蔽（原分支已回滚）」**（逐字），**不出现**「已隐藏」/「看不到」。
17. revisions 表：有一行脚注「列表不含当前正文本身」。
18. 若某 revision 的 `editor_source="manual"` → 署名显示 **「用户（Web UI）」**。
18b. ⭐ **anchor 深链（§16.14）**：打开一个 `source="auto"` 的节点 → 有「跳转到产生它的原文」链接，且 URL **同时含 `session=` 与 `around=`**（点进去 D3 页不报 `bad_request`）。
18c. ⭐ **容错**：打开一个 `source="manual"` 的节点（两列均为 `null`）→ **不渲染该链接**（也不出现 `around=undefined` 这种半截 URL）。这是 §16.14 第 2 条约束的断言。
18d. ⭐ **`first_raw_id`/`last_raw_id` 本期不暴露** → 该行**只有文字、没有链接**（§16.14 第 3 条）。若 D1 后来暴露了，再补链接。

**M4 · 搜索**
19. 输入中文词回车 → 有结果，摘要里的词被 `<mark>` 高亮，且**摘要其余文字未被吞**。
20. 输入含 `<`/`&` 的查询 → 结果区**不出现 HTML 解析效果**（字面显示）。
21. 把一个 URI 粘进搜索框 → 能命中该节点。
22. 搜一个不存在的词 → 出现 §6.5 的空结果文案（含「换个说法」建议），**不是一片空白**。
23. 快速连续输入 → 结果不闪回旧数据（序号丢弃生效）。
24. 按 `/` → 焦点进搜索框；在输入框里按 `/` → **不**进（避免打字被劫持）。
25. 结果头显示 `关键词模式（未启用向量）`。

**M5 · 纪律验证（最重要）**
26. **读路径不写库**：先记下 `nodes.last_accessed_at` 的快照与 `audit_log` 的行数 → 浏览树、开 10 个节点、搜 5 次 → **两者完全不变**。
    - 执行方式（`[推断]`）：用另一条只读连接比对（走 `/api/events` 的 `data_version`，或 `listAudit` 的行数），由主 agent 定。**关键是不能用被浏览的那条路径本身去验证**（自证无效）。
27. **零 POST**：DevTools Network 过滤 XHR → 上述操作**没有任何 POST**。
28. **不自动重载**：用另一个进程写库（触发 `/api/events` 的 `changed`）→ 只出现横幅，**当前页不重挂**。
29. **写后刷新**：由 D5 触发一次写 → 横幅**不**出现（因为自己看不见，§7.4），但页面**立即**刷新（`memory:changed` 生效）。

### 12.4 可机械核验的静态断言（`[推断]` 可并入 D6 的 check）

| 断言 | 检法 |
|---|---|
| 客户端无 npm 依赖 | `src/web/assets/**/*.js` 里 `import … from "<非相对路径>"` 命中数 === 0 |
| 客户端无写请求 | `assets/views/{tree,node,search}.js` 里 `"POST"` 命中数 === 0 |
| ⭐ **anchor 深链不得半截**（§16.14） | `views/node.js` 生成 `#/raw?` 链接时，**必须同时有** `anchor_session_id` 与 `anchor_entry_id`；两列任一为 `null` → 不渲染链接。断言：源码里不存在只凭 `anchor_entry_id` 拼 URL 的路径；手工用例见 §12.3 #18b–#18d |
| 无 `innerHTML` | 上述三个文件 + `app.js` 里 `innerHTML` 命中数 === 0（§7.5） |
| `shadowed` 文案正确 | `src/web/assets/` 下 `已隐藏` 命中数 === 0；`已遮蔽（原分支已回滚）` 至少出现 1 次（§4.5）。**注意：本文档自身不在此断言范围内**（文档里出现「已隐藏」是为了写禁令） |
| 术语正确 | `assets/` 下不出现 `priority`（§10.1 禁用词） |
| ⭐ **作废字段名零残留**（契约 §16.11 要求的机械核验） | `src/web/assets/**/*.js` 里 **`parent_id`** 命中数 === 0（改用 `parent_uri`，§16.3）；**`source_uri`** 命中数 === 0（改用 `uri`/`resolved_uri`，§16.1） |
| ⭐ **不得让用户输入 `MEM://`**（P17 / §16.8） | `assets/` 下不出现 `placeholder="MEM://` 之类的 URI 输入框；视图导航的 `name` 必须取自固定枚举（§4.3 的七条）。`grep -n 'MEM://' src/web/assets/` 只应命中注释/文档串，**不应**出现在任何 `<input>` 的 value/placeholder 绑定里 |
| ⭐ **边链接不得用 `node_id`**（§16.1） | `views/node.js` 里 `href` / `navigate` 的目标**不允许**由 `edge.node_id` 构造（只允许 `edge.uri` / `edge.resolved_uri`） |
