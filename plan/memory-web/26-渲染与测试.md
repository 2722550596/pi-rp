## §1 一句话定位

`revise` 当前的预览是**逐条文案摘要**（`替换「a」->「b」`），从不显示正文被改成什么样；本设计把它升级成 **edit 的完整模型**——`execute` 用 `generateDiffString` 把改前/改后正文算成权威 diff 塞进 `details`（Path A，落盘可审计），`renderCall` 在 `argsComplete` 时读库算一份预览 diff（Path B）。**去重：memory 不需要任何去重过滤**——call/result 是两个独立槽，**结果槽恒画权威**（§3.5，**不照抄** `edit.ts:232-234`，理由与反例留痕见 §11.1），batch 逐 mod 各画一段。

| 字段 | D6 怎么用 | 缺省时 |
|---|---|---|
| `ok` | `executeRevise` 汇聚循环的第一道过滤（`!r.ok` → 跳过） | — |

### §3.2 Path A：`executeRevise` 汇聚

在 `:663 const results = mods.map(...)` 之后、`:665 return` 之前插入：

```ts
const MAX_DIFF_BYTES = 8192;   // §5
const MAX_DIFF_ITEMS = 50;     // §5
const diffsForRender: Array<{ uri: string; diff: string; firstChangedLine?: number }> = [];
const beforeForRender: Array<{ uri: string; content: string }> = [];
let truncated = false;
for (const r of results) {
	if (!r.ok || r.beforeContent === undefined) continue;
	const after = store.resolveUri(r.uri);
	if (!after) continue;                       // 竞态兜底：mod 之间 self-delete 不可能，但别让渲染崩
	if (after.content === r.beforeContent) continue;   // 编辑是 no-op（例如 line_content 与原文相同）
	const { diff, firstChangedLine } = generateDiffString(r.beforeContent, after.content);
	if (diffsForRender.length >= MAX_DIFF_ITEMS) { diffsTruncated = true; continue; }
	let shown = diff;
	if (Buffer.byteLength(diff, "utf8") > MAX_DIFF_BYTES) { shown = cutDiff(diff, MAX_DIFF_BYTES); truncated = true; }
	diffsForRender.push({ uri: r.uri, diff: shown, firstChangedLine });
	beforeForRender.push({ uri: r.uri, content: r.beforeContent });
}
// details 的两个 flag 只在真截断时出现（§2.2）；不截断时 details 仍是四键
...(truncated ? { truncated: true } : {}),
...(diffsTruncated ? { diffsTruncated: true } : {}),
```

`NEW` 辅助 `cutDiff(diff, maxBytes): string`：**按整行边界切**（保前 N 行直到超预算），末尾追加一行 `⇢ （已截断）`。**MUST 按行切**：切在行中间会产出一行不满足 `diff.ts:9` 正则的内容 → **该行被静默涂灰**（§8 T8）。**MUST 用 `Buffer.byteLength` 计 UTF-8 字节**（中文正文下 `string.length` 低估约 3 倍）。
**逐条「漏了会怎样」**：

- **`!r.ok` 过滤**：失败 mod 的 `beforeContent` 本就 undefined，但显式过滤更防御（D4 若误在失败分支填了值）。漏了 → 渲染器在失败行下画一段 diff，误导。
- **`after.content === r.beforeContent` 判据**：用户可能 `line: 3, line_content: <原文>`——写回相同内容。`generateDiffString` 对相同输入返回 `""`（`Diff.diffLines` 无 change part → `output` 空）。漏了 → 出现一个空字符串 diff 项，渲染器要额外判空（见 §7）。
- **`generateDiffString` 而非 `generateUnifiedPatch`**：`patch` 是 `@@` hunk 头格式，`parseDiffLine`（`diff.ts:9`）对 `@@` **返回 null → 涂灰**（实测，§4.2）。漏了（用 patch）→ 整个 diff 灰掉，用户看到「看起来坏了」但无报错。
- **`cutDiff` 按行切 + 按字节计**：见上条。**`MAX_DIFF_BYTES`/`MAX_DIFF_ITEMS` 是常量，不是可配项**——避免 `details` 形状随设置漂移（审计要能假设上限）。
- **`diffsForRender.length >= MAX_DIFF_ITEMS` 放在 push 之前**：截的是「第 51 个及以后」的 mod，保持前 50 项与 `results` 的顺序一致。漏了（放之后）→ 边界处会多一个（`> 50` 而非 `>= 50`）。**`total` 数由 `diffsForRender.length` 自己携带，不需要额外字段**。

### §3.5 去重（**不**照抄 `edit.ts:232-234`——理由与本节的**反例留痕**）

现状原文（实测）：`const resultDiff = result.details?.diff; if (resultDiff && resultDiff !== previewDiff) { return renderDiff(resultDiff, { filePath: rawPath ?? undefined }); } return undefined;`

**memory 的对应物不是一个 diff 而是 N 段**，且**两槽不是同一容器**（见下）。⇒ 正确规则：

```ts
// ✅ 正确：结果槽恒画权威（契约 §6.3）
const authoritative = readDiffs(result.details);     // Array<{uri,diff,firstChangedLine?}> | undefined
// 无过滤、无「与预览相同就跳过」——详情见下方反例。
```

**为什么必须恒画**：`edit` 的 `renderResult` 敢写「相等就 `return undefined`」，是因为它的 `renderCall` 与 `renderResult` **共用同一个 `EditCallRenderComponent`**（`edit.ts:397` 取 `context.state.callComponent`，`:405-425` 把 preview 塞进它）——预览与权威是**同一容器里的同一份内容**，画两次才是真重复。
memory **不同**：`renderCall`/`renderResult` 是**两个独立槽**，`tool-execution.ts:286`（call）与 `:307`（result）各自 `renderContainer.addChild(...)`。预览画在 call 槽、权威画在 result 槽。⇒ **在 result 槽里画权威段，永远不会与 call 槽的预览「重复」**（它们渲染到不同位置）。

**那「重复控制」到底在哪里？** 在**槽内**：`renderReviseResult` 可能因 `tool_execution_update` 的流式多次 `updateResult` 被反复调用；但 `tool-execution.ts:278 renderContainer.clear()` 每次 `updateDisplay` 先清空，故**同一槽内天然不累积**——无需任何 diff 比较。**结论：memory 侧不需要任何去重过滤。**
> ```ts
> // ❌ 错误：照抄 edit 的「相等就跳过」
> const toDraw = authoritative.filter((a) => previews?.find((p) => p.uri === a.uri)?.diff !== a.diff);
> ```
> 它「看起来」是对 `edit.ts:232-234` 的合理推广，实则引用未定义的 `previews` 变量（预览在 **call** 槽的 `state` 里，**result 槽的 `context.state` 是同一对象但那不是判据**），且**对常见输入给出与 §3.5 结论相反的行为**：预览与权威相同（`argsComplete` 读库成功且 execute 期间无第三方改动，即**最常见路径**）时 `toDraw` 为空 ⇒ **result 槽什么都不画** ⇒ 正是本节要避免的「**预览有、权威无**」回归，且与契约 §6.3「结果槽恒画权威」直接冲突。
> **判据**：**凡是「因预览已画而跳过权威」的过滤都是错的**——两个槽渲染到不同位置，不存在跨槽重复。

现状 `renderMemoryResult` **已经**满足（`:146` 先取 `lastComponent` 或 `new Text`，`:150` 空文本也 `return component`）。改造后 MUST 保持：**在读取 `details` 前的任何一步都不得 early-return `undefined`**（拆分后的 `renderMemorizeResult` / `renderReviseResult` / `renderMemoryResultBody` 三个函数都适用）。

> **术语订正（原文措辞不规范）**：旧稿写「memory 的判据推广为逐段比较」，容易被读成「要做段级过滤」。**正确表述：`edit` 的整串比较在 memory 上无对应物——正确实现是「不做比较、恒画」。**

**这条是对契约 §6.3「去重：照抄 `edit.ts:232-234`」的必要修正**（已报主 agent，获准按 D6 口径实现）——`edit` 的两槽共用 `callComponent`（`edit.ts:383`/`:397`），memory 的不共用。**主张与证据见 §11.1。**

## §7 错误边界与降级

### §7.1 Path B 拿不到 store（`store` 未注入 / 未就绪）

`createMemoryToolRenderers(store)` 在 `_createMemoryModuleHost` 内**同步**建，`store` 已在 `:4295` await 过，**不存在未就绪窗口**。但 `renderCall` 仍 MUST 容忍：`store.resolveUri` 抛错（DB 被外部锁/删除）→ 整体 `try/catch`，降级为现状文案摘要。

### §7.2 export-html 的 `argsComplete: true`（契约 §6.2 的「致命缺陷」）

**事实**（实测 `tool-renderer.ts:82-96`）：`createRenderContext` 把 `argsComplete` 写死 `true`，`renderCall`/`renderResult` 都走它。⇒ 导出时 Path B 会读**当前库**（改后），而当前库可能在导出时**已不存在**（导出的是别的机器的会话）或**早已被后续编辑覆盖**。

**三个候选，D6 裁定选 (c) 为主 + (b) 为辅（主 agent 已批准，(b) 为一次性越界授权）**：

- (a) **Path B MUST 把结果只放进 `state`，且带 `argsComplete` 的「改前性」前提**：无法从导出侧证伪，故 (a) 单独不足。
- (b) 给导出传 `argsComplete: false`（改 `tool-renderer.ts:90`）：会让 `renderReviseCall` 的预览逻辑整段不跑 → 导出里 call 槽退回文案摘要。**这是正确性修复**，一行改动，且 `argsComplete: false` 在导出语义上**本来就是对的**（导出的会话里工具早已执行完，没有「参数未定稿」的概念，但也没有「实时预览」的概念——它该呈现的是**历史**，而历史由 Path A 提供）。
- (c) **导出以 Path A 为唯一权威**：`details.diffs` 从 JSONL 原样拿到，不依赖任何 live store。

**裁定（主 agent 已批准，2026-09-16）：(c) 为主 + (b) 为辅，且 (b) 得到一次性越界授权**（`tool-renderer.ts` 仅此一处、仅此一行）。**(b) 的回归已实测**（见 §10.4）：`argsComplete: false` 下 `edit` 的 `renderCall` 正常返回、不抛、无预览 diff；`edit` 的 `renderResult` 在 `argsComplete: false` 下**照样画出 `details.diff`**——所以导出不会掉 diff。

### §7.3 `diff` 为空串

`generateDiffString(a, a)` 返回 `{diff: "", firstChangedLine: undefined}`。渲染侧 MUST 跳过空串（不画空行、不画段头）。见 §3.2 的 `after.content === r.beforeContent` 已在上游挡一次，渲染侧再挡一次（两道防线，因为 details 可能来自外部）。

### §7.4 大库慢读

Path B 每次 `argsComplete` 一次 `resolveUri`（走 `uri` 索引 + 别名回退）。120 节点库实测无感；即使 10k 节点也是单行 PK 查询。**MUST NOT** 在 `renderCall` 里调 `search`/`recall`（那是 O(全库)）——契约 §6.3 硬约束 5 的「纯 SELECT」在此含「只做点查」之意。
