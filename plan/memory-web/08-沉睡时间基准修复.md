# 08 — forgotten/diagnostic 沉睡时间基准修复

## 根因

`MEM://forgotten` 与 `MEM://diagnostic` 的"沉睡天数"运算**两侧基准不一致**：

```ts
// 修前 memory-views.ts:49 / :184
const nowDays = epochDays(store.getWorldTime() ?? new Date().toISOString()) ?? 0;
//                        ^^^^^^^^^^^^^^^^^^^ 世界钟（故事内时间，如 2020-09-28）
const days = nowDays - epochDays(n.last_accessed_at ?? n.created_at);
//                       ^^^^^^^^^^^^^^^^ 真实墙钟（markAccessed/insertNode 写 new Date()，如 2026-09）
```

`getWorldTime()` 存在时（RP 库通常都有，elias 库 = `2020-09-28`）就用世界钟当"现在"，而
`last_accessed_at` / `created_at` 全是真实时钟写的。2020 减 2026 → **恒为负**的荒谬天数。

实测（`/home/yoshix7ti/world/magnolia/elias/.pi/memory.db`，world_time=2020-09-28）：

- `forgotten`：116 条全是负数，范围约 −2077 ~ −2178（修前 spike 输出见下）。
- `diagnostic`：`days > threshold` 恒不成立 → `stale` 分类**永远为空**，
  库健康诊断的"沉睡"一路彻底失效（修前输出 `No issues found. Memory system is healthy.`）。

## 改动点（只动 `memory-views.ts`）

1. 引入已导出的 `toEpochDays`：`import { formatRelativeWorldTime, toEpochDays } from "./recall.ts";`
2. `renderForgottenView`（原 :49）：`nowDays = toEpochDays(new Date().toISOString()) ?? 0`
3. `renderDiagnosticView`（原 :184）：同上
4. 两处 `epochDays(...)` 调用改为 `toEpochDays(...)`
5. 删除私有 `epochDays` 实现（原 :75-80）

`renderWakeupView`（:89 的 `store.getWorldTime()` 作标题）**未动** —— 那是纯展示，
显示故事内世界时间是正确语义。

## 为什么 `recencyBoost` 不改

判据：**天数运算的两侧必须同基准**。

| 用途 | 位置 | 两侧 | 基准一致？ |
|---|---|---|---|
| recall 打分 recency 加成 | `recall.ts:140 recencyBoost(doc.world_ts, nowDays)`，`nowDays` 来自 `module.ts:376` / `tools.ts:372` / `store.ts:1154` | `docTs = world_ts`（写入时世界钟） ↔ `nowDays = world clock` | ✅ 世界钟 ↔ 世界钟 |
| forgotten/diagnostic 沉睡天数 | `memory-views.ts`（本任务） | `last_accessed_at ?? created_at`（真实钟） ↔ `nowDays`（原世界钟） | ❌ 一实一虚 → **修** |

核对证据：

- `recall.ts:87 toEpochDays` 与 `store.ts:2` 的 `nowDays` 都基于 `getWorldTime()`；
  `world_ts` 由 `store.ts:238` 写入 = `input.world_ts ?? this.getWorldTime()`，即同源世界钟。
- 用户拍板："MEM那个forgotten毕竟是要拿last_accessed_at来判断，那肯定要用真实时间来算啊。"
  forgetten 判据对象是 `last_accessed_at`（真实钟），故必须换成真实钟；
  `recencyBoost` 判据对象是 `world_ts`（世界钟），基准本来就一致，**MUST NOT 动**。

## `epochDays` / `toEpochDays` 重复 → 已消除

`memory-views.ts` 本就 `import { formatRelativeWorldTime } from "./recall.ts"`，
新增 `toEpochDays` 无引入新依赖、无循环依赖，故直接统一改用导出的 `toEpochDays`，
删除私有重复实现（原地留一行备注说明）。
