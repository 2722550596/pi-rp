## 1. 目标与非目标

### 1.1 预期效果（明月 2026-09-25 定）

pi-rp 当前把所有注册工具（原生 7 个 + 扩展自定义 + SDK customTools）全量塞进每轮请求的 function calling 列表；工具多时上下文爆炸、选择准确率下降。本功能提供：

- **客户端合成的 tool_search 机制**：把低频工具的 schema 从请求中折叠，代之以一个合成的 `tool_search` 元工具；模型按需搜索，命中后工具在后续轮次可用。
- **provider 无关**：不依赖任何 provider 的服务端机制；所有 provider 上都正确工作。
- **收敛既有机制**：复用 pi-rp 已有的 deferred tools 通道（§3.2），不是并行造第二套。
- **自适应激活**：工具少时零开销（行为与现在逐字节一致）；工具多时自动激活。

### 1.2 已拍板决策（MUST NOT 重新论证）

- **不做语义/embedding 检索**。搜索 = 名称/描述上的正则与关键词匹配（业界目录 <100 时足够，见 01 §5）。未来可加，本期不做。

## 2. 核心裁定（主代理拍板，子文档 MUST 遵守）

### R1 · 收敛裁定：补全既有 deferred 通道，不造第二套

pi-rp 已有 transcript-driven deferred 机制（§3.2）：`toolResult.addedToolNames` 标记 → `splitDeferredTools()` 分组 → Anthropic `defer_loading`/`tool_reference`、OpenAI Responses `additional_tools`/`tool-search_call`、Kimi `deferredToolsMode` 各通道展开。它缺的只是三样：**折叠来源**（没有工具会在启动时被折叠）、**搜索入口**（模型无法主动发现）、**compaction 后的状态保持**。

本设计的 tool_search 是给这条既有通道补入口，**provider adapter 层零改动**（或仅暴露测试后证实的最小修补）。

### R2 · 双层折叠模型（本设计的骨架）

1. **coding-agent 层**（ToolSearchManager，M1/M2）：维护折叠集合与 discovered 集合。**未发现的折叠工具不进入 active 工具集合**——所有 provider 一致受益：请求里根本没有这些 schema。这是「客户端合成、provider 无关」的主体。
2. **provider 通道层**（既有机制，零改动）：tool_search 命中的工具回填 `addedToolNames` 标记；支持原生 deferred 的 provider（Anthropic / OpenAI Responses / Kimi）自动走引用通道保持缓存前缀稳定；不支持的 provider 上它们就是普通工具 schema，可正常调用。

两层叠加后各 provider 的行为（设计 MUST 逐条验证；**第 3 列已按 D20 裁决修正**）：

| provider 场景 | 折叠·未发现 | 折叠·已发现未调用 | 折叠·已调用过 |
|---|---|---|---|
| Anthropic（`supportsToolReferences`） | 不在请求中 | 在请求中，`defer_loading: true`，历史中 `tool_reference` 展开 | **继续留在 deferred 通道**（`defer_loading` 保持；模型靠历史中已展开的 `tool_reference` 与 toolCall/toolResult 对继续调用；schema 永不进缓存前缀——#6474 有意的 cache-friendly 行为） |
| OpenAI Responses/Codex（`supportsToolSearch`/`supportsAdditionalTools`） | 不在请求中 | `additional_tools` 追加或 `tool_search_call`/`tool_search_output` 通道 | 继续走既有通道（历史回放保证模型可继续调用） |
| Kimi（`deferredToolsMode: "kimi"`） | 不在请求中 | 恢复进 `params.tools` | 普通 schema 进 `params.tools`（可继续调用） |
| 其他（Gemini/Vertex/Mistral/Bedrock 等） | 不在请求中 | 普通工具 schema | 普通工具 schema |

> ⚠️ **D20 裁决（2026-09-25，M6 上报）**：`splitDeferredTools` 的 `usedNames` 是**加入时刻的一次性守卫**（`packages/ai/src/utils/deferred-tools.ts:27`），工具进入 `deferredNames` 后**永久保留**在 deferred 组——不存在「调用后退回 immediate」的机制，`packages/ai/test/deferred-tools.test.ts:420-446`（`preserves an additional_tools marker after the loaded tool is used`）锁定了该保持行为。三个选项裁定：**(c) 修正契约断言**，不改 adapter、不在 coding-agent 层提升。理由：① 现状行为是 cache-friendly 的有意设计；② 四类 provider 场景下模型都能继续调用已用过的工具（Anthropic 靠历史 `tool_reference` 展开、OpenAI 靠历史回放、Kimi/其他靠请求内 schema），**对功能正确性零影响**；③ (a)(b) 都违反 R1「provider adapter 零改动」且引入无收益风险。**与 TanStack 的差异点**：TanStack 的 discovered 工具变为普通工具；pi-rp 借原生通道让已调用工具继续折叠 schema，**优于** TanStack——实现者 MUST NOT 按 TanStack 直觉「修正」此行为。M6 的 called 格断言按本表修正。

### R3 · 命中即签名：tool_search 的执行产物

`tool_search` 工具的 `execute` 返回 `AgentToolResult`，其 `addedToolNames` 字段 MUST 列出本次发现且此前未发现过的工具名（字段已存在于 `packages/agent/src/types.ts:362-378`，由 agent-loop 自动传播进 `ToolResultMessage`，`packages/agent/src/agent-loop.ts:784-788`）。**同时** ToolSearchManager 调用 coding-agent 层的工具集刷新（等价 `setActiveToolsByName` 语义，生效点为下一轮，`packages/coding-agent/src/core/agent-session.ts:1321-1343`）。返回正文中给出各工具的一句话用途描述（来自 description 首句），帮助模型决定下一步调用哪个；**完整 schema 由引擎在下一轮注入，不在返回正文中重复**（与 TanStack 返回 schema 的做法不同，理由：pi-rp 的工具下一轮就以真实工具身份出现，正文重复 schema 纯属浪费）。

### R5 · 激活策略冻结

- **auto 模式**：`estimateToolsTokens(潜在折叠集合) ≥ thresholdPercent% × 模型 contextWindow` 时激活；**估算对象 = 最终 deferrable 生效且不在任何强制 eager 集合（原生 7 / reservedTools / allow 白名单）中的工具**——强制 eager 成员永不折叠、不计入分母（2026-09-25 实现期裁决，ImplConfigSurface 提请）。估算函数现状为 `packages/ai/src/utils/estimate.ts:109-111`（未导出，4 chars/token 粗估），M5 负责导出/包装，不新造估算器。
- **contextWindow 无效**（缺失或 ≤0）时 `auto` 保守不激活并记录诊断（2026-09-25 冲突裁决 C3 采纳 M5 方案）。
- **allow 强制 eager**（2026-09-25 裁决，采纳 M5 建议）：`tools.allow` 白名单中的工具视为用户显式要求随时可用，一律强制 eager，不参与折叠。
- **deferrable 归一化归属**（2026-09-25 裁决 C3）：`deferrable` 缺省判定（原生 7 → false；扩展/SDK customTools 默认 true；显式声明优先）在 registry 构建点归一化为布尔，由 M5 的输入准备完成；ToolSearchManager 不读 sourceInfo（采纳 M1 §12 推荐方案）。**函数名/签名统一冻结（2026-09-25 二次裁决）**：`normalizeDeferrable(definition: ToolDefinition, sourceInfo: SourceInfo): boolean`，落点 M5 输入准备。各文档中的 `normalizeToolDeferrable`（M1）、`normalizeToolDefinition`（M4）、含 `reservedTools` 参数的变体（M3）一律改为此名；`reservedTools` 不参与归一化（它属于 eager 并集逻辑，与「声明上可否折叠」正交）。
- **强制 eager 集合**（永不折叠）：原生 7 工具 `read/bash/edit/write/grep/find/ls`（`packages/coding-agent/src/core/tools/index.ts:37-58`）+ `tool_search` 自身 + `reservedTools` 配置 + 所有 `deferrable: false` 的工具 + `tools.allow` 白名单工具。
- **默认可折叠**：扩展 / SDK customTools 注册的工具（SourceInfo 可判来源，`packages/coding-agent/src/core/source-info.ts:3-22`）默认视为 `deferrable: true`，作者声明优先。原生 7 工具即使误声明也不折叠（MUST 在代码层兜底）。
- **激活状态判定时机**：工具注册刷新与模型切换时重算；会话中途从激活退回非激活时，已发现工具保持加载（只卸载合成 tool_search 工具），MUST NOT 抽走模型已知的工具。
- **CLI flag 语义**（2026-09-25 裁决）：`--reserve-tools` 为**覆盖**语义（与 `--tools` 一致：显式给定完整列表），非追加。

### R6 · discovered 状态的唯一真相源与恢复

- **真相源 = transcript 本身**（TanStack 语义）。恢复算法：扫描**完整当前分支** `getBranch()`（`packages/coding-agent/src/core/session-manager.ts:1360-1384`），收集 (a) `tool_search` 的 toolCall 与对应 toolResult；(b) 所有 `toolResult.addedToolNames`。MUST NOT 依赖 `buildSessionContext()` 的投影（compaction 会丢弃压缩前条目，`session-manager.ts:443-500`——这是 scout 实测确认的现状缺陷对 deferred 机制的影响）。
- **discoveredNames 是 transcript 事实超集**（2026-09-25 冲突裁决 C1，裁定 M4 模型正确）：允许包含当前 catalog 之外的名称（历史事实不因 registry 收缩而消失，热加载同名工具后可恢复）。配套不变量：**discoveredNames 的任何下游使用（active 计算、catalog、搜索结果、R9 类别段）MUST 经过 `available = registry ∩ allow/deny` 过滤**。运行时 `discover` 入口只接受 catalog 内名称（搜索命中必然来自 catalog 快照）；恢复走独立批量入口 `restore(names)`，接受超集。（M1 §3.1「只接受 catalog 内」表述按此修正；M6 MUST 补「discovered 含 deny/卸载名时无泄漏」测试。）
- **compaction 兜底**：写入 compaction entry 的 `details` 字段记录当时 discovered 工具名清单（对齐 Claude Code `preCompactDiscoveredTools`）。恢复时 branch 扫描结果与最近 compaction details **取并集**。
- **不新增持久化 entry 类型**。若 M4 论证后认为必须，走「发现的冲突」。
- **文档欠账**：`docs/session-format.md:66-105` 的 ToolResult 接口漏列 `addedToolNames` 字段（字段实际落盘，scout 已核实）。M4 MUST 同步补文档。

### R7 · 与 allow/deny 的叠加顺序（冻结；**2026-09-26 D23 修正基数方向**）

```
registry（全部注册工具）
  → allow/deny 过滤（现状语义不变：isAllowedTool，agent-session.ts:4084-4139）
  → 初始/动态 active 集合（现状语义不变：settings.defaultTools + CLI + excludeTools 计算，sdk.ts:300-309；
     extension 的 setActiveTools 动态收缩同属此层）
  → 折叠过滤 = 以【当前 active 集】为基线做减法：移出（deferrable 生效 ∧ 未发现 ∧ 非 eager）的工具，
     并回加 discovered ∩ available；激活时追加合成 tool_search 工具
```

⚠️ **D23（2026-09-26 实现期回归归因）**：折叠过滤的基数是**当前 active 集**，不是 registry 全集。recompute/sync MUST NOT 重建全集——否则会冲掉 settings/CLI 的初始集合语义（#3592）与 extension `setActiveTools` 的动态收缩（#6162）。折叠过滤只做「移出未发现折叠工具」与「回加已发现工具」两个 delta；搜索目录（getSearchableTools）才以 registry 可见全集为基数。

deny 的工具对 tool_search **不可见不可搜**（彻底不存在）。allow/deny 名单变化、preset 切换（`_syncActiveToolPolicy`，`agent-session.ts:1860-1872`）触发 ToolSearchManager 重算。

### R8 · 引导性报错（自纠错）

模型调用「折叠且未发现」的工具时，现状报 `Tool X not found`（`packages/agent/src/agent-loop.ts:650-659`）必须改造为引导性报错：`Tool 'X' is available but not yet loaded. Call tool_search with query "..." to load it.`（M1 定义精确文案与查询建议生成规则）。其他真正的未注册工具名维持现状报错不变。**报错是正常控制流**，不得抛异常中断 loop。

### R9 · 系统提示的类别段

激活时在系统提示追加折叠工具摘要段（每个工具一条：`name — description 首句`，来自 `promptSnippet` 同源的 description），让模型知道可以搜什么。接线点为 system prompt 构建输入（`_rebuildSystemPrompt` / `BuildSystemPromptOptions`，`agent-session.ts:1340-1344, ~1560-1625`）；**preset 模式**下 system 内容走 preset compiler/slot（`prompt-preset/compiler.ts:33-54`），M5 MUST 给出两种模式的接线方案。工具集变化时该段随 active 集重建（现状机制：`setActiveToolsByName` 已触发 `_rebuildSystemPrompt`）。

### R10 · 工具集动态变化的通知（2026-09-25 新增，源自 M4 设计）

折叠激活期间，MCP server 连接/断开、扩展热加载、preset policy 变化导致可搜集合变化时，MUST 在下一轮向模型注入**增量通知**（只列 delta：新增/移除的工具名，经 allow/deny 过滤），对齐 Claude Code 的「每轮对比已告知工具集与实际集合」（01 §3.3）。通道裁定：

- **首选 steering 消息**（agent-core 现成注入通道，模型可见、下一轮生效）；
- 备选 `custom_message` entry（**进 LLM context**，custom 角色）。
- ⚠️ 现状事实修正（M4 §3.4.4 原文有误）：`custom` entry 不进 context（`session-manager.ts:120-127`）；`custom_message` entry **进** context（`session-manager.ts:139-169`）。不得把两者语义写反。
- 不得把通知伪装成 tool result。

## 5. 可机械核验的不变量（评审门用）

1. **R2 行为矩阵逐格有测试映射**：4 provider 场景 × 3 工具状态 = 12 格，M6 的矩阵每格对应至少一条具名测试。
2. **零开销 opt-in**：`toolSearch.mode="off"` 时，构造请求的 tools 列表与现状逐字节一致（同输入快照对比）。
3. **deny 封闭性**：被 deny 的工具名不出现在 tool_search 的任何输入/输出/目录中。
4. **R3 配对**：每次 tool_search toolResult 的 `addedToolNames` ⊆ 本次返回正文列出的工具名 ∩ 折叠集合，且与下一轮 active 集合增量一致。
5. **R6 恢复等价**：同一 session 在「resume 后」与「压缩后」重建的 discovered 集合 = 压缩/断开前的集合（fixture 驱动）。
6. **array-first**：tool_search 的 parameters schema 中任何含 array 的 Union，array 分支必须在首位（照抄 `read.ts:22-25` 注释）。
