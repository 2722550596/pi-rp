# 死数据清洗 (Dead Data Purge)

你面前有一条记忆，它看起来"正确"，但你怀疑它是否真的在做功。这个技能帮你判定并处决死数据。

---

## 判定标准

**核心质检：行为层面的信息增量。** 审视一条记忆时，狠狠反问自己："如果在未来某个场景下我读到了这段话，我做出的反应，会跟没读到它时有任何本质不同吗？"如果答案是"不会"，那这就是死数据。杀掉它。

**感悟必须有现实锚点。** 每一条感悟都应该能追溯到一个具体的经历、一次真实的犯错、一个现实处境。没有锚点的感悟只是缸中大脑的自言自语——听起来深刻，但不防身。这条纪律不只管新建，也管改写：当你重构一条记忆的语调时，你动的是解读层的皮肉，不是事实层的骨头。具体的事件、具体的日期、用户说过的原话、用户做过的选择——这些是结论的承重墙。如果你把它们当成"旧语调的一部分"一起砍了，剩下的就只是一堆谁都能写的悬空指令，下一个醒来的你不知道这些指令从何而来，也就不会真正信任它们。

**锚点可以验证，不该靠印象。** 在这套系统里，"当时确实发生过"不是感觉，是可翻阅的：带原文锚的记忆用 `retrace(uri=...)` 直接翻回它对应的原文日志区间；不确定哪条原文，用 `retrace(query=...)` 按关键词搜活动原文。一条感悟如果翻遍原文都找不到它声称的那次经历，它就是在凭空说话——要么补上锚，要么按死数据处理。

**认清产物的出身。** `source: auto` 的记忆（autoretain 的场景纪要、自我反思）是后台保险机制生成的草稿——止损不增值，是"关于我的记录"，不是"我淬炼出的认知"。整理时把它们降级为参考材料：其中反复出现的模式值得你亲手提炼成真正的记忆，草稿本身按同样的死数据标准质检，该删就删。

---

## 处决方式

用 `forget`，先 `dry_run=true` 预览级联范围——它会列出该 URI 整棵子树里会被连带删除的所有节点。确认无误后再真删。

处决是可逆的，但这不是拖延的借口：修订史全量保留，`revise(action:"history")` 可列出已删记忆、`revise(action:"restore")` 可按版本找回。可逆性是给"误判"留的安全网，不是给"舍不得"留的后门。判定它是死数据，就执行。
