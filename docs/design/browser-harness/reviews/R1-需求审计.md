### 较重（评审门必须先拍板，拍板前不予通过）

**D1（P1）browser 剖面存储缺省装配：11-B 与 15-F 说法相反**
- 证据：11-B §0 E1「下游拿 `packages/browser-engine`……**即可获得完整状态面**」、§8「`packages/browser-engine/src/state/*`——browser 装配 provider：组装 HarnessStores……persist() 调用」、§10 验收 3「建 session→写三轮→**刷新页面→session 恢复**」；而 15-F §3.3 `storage.sessionRepo`「**缺省 InMemorySessionRepo**……OPFS 实现由模块 B 提供」、§4 S3「缺省 inMemory + 注入覆盖」。
- 影响：按 F 字面实现，browser 剖面缺省即内存态，刷新即丢会话——B 的验收 3 默认失败，E1「开箱即获状态面」落空，两文档必有一方需回写。
- 建议：拍板「`profile:"browser"` 缺省装配 B 的 OPFS provider（含 `navigator.storage.persist()`），in-memory 降为显式选项/降级路径」；若反拍（坚持显式注入），必须同步改写 11-B §0 E1 措辞与验收 3 前置条件，并向明月确认「纯前端开箱即持久」是否为隐含期待。

**D2（P2）delegatable subagent preset 的 browser 供给链无认领归属**
- 证据：12-C §4.8「待专项（§13.5）：delegatable preset 的 browser 来源——prompt-preset/loader.ts:1 直连 node:fs 读盘，**归 B/PackF 域**」；但 11-B §8 收编清单**不含** prompt-preset/loader.ts，15-F §9 触点表亦无此项。
- 影响：E4/E6 视角的已声明缺口（browser 剖面优雅空返回「No delegatable subagent profiles are configured」，12-C §4.8），但缺口**无主、无排期、无关闭条件**——「已声明」不等于「有闭环路径」。
- 建议：评审门指派归属（建议归 B，与其 StorageBackend 资源扫描收编同缝）并给排期；或明示「v1 接受 browser 无 delegatable preset」并把该限制写进 F 的下游可见面文档。

**D3（P2）I4 冻结文本与 13-D 的 sqlite-wasm VFS 落盘机制之间缺显式豁免申报**
- 证据：契约 §6 I4「任何设计文档不得引入**绕过** JsonlSessionRepoFileSystem / StorageBackend 接口的**第三条落盘路径**」；13-D §4 步骤 4/§9：browser 工厂经 `@sqlite.org/sqlite-wasm` 的 opfs-sahpool VFS **直写 OPFS**，不经两接口（「工厂闭包持 OPFS root，直接消费虚拟绝对路径字符串」）；13-D §12 冲突表（C1–C4）未申报此张力；11-B §11-1 只备案了 memory.db 的路径归类差异。
- 影响：设计本身合理（sqlite 页级写经字符串同步接口不现实，且 B/D 已就路径命名空间对齐），但按契约 §12「发现本文档错误时 MUST 在『发现的冲突』节申报」的程序要求，这是一处**未申报的冻结条款张力**；不处理则实现期任何一方都可援引 I4 否决 D 的方案。
- 建议：走冲突申报，在契约 I4 增补一句豁免：「经组装期注入的 `SqliteDatabaseFactory` 之引擎 VFS 对 sqlite 库文件的落盘为对等合法面（限 D 域）」。

**D4（P2）pi-tui 短期 stub 存在锚定临时解的风险（E8 精神）**
- 证据：15-F §5.4 两阶段设计——「**短期（本仓私有，bundle 级）**：alias 插件替换为 no-op stub……由 §11.1 ci-entry 断言兜底」；「**正解（反哺上游候选，归 E/A 协同）**：renderer sidecar + pi-tui sideEffects 标注」——正解仅为「候选」，无排期、无触发条件。
- 影响：stub 能跑且有 CI 兜底，但它正是 E8 要防的「锚定临时方案」形态：一旦 v1 发货，正解的优先级必然衰减。与候选推翻留痕齐备的其余部分相比，这是唯一的例外。
- 建议：评审门二选一：(a) sidecar 拆分列入 v1 交付范围；(b) 明文接受 stub 为 v1 终态，写明已知边界（渲染闭包内符号被调用的后果、扩展 type-only 纪律的强制性）与正解触发条件。

**D5（P2）`ToolDefinition.requires` 若不进 v1，扩展自建 shell 工具在 browser 漏网——必须显式拍板**
- 证据：14-E §3 步骤 10（同名覆盖层现成；能力声明层为提案，落 extensions/types.ts + agent-session.ts，归 C）；14-E §13-3「是否进 v1……若 v1 不做，扩展自建 shell 工具在 browser 的漏网属已知边界（v1 可接受则须在 C 文档显式声明）」。
- 影响：bash 本体禁了、扩展的 bash 等价物（如内部 spawn 的 "deploy" 工具）仍可进 browser 模型工具列表——与 E7 同构的口子，E6「能力面完整保留」的另一面。
- 建议：评审门拍板 v1 做或不做；不做则 C 文档必须显式声明该边界（不得静默）。

**D6（P3）契约 §5 开关值符号学与 I3 自相矛盾**
