## 1. 效果清单（验收锚点，来自 16 号文档）

E1. Browser 剖面可供给**自定义 prompt preset**（内容生效，不是只传 ID）；最高优先级。
E2. Browser 剖面可供给 **opening**：内建 opening 播种器可用，opening 预设内容可达，选择/注入不依赖 `process.env`。
E3. Browser 剖面可供给 **state schema**（含 JSON 定义；`.ts` validator 属 jiti 域，Browser 协商禁用——见 §5 边界）。
E4. 扩展 `ctx.ui.notify/select/confirm/input/editor` 在 Browser 不得静默 no-op：harness 必须提供宿主 UI 接缝（纯 TUI 渲染仍不需要——浏览器用自己的前端）。
E5. 显式指定了资源 ID 但资源不存在 ⇒ 组装期**报错/诊断**，不得静默回落 default 栈（消除 fs-shim 静默性）。
E6. node 剖面行为零变化（本文所有改动只在 browser/hosted 装配路径生效，或以缺省参数保持逐字节等价）。

## 2. 已核实事实（file:line 均为 pi-rp 本仓，除非标注 wl=worldlines-rivet）

### 2.1 引擎侧断裂点
- preset：`packages/coding-agent/src/core/prompt-preset/loader.ts:1-3` 顶层 `node:fs`；`:41-69` `loadPromptPresets(cwd, agentDir)` 读 `<agentDir>/prompt-presets` + `<cwd>/.pi/prompt-presets`。Browser 构建未 alias 此文件（`browser-engine/build.mjs` WORKSPACE_ALIAS_MAP 无它），命中 `shims/fs.ts:4-10`（existsSync 恒 false）⇒ 静默空集。
- preset 消费：`core/sdk.ts:540-542` `chooseDefaultPreset(loadPromptPresets(...))`；`options.preset` 只传 ID（`browser-engine/src/assemble.ts:112,332`），空集 ⇒ 回落内置 default 栈，无报错。
- preset 内置栈不受影响：`core/prompt-preset/default-stack.ts`（代码内置）。
- opening：内建扩展 `extensions/index.ts:6-10`（llama/memories/opening）仅 CLI `main.ts:595` 拼入；`assemble.ts:349`（现 :311）只用 `options.extensions.factories` ⇒ Browser 默认无 opening。即使传入 factory：`extensions/opening/index.ts:38-40` 读 `process.env.PI_OPENING`、`extensions/opening/preset.ts:20` node:fs、`:57-59` `openingsDir = PI_OPENINGS_DIR ?? getProjectConfigDir(cwd,"openings")` ⇒ 空集/无触发。（评审修正：env 读取在 opening/index.ts，非 preset.ts:40-42，原文档误标。）
- schema：Browser 把 `state/schema-loader.ts` alias 到 `browser-engine/src/browser-schema-loader.ts:23-31`（恒空集，头注声明协商禁用）；`options.schemas` 只收 ID（assemble.ts:113,333）⇒ ID 找不到仅 warning（`core/sdk.ts:601-612`）。
- UI 接缝：`assemble.ts` 无 uiContext/bindExtensions；ExtensionRunner 缺省 `noOpUIContext`（`core/extensions/runner.ts:361,497-501`：notify no-op、select/input→undefined、confirm→false、`ctx.hasUI=false`）。RPC adapter 是独立 node 路径（`modes/rpc/rpc-mode.ts:295-320` notify 走 `extension_ui_request`、:477-486 bindExtensions），不进 browser 包（`browser-engine/src/index.ts:5-6`）。
- 子代理：`core/subagent/run.ts:158-159` 透传 `preset: preparation.profile.id` 与 `schemas: preparation.schemas`，资源解析走同一 loader 链 ⇒ 上游资源供给修好子代理即修好（但 `run.ts:167-184` 的 stub resourceLoader 需同步核对 presets 面）。

### 2.2 下游（wl）消费契约——浏览器本地化时必须端到端等价
- preset 生产：IP 目录 `prompt-presets/<writer|角色id>.json`，`autoActivate: true` 表达主进程默认（`launch.mjs:142-143`）；creator 预设在 `<repo>/.pi/agent/prompt-presets/`（`launch.mjs:38,432-437` 注释）。角色子进程显式 `--preset <id>`（launch.mjs:262-263）。
- opening 生产：`<ipDir>/openings/<name>.json`；网关选择 → `WL_OPENING` env（launch.mjs:186,233）；内建播种器 + `wl-opening.ts` 适配层读 `WL_OPENING`/`WL_OPENING_PATH` 变换后调 `applyOpeningPreset`（wl `.pi/extensions/wl-opening.ts:550-570`）。
- schema 生产：`<ipDir>/schemas/<id>.json|.ts`（launch.mjs:97-115）；主进程 `--schema world,player,<角色>…`，角色 `--schema world,<id>`；全 `.json`（id-dependency-audit：54 文件 0 `.ts`）。
- prompt 模板：`--prompt-template <ipDir>/prompts` + 用户级目录（launch.mjs:159-161,252-255）。
- 扩展：9+4 个 `.pi/extensions/*.ts` 以绝对路径 `-e` 挂载（launch.mjs:53-69,171,220）；`--no-extensions` 只关自动发现、`-e` 照常（launch.mjs:75-76 注释）。
- RPC UI 消费面现成：`extension_ui_request` 事件 → 前端 `ExtensionUiHost.svelte`（select/confirm/input/editor 弹层 + notify toast）→ WS `ui` 命令 → `extension_ui_response`（wl `ws.mjs:283-287`；`extension-ui.ts:71-125` 扫描去重）。⇒ Browser 侧 UI 接缝按同形状回调即可复用前端。
- wl **当前无任何 createPiHarness 调用点**（全仓 grep 零命中）：本地化尚未发生，本文修复的是引擎供给面，下游迁移另行立项。

- **关键路径根差异（下游审计新增）**：wl `cwd` 是 repo root，而每个 IP 的资源根 `ipDir` 是相对 `cwd` 的路径，由 `--config-dir ipDir` 选择（wl `launch.mjs:140-146,162-169`）；Node CLI 在资源扫描前写全局 `PI_PROJECT_CONFIG_DIR`（pi-rp `main.ts:645-648`），`getProjectConfigDir` 随后读 env 并 `join(cwd,configDirName,...)`（`config.ts:504-513`）。Browser harness 没有 configDir 选项，process.env 也不是并发 session 隔离通道；只扫描 `cwd/.pi/*` 不会找到 IP 资源。资源补救必须新增 **per-harness `configDir?: string`**，相对 `cwd`，默认 `.pi`，严禁写全局 env。该项目配置根同时决定本任务 loader 路径、`SettingsManager.projectSettingsPath` 与 `AgentSession` 的默认 `StateStore` 根；`--settings-file` overlay 和 `--session-dir` 是独立的 per-save 持久化路径，不在本次 Browser 资源补救范围内。
### 2.3 引擎既有可复用先例（解法须收敛到这些缝，不得另造第四套）

- NullPackageManager：`browser-engine/src/null-package-manager.ts` 返回空集四类资源。
- SchemaValidator 有 `loadSchema(schemaId, namespace, schema)` 单点装载（`state/schema-validator.ts`；agent-session.ts:1989,2221 消费）；session 侧 `_loadedSchemaDefs` + `getLoadedSchemaDefs()`（agent-session.ts:636,2200）。
- preset 编译/激活运行时（`_ensureActivePresetRestored`、`chooseDefaultPreset`、subagent prepare）与资源来源解耦——只换 loader 层即可。

## 3. 冻结的资源形状与优先级

统一供给模型（全部资源同构，禁止 per-资源发明第二套）：

1. **OPFS 扫描（主通道，格式与 node 逐字节一致）**：把目标 node loader 的 `existsSync/readdirSync/readFileSync` 收敛为经 `StorageBackend` 的扫描器（11-B 步骤 8 已对 skills 定稿此法，本文扩及 preset/opening/schema(.json)/promptTemplates）。项目配置根逐 harness 解析：`projectRoot = join(cwd, options.configDir ?? ".pi")`；工程局部资源目录为 `join(projectRoot, "prompt-presets")`、`join(projectRoot, "openings")`、`join(projectRoot, "schemas")`、`join(projectRoot, "prompts")`，全局 preset 根独立为 `<agentDir>/prompt-presets`。Browser/hosted loader 只读显式 `options.configDir` 与 `.pi` 缺省，**禁止读取或写入 `PI_PROJECT_CONFIG_DIR`**（多会话隔离）；SettingsManager project settings 与 AgentSession 默认 StateStore 使用同一 root；node 继续沿旧 `getProjectConfigDir`/CLI env 逐字节工作。⇒ 同一 IP 的 node 项目配置目录树拷入对应 OPFS 路径即合法迁移。
2. **内联注入（打包通道，与 skills 同构）**：`CreatePiHarnessOptions` 新增 `configDir?: string`（相对 `cwd` 的项目配置目录路径，缺省 `.pi`）、`presets?: LoadedPromptPresetSource[]`、`openings?: OpeningPresetSource[]`、`inlineSchemas?: SchemaDefSource[]`（`schemas?: string[]` 保留显式 ID 列表，内联 schema 定义另名避免冲突；形状=对应 loader 的 LoadedXxx，带可选 `source`）。同一 options 传入的 configDir 随 session/子代理继承；不得设置进程级 env。合并语义与 skillsOverride 一致：内联并入扫描结果，**同名 ID 内联优先**（与「打包 > 磁盘」一致；冲突出诊断）。
3. **优先级总序**：内联 > OPFS 扫描；扫描内部**逐字节保持 node 现行替换语义**——preset 扫描序 [agentDir, project]，同 ID **后扫替换先扫** ⇒ project > agentDir（`loader.ts:45-67` "Project presets override global ones with the same ID"；schema node 现行同 ID 双条目共存、消费端 find 首中 = agentDir 胜，保序不新增去重，仅内联存在时做内联胜出去重）。
4. **触发参数**：
   - `options.preset`（ID）/ autoActivate 语义不变，但解析源变为上述合并集；**E5：显式 ID 未命中 ⇒ createPiHarness reject**（node CLI 语义不变，sdk 仍 warning）。
   - `options.schemas` 同理：显式 ID 未命中 ⇒ reject（现 sdk warning 保留于 node）。
   - opening 不经 env：harness 选项新增 `opening?: string`（ID），由内建 opening 扩展消费；Browser 装配默认并入该工厂并传 `{ configDir: options.configDir, storage, inline }`；内建读取 `join(cwd, configDir ?? ".pi", "openings")`，不读 process.env。env 触发通道仅 node。
5. **E4 UI 接缝（C3 终版：恒绑定）**：`CreatePiHarnessOptions.ui?: { uiContext?: ExtensionUIContext; mode?: ExtensionMode; onError?: ... }`；createPiHarness 在 session 构造后、返回前**恒执行一次** `session.bindExtensions(...)`（含"无 ui 无 opening"情形：bindings = noOp UIContext + mode rpc）——session_start 唯一发射点在 bindExtensions（`agent-session.ts:4279-4282`），不绑定 = 宿主工厂扩展的生命周期事件全部静默死掉，与 E5 反静默同类。`createHostExtensionUIContext` 的宿主处理器形状：双程 `request` + 单程必填 `fire`；Browser `ctx.ui.notify` MUST 通过 `fire({type:"extension_ui_request", id, method:"notify", message, notifyType})` 发出 RPC 同形事件（`rpc-mode.ts:210-218`），不得另走可选 notify 回调或静默丢弃，以便 worldlines-rivet 既有 `scanExtensionEvents`/toast 消费路径原样复用（wl `extension-ui.ts:82-93`）。缺省无宿主 `uiContext` 时仍是 noOp UIContext、`ctx.hasUI === false`（headless 明确无 UI 目标）；有浏览器前端的下游 MUST 传入 `createHostExtensionUIContext` 生成的适配器。U2 裁决：RPC request/response 类型走 type-only re-export。
6. **明确不做（v1 边界，写入设计文档边界节）**：`.ts` schema/validator 的 jiti 装载（Browser 协商禁用，维持）；包管理器（npm/git）通道；扩展磁盘发现；主题扫描（用户裁定与浏览器无关）；`WL_OPENING_PATH` 等下游 env 语义（下游适配层自身随扩展工厂化处理，非引擎职责）。
7. **子代理**：资源供给修复后，subagent preset/schemas 链自动受益；`run.ts` stub resourceLoader 若需注入父会话资源集，按「继承父会话已装载资源」设计（具体落点设计代理定，契约只冻结效果：browser 剖面子代理可用自定义 preset 与 schema）。

## 4. 诊断与可观测

- 合并集资源的溯源（source）：内联 `inline:<name>`、OPFS 扫描 `opfs:<path>`、hosted `host-fs` 扫描 `host:<path>`；`node-fs` 扫描面**不设置 source**（旧列表中的 `node:<path>` 不适用，确保 node 对象/JSON 序列化零变化），进入既有 diagnostics 通道。
- **promptTemplatePaths 亦入 E5 诊断环**：browser 剖面显式路径未命中或读取失败（包括 path 存在但 read/stat 抛错）⇒ 逐条 warn 诊断；node 保持静默 continue，E6 不受损。
- 显式 ID 未命中的报错信息必须列出：请求的 ID、合并集实际含有的 ID、各源摘要。
- 内联×扫描同名冲突：诊断（warn 级）+ 内联胜出，不静默。

## 5. 测试与验收基线

- 单测：各 loader 的 storage 化（内存 StorageBackend + OPFS mock）；两份同时存在且不同的项目配置根必须互不串读（cwd 相同、configDir 不同），覆盖 preset/opening/schema 与项目 SettingsManager、默认 StateStore 路径；内联合并/冲突/优先级；显式 ID 未命中 reject；opening 工厂默认装配 + `opening` 选项触发 `applyOpeningPreset`（skipIfSeeded 守卫保留）。
- Browser bundle 冒烟：以 `browserHarnessEsbuildOptions` 打包审计入口，验证 OPFS 布局下 preset/opening/schema 端到端可见（消除「绕过 alias 的假阳性」——早前主题冒烟教训）。
- node 回归：`loadPromptPresets/loadSchemaDefs/loadOpeningPreset` 既有测试逐字节不回归（`test/prompt-preset-loader.test.ts`、`schema-loader.test.ts`、`opening-extension.test.ts`）。

## 6. 模块切分（设计代理分工）

- **A · 资源装载缝**：storage 化 preset/opening/schema(.json)/promptTemplates；以 per-harness configDir 定位项目资源根并同步 `SettingsManager.projectSettingsPath`、`AgentSession` 默认 `StateStore` 根；内联注入 + 合并优先级 + 诊断 + 显式 ID reject + 子代理继承（cwd、configDir、agentDir、inline resources）。落点：`prompt-preset/loader.ts`、`extensions/opening/preset.ts`、`state/schema-loader.ts`（Browser alias）、`core/prompt-templates.ts`、`resource-loader.ts`、`settings-manager.ts`、`core/agent-session.ts`、`sdk.ts`、`assemble.ts`、`core/subagent/run.ts`（如需）。
- **B · 扩展 UI 接缝**：`ui` 选项 + bindExtensions 时序 + 内建 opening 工厂缺省装配（携带 per-session `configDir`）+ `ctx.hasUI` 语义 + RPC 形状对照（Browser notify 经 `fire` 发 `extension_ui_request` 同形事件）。**B12 防漂移断言**：不抽共享纯函数，增加同一 handlers 双实现逐成员 diff。落点：`assemble.ts`、`browser-engine/src/index.ts`，必要时只读引用 `core/extensions/runner.ts`。
