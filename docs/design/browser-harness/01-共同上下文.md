## 1. 术语表（全部文档统一用语）

| 术语 | 定义 |
|---|---|
| 运行时剖面（profile） | pi-rp 运行其上的载体类别。枚举见 §3。剖面 = 一组能力 + 对应的默认实现注入 |
| 能力（capability） | harness 运行所需的单项环境能力（如 shell 执行、持久 fs）。唯一来源见 §4 |
| 宿主壳（host shell） | 提供真 fs/shell 的桌面载体（Tauri/Electron 等），对应 hosted 剖面 |
| 归化（native-ize） | 把 Node 依赖改写为跨运行时接口 + 按剖面注入实现的过程；区别于"绕过"或"砍除" |
| 协商禁用（negotiated absence） | 能力缺失时工具/扩展不进入模型可见面，而非运行时报错。E7 的机制 |
| 打包通道 / 磁盘通道 | 扩展加载的两条通道：bundle 静态注册（全剖面）/ 磁盘发现（Node 专属） |
| 工作区（workspace） | agent 文件工具（read/write/edit/ls/grep/find）操作的文件命名空间，与 pi 自身状态存储（§6）分属不同子树 |

## 3. 运行时剖面枚举（冻结；新增剖面须走冲突申报）

| 剖面 | 载体 | 能力预期 |
|---|---|---|
| `node` | Node.js / Bun 进程（现状形态） | 真 fs + 真 shell，全工具面，磁盘扩展发现 |

- E6 落地口径：harness 代码本体不分叉；剖面差异只存在于（a）入口注入的实现（b）能力协商的开关值。**禁止**在 harness 内部逻辑散落 `if (profile === "browser")` 类分叉；剖面判断只允许出现在 §4 定义的能力查询与注入边界。

## 4. 能力协商（冻结原则；接口具体形状由模块 A 设计定稿后回填 §4.1）

- 原则 1：**能力有且只有一个来源**——ExecutionEnv（或其伴生对象）。禁止工具/扩展/存储各自探测 `typeof process`、UA 嗅探等第二来源。
- 原则 2：能力缺失的表现形式是**协商禁用**（模型工具列表不含该工具）或**注入替代实现**，不是运行时抛错。
- 原则 3：能力→工具开关的映射必须是一张**总表**（见 §5），不允许散落判断。

### 4.1 capabilities 接口形状（模块 A 定稿回填 2026-09-30；全文见 10-A）

**形状裁定**：capabilities 是 ExecutionEnv 的**伴生对象**，不扩展上游 `ExecutionEnv` 接口（types.ts:315 零改动）。扩展接口/伴生对象/静态剖面表三候选经证据评估，伴生对象胜出（推翻记录见 10-A §3 步骤 2）。

```ts
/** 唯一能力来源。由 negotiate() 在组装入口派生一次，此后只读；禁止任何模块自行拼写。 */
interface Capabilities {
  readonly shell: boolean;               // bash 工具开关（§5）、扩展 ctx.exec、npm-git 安装的开关依据
  readonly diskExtensions: boolean;      // 扩展磁盘发现通道（jiti）开关；打包通道不受影响
  readonly concurrentFsAccess: boolean;  // 是否存在会话外并发写者；false ⇒ 存储类文件锁整体旁路（no-op，非换实现）
                                         //   browser 的 false 隐含「单 tab 单写者」；多 tab 升级路径=Web Locks（另拍板）
}

/** 组装入口唯一产物：环境 + 能力同源同生命周期。 */
interface HarnessEnv { readonly env: ExecutionEnv; readonly capabilities: Capabilities }
```

**三剖面派生值**（negotiate 唯一构造点，落点 `packages/agent/src/harness/capabilities.ts`，纯 TS 零依赖）：

| 剖面 | shell | diskExtensions | concurrentFsAccess |
|---|---|---|---|
| node | true | true | true |
| browser | false | false | false |
| hosted | 宿主是否注入 Shell | false | 宿主申报（缺省 true 保守） |

**与 ExecutionEnv 的关系**：env 管"怎么做事"，capabilities 管"能做什么"；后者是协商层唯一事实，`BrowserExecutionEnv.exec` 恒返回 `ExecutionError("shell_unavailable")`（上游既有码，types.ts:158-165）仅为防御性深度，正常会话不应触达。能力查询允许出现的全部位置：**组装点、扩展注册上下文（`ExtensionContext` 增只读字段）、扩展注册边界（`registerTool` 的 `requires` 能力检查，不满足→拒绝注册+诊断条目；12-C §4.9，2026-09-30 评审门 R2-B2 申报扩充）**；**不进** `ExecutionToolContext` 与 `AgentSession`/`isAllowedTool`（I2 守恒）。内置 7 工具中唯一以 capability 位为开关依据的是 bash；grep/find 依据 Operations 注入存在性，其余依据 env 本身（§5 表）。

- 不变量 I2（双向相等）：**模块 A 定稿的 capabilities 字段集 === 全部设计文档实际消费的能力字段集**。多出的字段是死代码，少用的字段是私开来源，均违约。I2 消费点映射（2026-09-30 五方回执确认）：`shell`→E(bash)/C(ctx.exec,npm-git)；`diskExtensions`→C；`concurrentFsAccess`→B(锁策略)；D/F 零消费（差异全在组装注入）。

## 5. 能力→工具开关总表（冻结框架；具体开关值可被模块 E 实测后修订，修订须回写本表）

| 工具 | node | browser | hosted | 依据 |
|---|---|---|---|---|
| read | ✅ | ✅（OPFS Operations） | ✅（宿主注入） | E3/E6；Operations 注入现成（2.2） |
| write | ✅ | ✅（同上） | ✅ | 同上 |
| edit | ✅ | ✅（同上） | ✅ | 同上 |
| ls | ✅（注册；**默认不激活**，bash 覆盖，可显式启用） | ✅（OPFS Operations；**默认激活**，bash 替代） | ✅（宿主注入；同 node 默认不激活） | 明月 2026-09-30 插话拍板：bash 互补开关（原话见 14-E §0） |
| bash | ✅ | ❌ 协商禁用 | ✅ | E7 明月原话消息 5 |
| grep | ✅（spawn rg；**默认不激活**，bash 覆盖，可显式启用） | ✅（OPFS Operations，纯 JS 实现；**默认激活**，bash 替代；实测定值见 14-E §4） | ✅（宿主注入 Operations；≠宿主有 shell 即自动可用；默认不激活同 node） | 前提核查 P5；模块 E 实测回填（2026-09-30）：JS 实现典型亚 2s/最坏 10s（2003 文件/16MB 工作区），LLM 往返时延主导下可接受；GrepOperations 需开缝增 search 全绕行 |
| find | ✅（spawn fd；**默认不激活**，同上） | ✅（OPFS Operations，同上；FindOperations.glob 注入缝现成；**默认激活**） | ✅（同上） | 同上；纯遍历实测 S≈0.16s/M≈0.3-0.5s，可忽略 |

- 开关值语义三分（本表统一口径）：✅ = 注册且默认进入模型可见面；**「默认不激活」= 已注册、可经显式机制启用（settings `defaultTools`、SDK `tools`、preset tools 声明、扩展 `setActiveTools`），默认不进模型可见面**；❌ = 不注册（协商禁用，模型与扩展同名覆盖均不可见）。
- 原则注记（明月 2026-09-30 拍板）：**grep/find/ls 的默认激活状态 = bash 可用性的反函数（bash 互补开关）**——bash ✅ 的剖面默认不激活（模型走 bash 万能路线），bash ❌ 的剖面默认激活（bash 替代物顶上，浏览器化学习子代理机制）；任何剖面均可显式覆盖（显式声明优先于剖面默认）。

- 不变量 I3（双向相等）：**本表工具名集合 === `allToolNames`（`core/tools/index.ts:85`）**，7 项一一对应；每个工具在每个剖面必须有明确开关值（✅/❌），不允许空格。⚠️ 项在模块 E 定稿后必须变为 ✅/❌。
- 禁用语义冻结：❌ = 该工具**不注册进模型工具列表**（模型不可见），而非注册后报错。

## 6. 存储布局（冻结原则；OPFS 子树布局已由模块 B 回填，细则权威 = docs/design/browser-harness/11-B）

- 原则：**pi 自身状态**（session/settings/auth/models/memory.db）与 **agent 工作区**（文件工具操作对象）分属两个命名空间子树，互不越界。
- `getAgentDir()` 浏览器剖面归化为剖面注入的路径解析（node 剖面行为不变）；proper-lockfile 在 browser 剖面以单线程/单 tab 假设去除，hosted 剖面按宿主能力决定。
- 不变量 I4：任何设计文档不得引入绕过 JsonlSessionRepoFileSystem / StorageBackend 接口的第三条落盘路径。**豁免 [2026-09-30 评审门 R1-D3]**：browser sqlite 工厂（13-D）经 opfs-sahpool VFS 对 memory.db 的直写不在此限——sqlite 是单一二进制资产（非 harness 状态流），其访问经 SqliteDatabaseFactory 注入缝管控，与 I4 管控对象（session/状态流）不同层；13-D 已在 §12 申报备案。

### 6.1 浏览器剖面 OPFS 布局（模块 B 回填定稿）

全局命名空间：`/` = `navigator.storage.getDirectory()` 根；全部路径为虚拟绝对路径字符串，只进入 StorageBackend（同步面）/ FileSystem（异步面）注入缝；node 剖面同命名空间即真实绝对路径（`getAgentDir()` 现值），零行为变化。

- memory.db 物理落点默认在**工作区**子树（`resolveMemoryDbPath` 的 `<cwd>/.pi/memory.db` 默认语义平移，packages/memory/src/config.ts:59-67），settings/preset dbPath 可覆盖至任意虚拟路径（含 `/state/**`）；与上方原则叙述中 memory.db 的归类差异按 11-B §11-1 备案。
- `/state/agent/bin/`（fd/rg 托管目录）browser 剖面永不创建（E7 交集）。
- 状态子树全部文件格式与 node 剖面逐字节一致 ⇒ OPFS ↔ 磁盘目录级拷贝即合法迁移（E1 状态面兑现）。
- 降级与未知项（OPFS mtime 可靠性、persist/eviction、多 tab）见 11-B §4/§12；memory.db 的 sqlite 驱动细节归 13-D（D 已引用本节为布局权威）。

## 7. 扩展系统（冻结原则；通道细节由模块 C 定稿）

- 双通道冻结：**磁盘通道**（jiti 发现，node 剖面专属）与**打包通道**（bundle 静态 import + 工厂注册/虚拟模块表，全剖面可用）。两通道产物必须是同一 `Extension` 形状，下游扩展作者 API 不分叉。
  - **[2026-09-30 设计期注记]** 12-C 选型：打包通道 = ESM 默认导出工厂 + `loadExtensionFromFactory` 注册约定（`extensionFactories` 既有机制升格）；VIRTUAL_MODULES **降维为"扩展可 import 公共面"兼容性 key 清单保留**（不作为浏览器加载机制——jiti 无 browser exports 实测）；全局注册表方案否决（隐式时序/树摇敌对）。loader 拆分为纯 TS 装配核（api.ts）+ node 留守面，两通道同一 Extension 形状为 I5 的结构性保证。
- 不变量 I5：浏览器剖面上**必须能加载** AIRP 类扩展（工具注册型），且与 node 剖面加载同一份扩展源码的行为一致（注册的工具/命令/渲染器等价）。
- `ctx.exec`、扩展 npm-git 包安装（package-manager）属 Node 能力：browser 剖面协商禁用，hosted 剖面经宿主注入可用。具体 API 行为由模块 C 设计。
