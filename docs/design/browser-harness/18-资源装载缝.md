## 1. 一句话定位

把 preset（`prompt-preset/loader.ts`）、opening（`extensions/opening/preset.ts`）、state schema 的 `.json` 面（`state/schema-loader.ts` + Browser alias 面 `browser-schema-loader.ts`）、prompt 模板（`core/prompt-templates.ts`）四个 node:fs 直连 loader 收敛为**经 `StorageBackend` 的扫描器**（skills 先例，缺省参数 node 逐字节等价），并为 Browser/hosted 提供 per-harness `configDir` 项目根（同时选择 project resources、SettingsManager settings 与默认 StateStore root，不写全局 env）；叠加**与 skillsOverride 同构的内联打包通道**（`presets` / `openings` / `inlineSchemas`），统一解析顺序「内联 > OPFS 扫描（扫描内保持 node 现行替换语义）」，显式 ID 未命中在 `createPiHarness` 组装期 reject（E5），子代理会话经资源供给缝继承父会话资源集（契约 §3.7）。

### 2.5 Browser alias 面（state/schema-loader.ts 的重定义）

维持 `build.mjs` WORKSPACE_ALIAS_MAP 的 `"state/schema-loader.ts" → "src/browser-schema-loader.ts"` 改写不动（jiti/static 顶层 import 是 A2 禁入链，不能靠 storage 化消除——`.ts` schema 属协商禁用域，契约 §3.6）。**重定义内容**：`browser-schema-loader.ts` 从「恒空集 stub」升级为「storage + inline 参数化的 JSON-only 实现」，与 node 真身共享：

- **共享纯核**（新文件 `packages/coding-agent/src/state/schema-json.ts`，无 Node I/O/jiti 依赖；`node:path` 经 browser shim 可接受，可进 browser 图）：`parseJsonSchemaDef(filePath: string, rawText: string): LoadedSchemaDef`（把现 schema-loader.ts:108-130 的 JSON.parse + 形状校验 + 错误文案原样搬移）与 §2.1/2.3 的共享类型。node 真身与 alias 面都 import 它，解析逻辑零漂移。
- **类型权威**：alias 面经 type-only import 复用 node 侧 `LoadedSchemaDef/LoadedSchemaDefs/LoadSchemaDefsOptions/SchemaDefSource`（type-only 在 bundle 期擦除，先例：browser-schema-loader.ts:5 对 schema-validator 的 CustomValidator type import）。现状两 impl 返回形状域不同名（node `errors` vs stub `diagnostics`，browser-schema-loader.ts:13-20 对 schema-loader.ts:22-26）——本设计统一以 node 形状为权威，消掉这份漂移。
- **扫描循环各自持有**（不共享）：node 循环按 readdir 顺序逐文件分派 .ts/.json（保持既有列表顺序，E6）；alias 面只有 .json 分支（.ts 协商禁用，遇到 `.ts` 记一条 mergeDiagnostics 式提示后跳过，不报错——「协商禁用而非运行时报错」，与该文件现头注口径一致）。

### 2.6 per-harness 项目资源根（下游审计补页，契约 17 §2.2 / §3.1）

`cwd` 是 repo/workspace 根，不是 IP 目录。worldlines `launch.mjs:140-146,162-169` 对每个 IP 传相对 cwd 的 `--config-dir ipDir`；Node CLI 当前通过进程级 `PI_PROJECT_CONFIG_DIR` 传递（`main.ts:645-648`），但 browser harness 可能在同一进程并发装配多个 session，**不得使用或写入该全局 env**。

- `CreatePiHarnessOptions.configDir?: string` 是本 harness 的项目配置根相对 `cwd` 的路径，缺省 `.pi`；解析 `projectRoot = join(cwd, configDir ?? ".pi")`。它同时选择 project `settings.json` 与 AgentSession 的默认 StateStore 根（`join(projectRoot,"state")`）；显式 `settings.state.storeDir` 保留优先级。`--settings-file` overlay 与 `--session-dir`/SessionManager 路径不在本次范围。
- harness 将已解析的 `configDir` 显式传给 preset/opening/schema/promptTemplates loaders、`DefaultResourceLoader`、`SettingsManager`、`CreateAgentSessionOptions`/`AgentSessionConfig` 与 `createOpeningExtension` deps。四 loader 的 configDir 选择 project 资源目录；agentDir 级 preset/prompt/schema 扫描根保持独立。
- Browser/hosted 显式 configDir 时，资源 loader、`SettingsManager.projectSettingsPath` 和默认 StateStore root 均使用该 harness 的 projectRoot；不得调用会读取 `PI_PROJECT_CONFIG_DIR` 的 `getProjectConfigDir`。无 configDir 的 Node 调用保持旧 `getProjectConfigDir`/CLI env 路径，E6 不变。`PI_OPENINGS_DIR` 仅在未显式 configDir 的旧 Node opening 路径有效。
- `_configDir?: string` 随 AgentSession 保存；`getResourceSupply()` 返回该值，`runSubagent` 原样继承。Browser 父会话恒显式传入（默认 ".pi"）；Node 父会话可为 undefined 并继续使用旧 env 语义。子代理不改写 cwd 或进程 env。
- 并发隔离不变量：同 cwd、不同 configDir 的两个 harness 必须各自读取 project resources/settings/default state；全局 agentDir 根仍按既有规则共享。显式 `promptTemplatePaths` 的路径解析仍 cwd-relative，不额外拼 configDir。

## 3. 行为契约逐步

### 步骤 1 · loader storage 参数化（逐字节等价规则）

四个 loader 把 `existsSync/readdirSync/readFileSync/statSync` 直调逐一替换为 `storage.*`；项目级扫描根按 §2.6 显式取 `join(cwd, configDir, resourceName)`，**扫描顺序、agentDir/project 顺序、过滤与排序规则保持不变**：

- preset：扫描 dirs 为 `[join(agentDir,"prompt-presets"), join(cwd,configDir,"prompt-presets")]`（Browser/harness；node 未传 configDir 时第二项仍为 `getProjectConfigDir(cwd,"prompt-presets")`）；同 ID 后扫替换先扫不动；递归、`.json` 过滤、`sort()` 不动。
- opening：`listOpeningPresets/loadOpeningPreset` 的 project root = `join(cwd,configDir,"openings")`（显式 configDir）；旧 Node 路径未传 configDir 时保留 `PI_OPENINGS_DIR ?? getProjectConfigDir(...)`。readdir 排序与单文件 try/catch 不变。
- schema：dirs 为 `[join(agentDir,"schemas"), join(cwd,configDir,"schemas")]`（显式 configDir）；node 未传时 project 项沿用 getProjectConfigDir；readdir 扁平、`.ts`/`.json` 分派不动。`loadCustomValidators`（:133-155）**一行不动**。
- promptTemplates：default project dir = `join(cwd,configDir,"prompts")`（显式 configDir；Node 缺省旧 getProjectConfigDir）；`loadTemplatesFromDir` readdir/symlink-stat/`.md` 过滤不动；显式 `promptPaths` 仍按既有 cwd-relative 路径解析，不额外拼 configDir。
- 顶层 import：三个入图 loader 删除 `node:fs`（及改 bare `path` import，`skills.ts:4` 先例）；schema-loader 真身经 alias 不入图且 jiti 域保留 node:fs（§2.5/§7.7）。
- node 缺省等价性：所有 loader 的 configDir 缺省不显式传入 ⇒ getProjectConfigDir / PI_PROJECT_CONFIG_DIR 旧行为不变；Browser assemble 将默认值 ".pi" 显式传入，且绝不读写进程 env。

**漏了会怎样**：不参数化 storage ⇒ browser 剖面四 loader 命中 `shims/fs.ts`（existsSync 恒 false :10-12、readdirSync/readFileSync 结构化抛错）⇒ 静默空集或抛错，E1/E2/E3 全灭；Browser/hosted 若漏传 per-harness configDir，则仅扫 `cwd/.pi` 而漏掉 wl `--config-dir ipDir` 资源，或若回落全局 env 则同 cwd 并发 harness 交叉污染；若改成「browser 另写一套 loader」⇒ 违反契约 §3「禁止 per-资源发明第二套」，且 node/browser 双实现必然漂移。

### 步骤 2 · 内联源接收与复验证（单约定）

- **preset 内联**：每一项经现成 `normalizePreset(raw, filePath, diagnostics)`（loader.ts:152）重入——schemaVersion 校验、items 归一、变量/模型字段类型收口全部复用 node 解析链；产物 diagnostics 并入该项 `LoadedPromptPreset.diagnostics`。坏内联 ⇒ error 级诊断 + fallbackPreset（与磁盘坏文件同待遇），**不静默、不抛**。
- **schema 内联**：复用 `parseJsonSchemaDef` 的形状规则校验对象体（schema 必须为对象、namespace 必须为 string；错误走 `errors` 列表，文案同 node）。
- **opening 内联**：OpeningPreset 本就宽松（messages/state 任意子集，`applyOpeningPreset` 容错），仅要求对象 + `id`；不发明新校验。

**漏了会怎样**：可信直通（跳过 normalize）⇒ 下游打包了一个 `schemaVersion: 2` 或 items 拼错的 preset，会在 compileMessages 期才炸（prepare.ts:249-253 的 compilation errors），且与磁盘同名资源行为不一致——两套验收标准。

### 步骤 3 · 合并算法与优先级（契约 §3.3 C1 裁决版）

总序：**内联 > OPFS 扫描；扫描内部逐字节保持 node 现行替换语义**。
三类内联数组内部同 ID（schema 用 schemaId）统一按输入顺序处理：**后项胜出 + warn**；对扫描源的遮蔽也单独 warn。

- **preset**（`loadPromptPresets` 内）：先按现行循环扫描（[agentDir, project]，后扫替换先扫，project > agentDir——loader.ts:56-64 现行为），随后追加内联：同 ID **内联替换扫描项**，并在胜出项 diagnostics 追加 warn：`Inline preset "<id>" (source) overrides scanned <filePath>`；**内联数组内部同 ID = 后项胜出 + warn**（与扫描替换语义同构；三资源同规则，评审条件 2）；`annotateDuplicatePresetIds` 照旧收尾。inline 空 ⇒ 与现行逐字节一致（无新增诊断、无 source 设置）。
- **schema**：扫描循环保序不改（node 现行同 ID 双条目共存、消费端 `find` 首中 = agentDir 胜，契约 §3.3 保序不新增扫描去重）；有内联时，先按 inline 数组顺序归并，重复 schemaId 后项替换前项并 warn，再移除同 ID 扫描副本、记录 warn，最终内联胜出条目追加于列表尾。
- **opening**：`listOpeningPresets` 返回合并列表（扫描 id 排序 + 内联首次出现顺序）；inline 数组重复 id 时后项胜出并 `console.warn`，inline/扫描同 id 时 inline 胜出并 warn（opening 无 diagnostics 通道，见 §7）；`loadOpeningPreset` 返回同一最终胜出项。
- **source 标签**（契约 §4 + U 系列裁决）：内联 = `source` 显式值，缺省 `inline:<preset.id|opening.id|schemaId>`；扫描项在 `storage.kind === "opfs"` 时 = `opfs:<filePath>`、`kind === "host-fs"` 时 = `host:<filePath>`（Q2 裁决）；`node-fs` **不设置 source**（契约 §4 旧列表中的 `node:<path>` 不适用，按同段裁决及本文统一口径处理；对象形状与现 JSON 序列化零差异，E6）。

**漏了会怎样**：若按契约旧字面把扫描序改成 agentDir 胜出 ⇒ node `loadPromptPresets` 行为改变，违反 E6（已裁决，见 §12 冲突 1）；若 schema 也做无条件去重 ⇒ node 现行「双条目共存 + 首中」语义被改，`/schema` 列表与既有测试漂移；若内联与扫描同名不告警 ⇒ fs-shim 式静默性在打包通道复发（契约 §4 明文禁止）。

### 步骤 4 · 显式 ID 未命中 ⇒ createPiHarness reject（E5）

## 7. 错误边界

1. **坏内联 preset**：normalize error 诊断 + fallbackPreset（空 items 栈）——与磁盘坏文件同待遇；显式激活该 ID 不 reject（集合中「存在」），行为与 node `--preset` 指向坏文件一致（setActivePreset 按 ID 命中，不查可用性——agent-session.ts:2272 邻域；E5 只覆盖「不存在」）。
2. **扫描 IO 语义**：storage 抛错时保持各 loader 现有 catch 语义——preset 单文件 parse 失败 = error 诊断 + fallback（loader.ts:103-119）；schema `.json` 失败 = errors 列表（:65-70）；opening = 返回 undefined/[]（:61-84）；prompts 目录级 catch 返回已收集部分（prompt-templates.ts:171-175）。OPFS 镜像已 hydrate，读失败面收敛为「目录不存在」（返回空），与 node existsSync=false 同形。
3. **`.ts` schema/validator**：alias 面 `.ts` 记跳过提示（warn 级 mergeDiagnostics），不抛——「协商禁用而非运行时报错」；`loadCustomValidators` browser 恒 []（现 alias 行为保留）。
4. **reject 与 warning 的分界**：browser/hosted 组装期 reject（步骤 4）；同集内 ID 存在但内容坏 = 不 reject（边界 1）；`opening` ID 未命中 = reject（Q3 裁决采纳，与 E5 同机制，错误含可用 opening 清单）。
5. **双扫描成本**：assemble 预扫（reject 用）+ createAgentSession 内部装载各一次；OPFS 镜像内存态、目录条目量级，无 IO 放大。若未来资源量级失控，可把 assemble 预扫结果以参数直通 session（接口已留：inlinePresets/inlineSchemas 即此形状），v1 不做。
6. **process.env 类触点在 browser 的隔离**：`PI_OPENING` 仅 node default export 读取；`PI_OPENINGS_DIR` 仅 configDir 未传入的旧 Node 路径读取。Browser harness 总把 `options.configDir ?? ".pi"` 显式下传，项目资源 loader 不读写 `PI_PROJECT_CONFIG_DIR` 或 `PI_OPENINGS_DIR`；同进程多 harness 因此各自读取自己的 projectRoot。Node 未传 configDir 的旧 env 覆盖保留。
7. **alias 类型漂移根治**：§2.5 统一 node 形状为类型权威后，`browser-schema-loader.ts` 自带 `LoadedSchemaDefs`（diagnostics 域）声明删除，编译期即锁定两侧同构。
