## 4. 行为契约

### 4.1 设置解析（NEW，`packages/memory/src/clock.ts`）

`config.ts` 的 `MemorySettings`（`:24`）新增字段：

```ts
clock?: { mode?: "world" | "real"; timezone?: string };
```

```ts
// clock.ts（NEW）
export type MemoryClockMode = "world" | "real";
export interface ResolvedMemoryClock {
	readonly mode: MemoryClockMode;
	/** real 模式的 IANA 时区（已校验；缺省为进程本地时区名）。world 模式为 undefined。 */
	readonly timezone?: string;
}
export const WORLD_CLOCK: ResolvedMemoryClock = { mode: "world" };
export function resolveMemoryClock(raw: { mode?: unknown; timezone?: unknown } | undefined): ResolvedMemoryClock;
```

规则（2026-10-16 收口，C3、M-1：无 warning 返回通道；与 `packages/memory/src/schema.ts:235-238` 的迁移提示同用 `process.stderr.write`、`[memory]` 前缀和末尾换行，不进 audit_log，不 throw）：
- `raw` 缺省或 `mode` 缺省 → `WORLD_CLOCK`。
- `mode` 不是 `"world"`/`"real"` 的值 → `WORLD_CLOCK`，`process.stderr.write("[memory] invalid clock mode; using world\n")` 记一条。
- `mode === "real"`：`timezone` 缺省 → 进程本地时区（`Intl.DateTimeFormat().resolvedOptions().timeZone`）；`timezone` 非字符串，或 try/catch 构造 `Intl.DateTimeFormat("en-US", { timeZone })` 抛错 → 回退进程本地时区并记一条 warn（01 §2.1 :43；§10 未决项 3 的 warning 通道之争随之关闭）。
- `mode === "world"` 时忽略 `timezone`，不 warn。
- 永不 throw。

已在本机核对（bun 探针）：`Asia/Shanghai` 有效；`Not/AZone`、空串在构造 `Intl.DateTimeFormat` 时抛错（try/catch 可捕获）；`Intl` 能输出 `2026-10-16T05:31:07+08:00` 形式（见 4.2 的 `formatStamp`）。

### 4.2 real 模式的时间函数（NEW，同在 `clock.ts`）

```ts
/** 带偏移的 ISO 串，偏移按 clock.timezone 在该瞬间的实际值（DST 逐次计算）。 */
export function formatStamp(date: Date, clock: ResolvedMemoryClock): string;
// world: date.toISOString()；real: "YYYY-MM-DDTHH:MM:SS±HH:MM"（例 2026-10-16T05:31:07+08:00）

/** 按时区的日序数：world = toEpochDays(ts)（现状）；real = 该瞬间在 timezone 的本地日。 */
export function dayNumber(ts: string, clock: ResolvedMemoryClock): number | null;
```

real 模式实现要点（2026-10-16 收口，C3：`hourCycle: "h23"`，删 `hour === "24"` 归一）：`Intl.DateTimeFormat("en-CA", { timeZone, year, month, day, hour, minute, second, hourCycle: "h23" })` 取 `formatToParts`；偏移取 `timeZoneName: "longOffset"`（`GMT+08:00` → `+08:00`；`GMT` → `+00:00`）。保留 `formatToParts`：`format()` 不输出偏移（已实测四个时区：`Asia/Shanghai`、`America/New_York`、`Pacific/Kiritimati`、`Australia/Lord_Howe`，含半小时/45 分钟偏移），而契约要求带偏移 ISO。任意 IANA 时区名是 `Intl.DateTimeFormat` 的固有行为，不需要额外代码。`dayNumber` 用同一套 parts 得到本地 Y-M-D，再套 `toEpochDays` 的 `Date.UTC(...)/86400000` 公式。

### 4.3 store 上的时钟（NEW 方法，`store.ts`）

理由：`store.put` 的时间回退在 store 内（`:425`），autoretain、tidy、seed、import 都经它写入且不传 `world_ts`；这些路径必须也切换。因此时钟挂在 store 上。

```ts
// store.ts（NEW）
private clock: ResolvedMemoryClock = WORLD_CLOCK;
setClock(clock: ResolvedMemoryClock): void;     // createMemoryModule 或 web 每次打开 store 后调用
getClock(): ResolvedMemoryClock;
/** 写入打点回退。world: getWorldTime()（可能 null，即现状）；real: formatStamp(new Date())（永不 null）。 */
nowStamp(): string | null;
/** 参照"现在"（相对标注、快照首行、recency）。world: getWorldTime() ?? new Date().toISOString()（现状回退）；real: formatStamp(new Date())。 */
referenceNow(): string;
```

改动落点：
- `store.ts:425`：`input.world_ts ?? this.getWorldTime()` → `input.world_ts ?? this.nowStamp()`。
- `store.ts:1697`：`nowDays: toEpochDays(this.getWorldTime() ?? new Date().toISOString()) ?? 0` → `nowDays: dayNumber(this.referenceNow(), this.clock) ?? 0`。
- `store.ts:1654-1677`（getWorldTime/setWorldTime）不改。
- 默认 `WORLD_CLOCK`，所以未调用 `setClock` 的外部消费者行为不变。
- 一个 DB 文件共享一个 store 单例（`agent-session.ts:5489` `getMemoryStoreSingleton`）；同库两个会话配置不同时钟属误用，文档写明"最后一次 `setClock` 生效"（见 10.3）。

> **静态记忆宏**（`memory.awaken`、`memory.recent`、`memory.index`）

> 三个宏对应三个记忆 slot，内容相同，但是静态的：一个静态纪元内只计算一次，之后每次请求都用同一份结果。纪元边界见本文档"静态纪元"一节（会话就绪、切换预设、工具集变化、模型变化、压缩完成后）。
>
> 展开结果第一行是快照时间，后接“此后新写入的记忆不在这份快照里，需要时用 recall 或 retrieve 查”；正文使用绝对日期。slot 形式（`"kind": "slot"`）每轮重新渲染，写法不变。
>
> | 宏 | 参数 | 说明 |
> |---|---|---|
> | `{{memory.awaken}}` | 无 | 醒来记忆（awaken 清单）全文 |
> | `{{memory.recent}}` | `rawCount=N,snippetCount=M`，缺省 1 与 4 | 最新 N 条给全文，其后 M 条给 snippet |
> | `{{memory.index}}` | 无 | 各 domain 根节点的 snippet |
>
> 参数写法是键值对，逗号分隔，键名只能是 `rawCount`、`snippetCount`；未知键忽略，非法值用默认。
>
> 摆放：静态宏可放在 history 之前。它的内容在纪元内不变，不影响缓存前缀的逐轮稳定性。需要每轮变化的内容仍放在 history 之后，role 写 `"user"`。
>
> 记忆写入不会立即刷新宏；下一次静态纪元（包括压缩完成）首次使用时重新取值。需要当前库内容时用 recall 或 retrieve；slot 形式每轮反映当前内容。
