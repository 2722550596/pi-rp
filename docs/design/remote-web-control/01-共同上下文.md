# Remote Web Control（/remote）：共同上下文

> 本文是本设计阶段所有模块设计文档的共享契约，所有模块 MUST 遵守；发现错误或需变更 MUST 申报冲突并由主设计回写，不得各自改造。
> 权威顺序：`00-需求原话.md` 用户原文及其效果清单 > 本文已核实的现状与契约 > 模块设计文档 > 实现代码。

## 1. 定位与兄弟项目的关系

本设计实现"个人远程控制"：**Node TUI 进程是执行者（host），浏览器是参与者（participant），无平台服务，直连**。

兄弟设计 `docs/design/browser-session-collaboration/` 是"平台多人协作"方向：浏览器本地执行 Pi（browser-engine 为执行者），平台 broker 协调多参与者。两者互补、不重叠：

- 参与者侧协议完全同源：都复用 `PiClient` / `pi-protocol` / `PiServerService`（该设计 §3.1 要求收敛参与者协议）。
- 本设计新增的 WebSocket transport 恰构成"标准 WebSocket helper 是否属 Pi 通用 API"（该设计 §4 待论证项）的第二个消费者证据；实现须保持通用、不得耦合 `/remote` 业务。
- 该设计 §3.4"不做 host authentication/凭据策略"限定的是平台协作场景的范围，不禁止本功能自带 token 认证（直连模式无平台层，token 是唯一安全边界）。

## 2. 架构总览

```
┌ TUI 进程（InteractiveMode）────────────────────────────┐
│  AgentSession ◄── AgentSessionRuntime（/new /resume）  │
│      │ subscribe                    │ rebind 回调      │
│      ▼                              ▼                  │
│  TuiSessionRuntime（wrap，dispose=detach）              │
│  RemoteHostController                                    │
│    ├─ token（32B random，仅内存）                       │
│    ├─ PiServer + TuiSessionService（单会话视图）        │
│    └─ WebSocketListener（HTTP 静态 + /ws/<token>）      │
└─────────┬──────────────────────────────────────────────┘
          │ GET /（web 静态文件）  GET /ws/<token>（WS upgrade）
          ▼
   浏览器（vanilla TS web client）
    ├─ PiClient + WsByteTransport（fragment 取 token）
    └─ transcript 渲染 + composer（prompt/steer/abort）
```

## 3. 冻结契约

### C1 WebSocket transport（模块 D1，归属 `packages/server`）

- 新目录 `packages/server/src/transports/ws/`，结构对照 `transports/unix/`（`index.ts` / `listener.ts` / `preset.ts` / `types.ts`）。
- 导出 `createWebSocketListener(options)` 实现 `PiServerListener`（`packages/server/src/listener.ts:4-10`），以及便捷 preset `createWebSocketServer(service, options)`（对照 `createUnixServer`）。
- Listener 职责 = HTTP 静态文件服务 + WS upgrade 认证，认证完成后把 WebSocket 适配为 `ByteConnection`（`packages/server/src/connection.ts:6-10`）交给 `accept`。二进制帧 ↔ chunk，text 帧一律拒绝（协议是 CBOR 二进制）。
- 新增 runtime 依赖 `ws`（根 `node_modules` 已有 8.21.0 传递依赖，声明入 `packages/server/package.json`，版本 `^8.21.0`）。不引入其他依赖。
- 静态服务约定：`GET /` 返回 `index.html`；`GET /<file>` 返回 staticDir 内文件（MIME 白名单：html/js/css/svg/png/ico/wasm/map；必须防路径穿越）；其余 404。不提供目录列表。`staticDir` 未配置时所有 GET 一律 404。
- listener 暴露结构化实际绑定信息：`boundPort?: number`（`port:0` 由 OS 分配后必须可取得真实端口，URL 与 status 不得使用 0）；`address` 字符串仅作人类可读展示，不做解析契约。
- listener 主动关闭（`close()`）对已建立的 WS 连接使用 close code `1001`（going away）与 reason 字符串 `server shutdown`；web 端将该组合识别为宿主终止态、停止自动重试（见 C4）。
- 同属 D1 范围的 `packages/server` 公开 API 扩展（协议 schema 仍零改动，D2 评审冲突 1/2 的裁定）：
  - `PiServer.removeSession(id)`：对该 id 的 live session 向全部已 attach 连接发送既有 `session_removed` 事件变体（`protocol/src/schemas.ts:407-410`）、解除各连接 attach、unsubscribe、等待 in-flight `operationCount` 收敛后 dispose runtime 并从 liveSessions 移除。宿主在 TUI 会话替换时调用；不存在该 id 时为幂等 no-op。
  - `PiServer.sessionParticipantCount(id)`：只读方法，返回已 attach 到该 session 的已握手连接数（participants 定义；不含仅完成 HTTP upgrade 的连接）。
- 认证约定：仅 `GET /ws/<token>` 可 upgrade；token 恒时比较（`crypto.timingSafeEqual`）；失败返回 401（upgrade 前 HTTP 响应）。成功后的连接交给 `accept`，协议握手（hello/version）由 `PiServer` 既有逻辑完成，**不改 `pi-protocol` 任何 schema**。
- 绑定地址由调用方传入；本 transport 不读取任何配置文件/环境变量。

### C2 token 与 URL 格式（模块 D1/D2/D3 共同遵守）

- token：32 字节 `crypto.randomBytes` → base64url（43 字符）。每次 `/remote` start 重新生成；仅存 RemoteHostController 内存；`/remote stop` 立即失效（关闭 server）。
- WS URL：`ws://<host>:<port>/ws/<token>`。
- 页面 URL（分享出去的链接）：`http://<host>:<port>/#<token>`。token 只出现在 fragment（不进 HTTP 请求字节、不进 server 日志）；页面 JS 从 `location.hash` 取 token 拼 WS URL。WS upgrade 请求中的 token 路径是已接受的暴露面（自托管直连场景）。
- 不做 view-only token（见 00 拍板记录）。

### C3 coding-agent 集成（模块 D2，归属 `packages/coding-agent`）

- 命令：`packages/coding-agent/src/commands/remote.ts`，注册入 `builtins.ts` 清单（对照 `shareCommand`，`builtins.ts:737` 模式）。
  - `/remote`（或 `/remote start`）：开启分享或幂等重显链接。默认绑定 `remote.host`（loopback 时仅显示本机链接 + "用 `/remote lan` 开启局域网访问"提示，不显示二维码——loopback QR 不可达，展示即误导）。
  - `/remote lan`：以 `0.0.0.0` 重启监听（旋转 token，旧链接立即失效），枚举 RFC1918 地址输出全部局域网链接 + 终端二维码（QR 取第一个候选；无 RFC1918 地址时不伪造，仅提示）。这是 E1 手机场景的一条命令路径，同时保持"监听全部网卡必须显式操作"的安全默认（D2 评审冲突 5 的裁定）。
  - `/remote stop`：停止并撤销 token。
  - `/remote status`：端口、会话、参与者数（来源 `PiServer.sessionParticipantCount`，见 C1）。
- 宿主：`packages/coding-agent/src/server/remote-host.ts` 导出 `RemoteHostController`：
  - `start()`：生成 token → 构造 `TuiSessionService` + `PiServer` + `createWebSocketListener` → 返回链接信息。
  - 会话视图：`TuiSessionService.listSessions()` 返回当前会话元数据；`openSession(id)` 返回 wrap 当前 `AgentSession` 的 runtime；id 不匹配当前会话即 `SessionNotFoundError`。不实现 `createSession`（抛 `PiServerError invalid_request`）。
  - `TuiSessionRuntime`：snapshot/prompt/steer/abort/setModel/setThinking/getPhase/subscribe 委托给 `AgentSession`，转换逻辑复用/提取自 `CodingAgentRuntime`（`coding-agent-server.ts:368-668`；该类当前未导出，允许最小改造为可复用，但不得改变 CodingAgentPiServer 现有行为）。**dispose() 必须是 detach 语义**：仅取消订阅与清理，绝不触碰 `AgentSession` 本体（PiServer 在无连接且 idle 时会 dispose runtime，`sessions.ts:387-408`；TUI 会话生命周期归 `AgentSessionRuntime`）。
  - 会话跟随：TUI 侧 `/new` `/resume` 等替换会话时（`agent-session-runtime.ts:117` `setRebindSession` 接线点，由 InteractiveMode 既有 rebind 回调显式通知），RemoteHostController 更新当前会话引用，并对旧 session id 调用 `PiServer.removeSession(id)`（见 C1；现状 PiServer 无发射链，此 API 为本设计新增）。已连接的 web 端收到 `session_removed` 后自行重新 list+attach 到新会话（效果 E6）。
- 生命周期：TUI 退出（SIGINT/SIGTERM/正常退出路径）时同步关闭 server 与端口（效果 E7）；重复 `/remote` 幂等重显链接；streaming 中允许开启/停止（不阻塞 turn）。
- settings（`packages/coding-agent/src/core/settings-manager.ts`，对照 ToolSearchSettings 模式 `settings-manager.ts:30-59`）：
  - `remote.host`：string，默认 `"127.0.0.1"`；`"0.0.0.0"` 表示监听全部网卡（局域网直连需用户显式开启）。
  - `remote.port`：number，默认 `0`（随机分配；固定端口便于隧道脚本）。
  - getter 校验回退模式对照 `getToolSearchEnabled()`（`settings-manager.ts:1139-1147`）。

### C4 web 客户端（模块 D3，源码归属 `packages/coding-agent/web/remote/`）

- 源码目录 `packages/coding-agent/web/remote/`（**在 `src/` 之外**，避免进入 tsgo 常规编译；入口 `index.html` + `src/main.ts`）。
- 构建：esbuild 单步打包（新增 script，如 `build:remote-web`），产物 `packages/coding-agent/dist/server/remote-web/`；`copy-assets` 与 `copy-binary-assets` 各增加对应复制行（binary 布局平铺 `dist/remote-web/`）。运行时 staticDir 解析必须同时兼容 npm dist 布局与 binary 布局（参照 export-html vendor 资源的运行时解析方式，设计时核实）。
- 传输：`WsByteTransport` 实现 `ByteTransportFactory`（`packages/client/src/transport.ts`）适配浏览器 `WebSocket`；直接依赖 workspace 包 `@earendil-works/pi-client`、`@earendil-works/pi-protocol`、`@earendil-works/pi-session-protocol`（若需 transcript 类型转换）。
- UI 能力（效果 E2/E3）：transcript 列表（user / assistant 含 thinking / tool 调用与结果 / summary 项）、流式增量（session_progress）、composer（idle→prompt；turn 中→steer；abort 按钮）、状态栏（phase/model/queued steer count）、断线重连（`PiClient.reconnect` + 重新 attach）、`session_removed` 后自动重新 list+attach 跟随会话切换。
- 终止态识别：WS close code `1001` + reason `server shutdown`（见 C1 listener.close 约定）显示"宿主已停止分享"并停止自动重试；其他 close 原因按普通断线处理（进入可重试恢复流程）。
- 兼容性目标：安卓 13 / MIUI 14 浏览器与桌面 Chrome/Firefox/Safari 最新版。**禁止 WebCrypto、HTTPS-only API**（局域网 http 必须可用）；ES2020 语法目标；移动端 viewport 与软键盘适配（composer 固定底部）。
- 不做：模型切换 UI（协议支持但 v1 不暴露）、extension 对话框应答（协议无 ui-request，见 §5）、主题系统（固定暗色即可）。

### C5 二维码

- `qrcode` npm 包（runtime 依赖，加入 coding-agent），终端半块字符渲染（`QRCode.toString(type: "terminal")` 或等价 UTF8 渲染）；与链接文本同时显示，二维码放不下时降级为纯链接文本（对照 omp `/collab` QR fallback 行为）。

## 4. 行为契约（全模块共同）

1. **协议零改动**：`pi-protocol` 不新增/修改任何 schema、命令、事件。web 端是纯参与者。
2. **单写者不打架**：TUI 与 web 并发 prompt/steer 都通过 `AgentSession` 既有队列语义（具体排队/steer 行为由 D2 以 `agent-session.ts` 证据写明；两端口感一致，不允许 web 端私设策略）。
3. **不承诺 exactly-once / 事件回放**：断线恢复 = 重新 attach + 全量 snapshot（`client` README 既有语义；`browser-session-collaboration/01` §2.1 同样结论）。
4. **快照大小限制**：attach 快照受 `DEFAULT_MAX_FRAME_LENGTH`（16MB，`protocol/src/framing.ts:9`）约束；超长会话 attach 失败为 v1 已知限制，不静默截断。
5. **安全默认**：默认绑定 `127.0.0.1`；任何网卡监听必须用户显式配置；token 恒时比较；静态服务禁目录列表、防路径穿越。

## 5. 非目标（v1 明确不做）

- relay / 公网中继 / NAT 穿透（隧道由用户自配）
- view-only 链接、多级别权限
- 多参与者协调提示（多个浏览器同时连允许，但无参与者名单 UI）
- extension select/editor 对话框在 web 端应答（协议无此事件；对话框仍由 TUI 回答）
- 子代理面板、transcript 树导航、`/model` 等 host-only 操作
- 会话创建（web 端只能 attach host 当前会话）
