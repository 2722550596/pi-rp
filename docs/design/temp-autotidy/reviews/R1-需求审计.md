## §2 哨兵专查

### E2 上下文零污染——PASS，未发现任何泄漏路径

逐路径排查：

1. **tidy LLM 对话本体**：只存在于 runner 内存 `AgentContext`（01 §3.2 R6，`messages: []` 起步）。LLM 调用经 `sideStreamFn` → `RequestGateway.streamSimple`（request-gateway.ts:130 实读，五参签名与 agent-session.ts:4522-4526 现有调用形状吻合）直连传输层，不经 SessionManager、不落 session 树。**transcript：无接触。**
2. **raw_log**：raw_log 唯一写入点 = module.onTurnEnd 从 `host.getTurnMessages()` 批量 append（module.ts:770-776 实读）。tidy 不产生角色 turn、不调 onTurnEnd 写路径。**raw_log：无接触。**
3. **autoretain 消费面**：autoretain 消费 raw_log 于角色 turn 末（同上路径）；tidy 对话不在 raw_log，永不被消费。**autoretain：无接触。**
4. **传输层不阻塞**：gateway priority 0（"Larger value = higher priority. 2=main loop, 1=compaction, 0=subagent"，request-gateway.ts:22-23 实读），02 §3.A.2 的让路论证成立；未配门时不门控（:29-33 注释实读吻合）。
5. **简报/失败通知是唯一角色可见产物**：经 `sendCustomMessage` 落 custom_message，属 E4/D1 的**设计内交付**而非 tidy 对话泄漏；compaction:exclude（module.ts:704-707）防其被压缩进长期上下文，500 字符上限防常驻负载膨胀（01 §2.4）。triggerTurn:false 的两条引擎路径实读核实：流式中不 steer（`options?.triggerTurn !== false` 门，:2901）、排队至 turn_end 后 flush——**不会把简报插进当前 turn 的 LLM 上下文中间**。
6. **历史污染源已绝**：D10 否决 runSubagent 的唯一污染路径（子会话无条件挂 memory module）经源码坐实（:4765-4766），改道后该向量不存在。
7. 事件面 `model` 字段显示占位 stub——纯观测噪声，01 §5 已立"落账以 tidyCtx.modelId 为准"的禁令。

### E7 简报风格——PASS，是可执行的具体禁令

03 T1 落实为：①五类禁令逐类列出**触发短语**（"好了，完成了""整理完毕！""这是简报""以下是本次整理的报告""希望对您有帮助"/"接下来我将""让我先看看""经过判断"…/道歉自评类/禁问句/禁抒情调侃）；②正向要求（第 1 行直接是固定格式总览 `TEMP 整理：<N> 条 → 归位 X、合并 Y、删除 Z、未处理 W；TEMP 余 R`）；③六个动词限定 + 每行格式模板；④**总检验法**（"把任何一行删掉，简报若不缺信息，这一行就不该存在"）——模型可自检的判据。配套：静态测试断言禁令段存在（03 §9.2-2）、快照防顺手改文案（§9.2-3）、真模型冒烟检查单（§9 行为验收，执行责任契约 §7-03-3 已裁）。这不是一句"保持直接"，是硬约束 §5.1 的完整可执行化。

### E8 TEMP 通用性——PASS（附 V-1 修正令）

- 03 T1 草稿定性段明文"可能是一切：反思、便签、转述、设定、清单、半截话……禁止对内容类型做任何假设"，"反思"仅作为可能性枚举出现，非假设；五步判断框架标注"与主题无关"，各步（读懂→过时判定→查重→归位→两可裁决）对购物清单/设定/代码片段同构成立；无任何"self-reflection 专属"表述。
- S12 的 set_time/awaken 禁令是**工具职能**划界，非内容类型假设。
- 机制侧配套：{temp_list} 底册全量直出 + N1-N4 导航修复保证任意类目/任意深度草稿可见。
- **但**：03 §2.2 给 {temp_list} supplier 的口径写反了（偏差 V-1）——按 03 版本实现会破 E8 的跨会话清理，必须按 01/02 的全库口径回写 03。

### D3 覆写自由——PASS，两字段机制真实支撑"完全别的哲学"

- **使命整体可换**：使命表述（清到零哲学）整体住 taskPrompt（03 §2.3/§3.3），覆写即换使命；systemPrompt 连判断框架、行为守则、简报规范一起让位。换哲学 ≠ 只换措辞：覆写 taskPrompt 为"归纳成周报不清空"（03 §3.3 原例）或彻底换掉两字段（推荐组合已给出），机制上无任何引擎强制拼接的残留——01 §3.1 T3 是字段级替换，不是叠加。
- **"甚至也可以不清空"有真实语义支撑**：01 §3.1 ①分支——tidy 完成未清零 → 简报照发 + hysteresis 不重触发，明确以 D3 为依据论证（否则不清空型使命每代死循环烧 token）。非清空使命"每积压代只跑一次"是文档化的既定语义，不是缺陷。
- **观察 O-1（低）**：默认 systemPrompt 框架内嵌删除倾向默认值（"纯过程性碎语 → 删""残渣 → 删"），只覆写 taskPrompt 为"不删除"型使命时会收到混合信号。03 §3.3 已声明这是刻意的安全底线设计，且 D3 原话只要求"留位置支持自定义"（机制自由，已满足）。可选改进：03 可考虑一句"删除类默认取舍让位于任务书使命"的从属声明（注意不可让安全底线 S3/S12 一并被覆盖），不构成门槛项。

### E9 可关闭——PASS（附 V-6 边界申报）
