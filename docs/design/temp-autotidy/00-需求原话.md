## 2. 效果清单（用户要的功能效果；注释，非原文）

| # | 效果 | 验收口径 |
|---|---|---|
| E1 | TEMP 积压到阈值时**自动**触发整理，不需要角色 agent 主动执行任何动作 | 阈值到达后整理发生，全程无角色 turn 参与 |
| E2 | 整理**异步**执行：不打断角色当前对话、不阻塞回合循环、不污染角色上下文 | 角色回合内触发整理时，角色无感；整理对话不进入角色 transcript/raw_log |
| E3 | 角色 agent 无记忆工具（纯只读 preset）的场景也能完成整理 | tools.allow 不含记忆工具的 preset，其会话的 TEMP 照样被自动整理 |
| E4 | 角色**可感知**整理结果：简报告知记忆发生了什么变化 | 整理完成后角色会话收到简报（下 turn 自然可见，不唤醒新 turn） |
| E5 | 整理使命可由 preset 作者**自定义**——不一定清空 TEMP，甚至可以不清空 | preset 字段可整体覆写 tidy 提示词，机制与 compaction 提示词覆写同惯例 |
| E6 | 整理失败有兜底：手动通知路径保留 | tidy 失败/禁用/未配置时，现有 rp-notify 手动通知照发 |
| E7 | 简报语言**直接**：无"好了，完成了""这是简报"类过渡性废话 | 默认提示词含明确的简报风格禁令；实测主流模型输出无碎碎念 |
| E8 | TEMP 被当作**通用缓冲区**对待：整理 agent 必须处理任意类型的草稿，不做内容类型假设 | 提示词的判断框架对任意主题草稿均成立；不出现"self-reflection 专属"假设 |
| E9 | 自动整理是**可配置选项**（"加入自动整理的选项"），非不可关的强制行为 | settings 可整体关闭，关闭后行为与现状完全一致 |
| E10 | agent 能从公开工具面发现并读取 audit 全文；“全文落 audit”不能成为只有数据库/Web 可见的死路 | `recall` 暴露只读 audit 系统视图；截断通知携带精确审计 URI，agent 可直接调用并取回该条完整简报 |

**实现路线改道留痕（主代理调研中的解法内部迭代，非用户改道）**：

- 初选 `runSubagent`/`spawnAgent` 复用引擎 → **前提失效**：AgentSession runtime build **无条件**挂 memory module（agent-session.ts:4765-4766 无 guard），子会话解析到同一 memory.db（PI_MEMORY_DB/settings 继承）→ tidy 整理对话会写进角色 raw_log、触发自己的 autoretain，双重污染；除非侵入引擎加禁用开关。
- 改选 memory 包内 `TidyRunner`（agentLoop 驱动）+ host 注入 `StreamFn`：零 AgentSession、零污染、headless 依赖方向不破坏（pi-agent-core 本就是 memory 依赖）。**此改道是解法层迭代，效果清单不变**；已按效果对齐纪律在此留痕，评审门的功能本质审计仍需独立验证"LLM agent 是本质需求还是过度设计"。
