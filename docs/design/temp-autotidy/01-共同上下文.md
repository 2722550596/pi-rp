## §2 冻结契约（共享形状——各设计文档 MUST 原样引用，MUST NOT 改名/改形）

### §2.1 settings schema（`settings.memory.temp.autoTidy`）

```jsonc
"memory": {
  "temp": {
    "threshold": 10,              // 既有字段，不动（temp-notify.ts:15-17）
    "autoTidy": {
      "enabled": true,            // 缺省 true（D5）
      "model": "provider/model",  // 可选；缺省 → 会话主模型（D5）；解析在 host 侧
      "maxTurns": 30,             // 可选；agentLoop 轮数上限（缺省值由 01 定，须写明依据）
      "timeoutMs": 600000         // 可选；总超时（缺省值由 01 定，须写明依据）
    }
  }
}
```

解析容错：非法值（负数/非字符串 model）→ 01 文档定义降级行为（倾向：字段级忽略 + 缺省，不 fatal——整理是旁路功能，绝不因配置错误阻塞主会话）。

### §2.2 preset 提示词覆写（**已定稿，2026-09-30 DesignHostSide 广播，主代理确认冻结**）

- 机制锚点：**`hiddenOverrides.tempTidy`**（与 `hiddenOverrides.compaction` 同级同惯例，loader.ts:233-239 为参照）。
- **字段切分（冻结）**：

```jsonc
"tempTidy": {
  "systemPrompt": "...",  // tidy agent 人格/持久规则/简报风格禁令（E7/D7/D8 落点）
  "taskPrompt": "..."     // 一次性任务模板 = 使命表述 + {temp_list} 变量（D3/E5 落点）
}
```

  切分依据：**字段数 = LLM 调用面数**——tidy 恰好两面（`AgentContext.systemPrompt` + agentLoop 首条 user 消息），compaction 五字段对应其五个调用面，照此惯例不加不减。
  缺省行为：字段缺省/非字符串/**空白串** → 字段级落内置默认（对 compaction 的刻意收紧：tidy 无人在环，空白串不留白）。两字段全缺省 = 完全内置行为。
- 覆写值传递通路（**已定稿**）：`MemoryModuleHost` 新增 **pull 模型 getter `getTempTidyPromptOverrides()`**（host 活读 `_activePreset`）。理由：`setActivePreset` 同 dbPath 切换不触发 runtime rebuild（agent-session.ts:2292-2305），push 模型会送旧值。
- 模板变量机制：与 compaction `{conversation}` 同惯例——module 侧运行时 plain regex replace（compaction.ts:713-717 先例），不经 preset 宏引擎。变量语义表归 03。

### §2.3 MemoryModuleHost 新增原语（02 实现、01 消费）（**修订 v2：R3 审计裁决，废除 TIDY_MODEL_STUB 占位模型**）

```ts
sideStreamFn(options: {

  modelRef?: string;

}): Promise<{ streamFn: StreamFn; model: Model<any> }>;
// StreamFn = pi-agent-core 类型（packages/agent/src/types.ts:28-33）；model 为 host 解析后的实例，
// 01 直接填 AgentLoopConfig.model —— 消除"占位模型"类型谎言（R3 审计：更简替代存在，采纳）。
```

### §2.4 简报投递通道

- `host.sendCustomMessage` 需支持 options 透传：现签名 `sendCustomMessage(message)` 单参（module.ts MemoryModuleHost），02 将其扩为 `(message, options?: { triggerTurn?: boolean })` 并改造 agent-session.ts:5033-5035 的绑定（现硬编码 `triggerTurn: true`）。
- 简报消息规格：`customType: "rp-notify"`、`display: false`、**`triggerTurn: false`**（D9）、`details: { kind: "temp-tidy-report", ... }`。
- content = tidy 最终 assistant 文本（提取规则见 §2.6）；长度上限由 01 定（建议 500 字符截断，写明依据）。

### §2.5 tidy 工具上下文（tidyCtx）

```ts
{
  modelId: "temp-tidy",   // 落 audit 的 editor_model / 修订史 editor_model——天然可辨
  sessionId: undefined,   // 无 → recall 可见性无 foreign 过滤，全库可见
  leafId: undefined,      // 无 → provenance 不盖锚（tools.ts:698-699 双真条件）→ 节点分支无关，全会话可见
  turn: undefined,
}
```

工具实例：`createMemoryTools(store, tidyCtx)` 独立构造（tools.ts 闭包捕获 ctx 参数），**不经** synthetic extension / host.getSessionInfo。ToolDefinition → pi-agent-core `AgentTool` 的转换 adapter 由 01 文档设计（types.ts:427）。

### §2.6 简报提取规则

agentLoop 终态 `AgentMessage[]` 中**最后一条 assistant 消息的 text**（拼接全部 text block）。空/缺失 → 视为整理失败（走 D1 兜底）。01 文档细化边界（如最后 assistant 只有 toolCall 无文本时的回看规则）。

### §2.7 跨进程互斥锁

- 存储：`memory_kv` 表，key = **`"temp-tidy-lock"`**，value = JSON `{ startedAt, heartbeatAt, pid?, sessionHint? }`。
- 协议：抢锁 = 原子"不存在或 heartbeatAt 已僵死才写入"；持锁期周期刷 heartbeat；结束（成功/失败）删锁。心跳周期与僵死阈值由 01 定（建议 30s / 5min）。
- 抢锁失败 → 本次触发静默放弃（他人在整理），**不**发手动通知。

### §2.8 触发接线（01 设计，现状锚点）

- 现状：module.ts:643-647，`checkTempThreshold` 命中 → `tempNotified = true` + `host.sendCustomMessage`。
- 改造方向：命中时先查 `autoTidy.enabled` → 抢锁 → 抢到则 fire-and-forget 起 TidyRunner（`void` promise，模式同 agent-session.ts:1191）。三分支语义（**修订 v2：R2-F7 消歧，本条为准**）：**未启用** → 现有 rp-notify 手动通知（现状路径）；**抢锁失败** → 静默（他人在整理，§2.7；不发通知）；**抢锁后执行失败** → 按 D1 兜底走手动通知。滞后标志（`tempNotified`）与 tidy 生命周期的联动语义由 01 文档定义（须回答：tidy 在跑时新写入再超阈值怎么办；tidy 完成未清零怎么办）。

### §2.9 TEMP 活跃草稿清单直出（{temp_list}）+ 导航缺陷必修（**修订 v2，2026-09-30 明月拍板**）

**背景（DesignPromptSide 实测发现）**：现状**没有任何工具能列全 TEMP 活跃草稿**——
1. `recall(uri="TEMP://")` 失败：TEMP:// 域根不存在（store.put 祖先补占位只建到第一级，永不建域根本身，store.ts:477-481）；
2. stub 类目下子节点不渲染（tools.ts:311 stub 早退在子树渲染之前）；
3. `MEM://index/TEMP` 只列 parent_id===null 且非 stub → 嵌于 stub 类目下的草稿（autoretain 草稿的常态）不可见；
4. `MEM://recent/<N>` 混全部 domain 且有截断。

**裁决（修订 v2，明月拍板推翻初版"绕过"方案）**：
- **导航缺陷属于严重 bug，必须修复，在本功能范围内完成**（初版"以 {temp_list} 绕过、缺陷另开任务"被明月否决："怎么可能会绕过啊，肯定是想办法补，这个是严重 bug"；"recall domain 甚至不会做到给遍历，这个漏洞太明显了"）。修复是**全库导航语义**问题（所有 domain 的 stub 类目皆受影响，非 TEMP 专属）：recall 的域级遍历能力、stub 节点的子树渲染顺序、域根节点的创建/等价机制——由 **01 文档新增设计职责**（§6 范围表已更新）。
- `{temp_list}` 直出**保留**：修复后它仍是 tidy 的确定性底册（省一轮 recall 遍历，且服务自定义 taskPrompt 的 preset 作者——覆写后模板仍可直接引用清单）。与修复不冲突：修复保库的基础导航能力（手动整理路径、角色自查都受益），直出保 tidy 的起手效率。03 模板中仍声明快照陈旧兜底指令。
- `MEM://index/<domain>` 的可见性口径（只列顶层）是否同步修，由 01 文档在导航语义设计里一并回答。
