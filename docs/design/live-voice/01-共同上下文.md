# live-voice 共同上下文（冻结契约）

> 本文是 `docs/design/live-voice/` 下所有模块设计的共享地基。设计代理 MUST 阅读 `00-需求原话.md` §1，并逐条引用原文消息；各设计文档 MUST 遵守本文的事件、字段、状态和数据口径，MUST NOT 私自改名或改形。若发现本文错误，先在本模块文档的「冲突与待拍板」节举证，由主代理统一裁决回写。

## §0 权威层级

1. `00-需求原话.md` §1：用户原话与用户明确补充，是需求最高裁决依据。
2. 本文：访谈裁定、跨模块契约和已核验事实。

4. 实现和注释。

低层与高层冲突时按高层；发现需求本身矛盾时停止实现并回到用户确认，不能靠实现替用户裁决。

## §1 范围与部署

- 项目仓库：`~/projects/pi-rp`；当前全局 `pi` 命令解析到 `packages/coding-agent/dist/cli.js`（本机 `readlink -f "$(command -v pi)"` 实测）。核心 API 改动落在本仓；语音扩展安装在 `~/.pi/agent/extensions/live-voice/`，全局对所有项目可见。
- Pi 扩展使用 TypeScript；全局目录和 `/live` 命令注册是现有能力：`packages/coding-agent/docs/extensions.md:7,93-99,109-120`。
- 语音只支持交互式 TUI：`ctx.mode === "tui"`；RPC、JSON、print 模式不可启动本机音频。现有 mode 说明见 `packages/coding-agent/docs/extensions.md:967-973,3039-3047`。
- `/live` 是 toggle。Pi/会话启动、恢复、扩展 reload 后一律关闭；不持久化 live-on。关闭 live 关闭本地采样。
- `/live` 关闭边界：停止音频采集和本地模型、取消/丢弃尚未提交的录音与 voice API 请求、停止 TTS 播放；异步回调必须受本轮 generation/AbortSignal 保护，关闭后不得再发送 user 消息或播音。已经调用 `pi.sendUserMessage` 的 Pi 轮次继续运行，文本保留，不再 TTS。

## §2 状态机（跨模块统一命名）

状态名是可观察状态/状态栏口径，不强制实现为互斥单枚举：Pi 任务的 `piBusy` 与语音输出队列/worker 可并行；TTS 期间 Pi 仍可处理 queued follow-up。麦克风 gate 必须按 §2.3 的联合条件执行。

| 状态 | 麦克风与工作 | 进入/离开条件 |
|---|---|---|
| `OFF` | 不采集，不运行 KWS/VAD，不播放音频；footer 清除 live 状态。 | 进程/会话启动默认态；`/live` → `ACTIVE_LISTENING`。 |
| `ACTIVE_LISTENING` | 本地 VAD 对麦克风帧做语音活动/句尾检测；远程 ASR 只在一句结束后接收该句音频。任何人声都会重置空闲计时，不做说话人识别。 | `/live` 开启，或 `WAKE_CUE` 完成，或 Pi 已 settled 且 TTS 队列清空 → 本态。句尾静默约 1.5 秒 → `INPUT_PROCESSING`；累计 30 秒无人声 → `WAKE_STANDBY`。 |
| `INPUT_PROCESSING` | 当前句音频已冻结在内存；远程 ASR 得到粗文本，再由独立 LLM 按 transcript 指令结合上下文改写；不采新音频。 | `ACTIVE_LISTENING` 结束一句 → 本态。有效文本调用 `pi.sendUserMessage` 后 → `PI_TURN`；Pi 若已忙则用 `deliverAs:"followUp"`；空文本/失败提示用户并回 `ACTIVE_LISTENING`。 |
| `PI_TURN` | `piBusy=true`，等待当前 Pi 队列（工具、重试、压缩、follow-up）处理；不采新音频。可与 `SPEECH_PREPARATION`/`SPEAKING` 重叠。 | user 消息触发 `agent_start` → 忙；每条合格的 assistant `turn_end` 立即加入 speech queue；`agent_settled` 只清除 `piBusy`，不触发 TTS。Pi settled 且 speech queue/worker 都空时才可恢复 ASR。 |
| `SPEECH_PREPARATION` | 串行处理 speech queue 头部：保留 Pi 原文，远程 LLM 生成独立口语稿，再远程 TTS 生成音频；不采新音频。可与 Pi 继续处理 follow-up 并行。 | 收到合格 assistant `turn_end` 入队后尽快开始；当前项成功 → `SPEAKING`；失败提示并丢弃该项，再处理下一项。 |
| `SPEAKING` | 按 assistant 回复生成顺序播放一个 TTS 项；麦克风暂停；不支持语音插话或输出重叠。 | 当前音频结束：若队列仍有项 → `SPEECH_PREPARATION`；若 Pi 仍忙 → 保持不采音并显示 `PI_TURN`；只有 Pi settled 且队列为空才回 `ACTIVE_LISTENING` 并重置 30 秒。 |
| `WAKE_STANDBY` | 只保留本地 KWS 的麦克风采样，不运行远程 ASR、不向云端上传待机音频、不保存录音文件。 | `ACTIVE_LISTENING` 连续 30 秒无人声 → 本态；本地命中唤醒词“话说” → `WAKE_CUE`。 |
| `WAKE_CUE` | 播放短、低音量本地提示音；忽略提示音期间的麦克风帧，避免把提示音收进请求。 | KWS 命中后进入；提示音播放完毕 → `ACTIVE_LISTENING`，此后才收新语句。 |

### §2.1 计时与活动判定

- 默认 `idleToStandbyMs = 30_000`、`utteranceEndSilenceMs = 1_500`；二者通过现有 per-extension 全局 settings API 持久化并可调，不按 preset 分开。能力证据：`packages/coding-agent/src/core/extensions/types.ts:343-352`。
- 30 秒只在 `ACTIVE_LISTENING` 累计。输入处理、Pi 生成、口语稿/TTS 队列处理及播报期间暂停；只有 Pi settled 且所有口语稿/TTS 工作清空、状态回到 `ACTIVE_LISTENING` 时，才重新给完整 30 秒。
- VAD 只区分人声/非人声，不区分说话人。旁人、电视或其他环境人声在 active listening 状态下同样可能结束成一个句子并成为 Pi 输入；这是用户接受的行为，`/live` 是总开关。
- 提示音只在从 `WAKE_STANDBY` 唤醒时播放；`/live` 手动开启用 footer 确认。

### §2.2 状态反馈与失败出口

- 用 `ctx.ui.setStatus("live-voice", ...)` 更新 footer，不把状态变化写进聊天 transcript。状态至少区分：`ACTIVE_LISTENING`、`WAKE_STANDBY`、`INPUT_PROCESSING`、`PI_TURN`、`SPEECH_PREPARATION`、`SPEAKING`；`OFF` 清除状态。API 与状态 API 证据：`packages/coding-agent/docs/extensions.md:166-168,2700-2702`。
- ASR 或 transcript 后处理无有效文字：不发空 user message，提示“没听清/本句未处理，请重说”，回 `ACTIVE_LISTENING`。
- ASR、两种 LLM 后处理或 TTS 请求失败：不自动重试，不伪造文本/音频 fallback；显示具体阶段错误并保持 live。输入阶段未提交的句子丢弃，用户可重说；某个 TTS 队列项失败时丢弃该项并继续后续项，不改变 Pi 原文；麦克风仍须等 Pi settled 且语音队列清空后才能恢复。
- `/live` 关闭、session shutdown 或扩展 reload 都走同一清理路径；不得留下录音子进程、TTS 播放进程或会在之后提交的旧请求。

### §2.3 Pi 与 TTS 并行时的联合采音规则

- 每条合格的 assistant `turn_end` 都向 FIFO speech queue 加一项，携带原文快照及其源 user turn 的 voice-config 快照；唯一 TTS worker 在事件 handler 返回后立即处理队首，先做 spoken rewrite 再 TTS/播放。不得等整个 Pi 队列 settled，也不得并发播放多个条目。
- `agent_settled` 仅将 `piBusy` 清为 false；若 TTS worker 或 speech queue 仍有工作，继续播报但保持麦克风暂停。若 TTS 项已播完而 `piBusy` 仍为 true，仍保持麦克风暂停，不插入 ASR。
- 仅当 live 仍开启、输入 API 不忙、`piBusy === false`、speech queue 为空且无 rewrite/TTS/播放工作时，才进入 `ACTIVE_LISTENING` 并重置 30 秒计时。这样既尽快播出每条答复，又不在答复间隔漏收用户语音。

## §3 本地音频与模型边界

- 当前工作环境为 WSL2/Linux；本机 `pactl list short sources` 实测 `RDPSource`（44.1 kHz、单声道），`pactl list short sinks` 实测 `RDPSink`（44.1 kHz、双声道），`/mnt/wslg/PulseServer` socket 存在；`parec`、`paplay`、`pactl`、`ffplay` 均在 PATH。设计目标采用默认 PulseAudio source/sink，进入 Sherpa 采样率时显式重采样。
- 用户已选本地关键词模型。Sherpa-ONNX Node 流式 KWS/中文模型及自定义关键词的官方入口：<https://k2-fsa.github.io/sherpa/onnx/javascript-api/examples/keyword_spotter.html>、<https://k2-fsa.github.io/sherpa/onnx/kws/>；Node VAD 示例：<https://k2-fsa.github.io/sherpa/onnx/javascript-api/examples/vad_microphone.html>。它是实现候选；“话说”的真实误唤醒率、RDPSource 音质、CPU/内存仍须在当前机器 smoke 验证，不能把官方接口示例当实机验证。
- 本地处理限于音频输入输出、VAD 和待机 KWS。ASR、用户文本 LLM 改写、assistant 口语稿 LLM 改写、TTS 均是远程 API。待机音频不得上传；原始音频只保存在当前进程内存，不写本地音频文件。
- 不设计 Windows 原生、macOS、RPC 或 headless 音频。设备/音频命令不可用时 `/live` 必须报错并保持关闭，不得静默退化成键盘以外的假语音能力。

## §4 消息与事件契约

### §4.1 用户输入

1. 句尾 VAD 输出单句 PCM；`transcribeAudio(audio)` 由远程 ASR adapter 提供粗文本。
2. `rewriteTranscript({ rawTranscript, recentContext, instructions })` 由另一独立 LLM 请求生成自然 user 文本；它可以按上下文修正转写、重组口语，但不能凭空增加用户未表达的新请求。
3. 有效文本通过 `pi.sendUserMessage(text)` 发送，使用真实 user role；Pi idle 时正常发送，若 ASR/改写期间已有手动 Pi turn，则指定 `deliverAs: "followUp"` 排到该轮之后，不 steer/中断。后者的 session 顺序按实际送达顺序而非话语起始时间；这是用户确认的取舍。TUI 正常显示。API 证据：`packages/coding-agent/docs/extensions.md:1424-1452`。
4. live 开启期间，手动键入的 user 消息照常送入 Pi；它产生的最终 assistant 回复也 TTS。所有 Pi turn 和 TTS 工作期间暂停麦克风。

### §4.2 Assistant 回复

- `message_end` 会对 user、assistant、toolResult 消息触发，不能在该事件中逐条直接播音（`packages/coding-agent/docs/extensions.md:614-620`）。
- `turn_end` 每个 assistant turn（一次 LLM 回复及其工具调用）触发一次。遇到 `message.role === "assistant"`、`stopReason === "stop"`、含可见文本且无 toolCall 的完成答复时，立即把原文快照加入唯一串行 TTS 队列，开始 LLM 口语改写；不等整个 Pi 队列 settled。工具调用 turn、空文本、`error`/`aborted`/`deferred` 不播；`length` 不立即播，若后续自动 continuation 产生正常 stop 回复则只播正常 stop 回复，若整个 agent 最终 settled 仍没有正常 stop 回复则保留原文但不合成不完整片段。事件/字段证据：`packages/coding-agent/docs/extensions.md:600-612`、`packages/coding-agent/src/core/extensions/types.ts:867-872`、`packages/ai/src/types.ts:393,431`。
- `agent_settled` 只表示 Pi 不再自动重试、压缩或消费 queued follow-up；它只清 `piBusy`，不是 TTS 触发器。若 Pi settled 时 TTS 队列未空，继续按序处理；若某个 TTS 播完但 Pi 仍忙，麦克风保持暂停。仅当 Pi idle 且队列/worker 均空时恢复 `ACTIVE_LISTENING`。证据：`packages/coding-agent/docs/extensions.md:584-612`。
- TTS 队列单 worker，口语稿生成与音频播放按 assistant 答复完成顺序串行；不重叠播放，不在两条 TTS 之间短暂恢复收音。live 开启期间手动键入和语音输入对应的每条正常最终 assistant 回复均进入队列。
- 原 assistant message 保持不变。回复 LLM 的结果只作为 TTS 输入，不替换 Pi transcript 或后续 Pi 对话上下文。

## §5 后处理上下文与两组指令

- “轮”按当前 session branch 中实际送达顺序定义：一条 user message 及其后到下一条 user message 之前的可见 assistant 文本/工具活动为一轮；取最近 4 轮，另加当前待处理原文。
- 允许加入简洁工具活动标签，如 `[tool_call: read <path>]`；只说明工具与短目标，不带 tool result。不得把 shell 完整命令、工具输出、隐藏思考、system prompt、AGENTS/技能文件、图片或附件发送给后处理 API。
- 角色指令从活动 preset 的扩展命名空间读取；不读取/转发整份 Pi system prompt。输入与输出任务使用两份互不混用的指令：
  - transcript instructions：结合近 4 轮自然修正 ASR 文本，尽可能保留用户原意与本轮语言，只输出将被发送为 user message 的文本。
  - spoken-reply instructions：对最终 assistant 原文生成适合角色播报的口语稿。短回复基本保留；长回复按内容压缩到约 2–4 句；代码/表格/长列表改成简要口头概括，细节留在屏幕。可加入少量人设语气，不得新增事实、决定或承诺。
- ASR 改写语言跟随本轮用户语音；TTS 语言跟随 assistant 原回复，除非该 preset 指令明确要求切换语言。
- preset 可提供 provider-neutral `ttsProfile`，具体 profile 到服务商 voice ID 的映射留待 API 接线阶段。

## §6 preset 扩展元数据契约

### §6.1 JSON 形状

```jsonc
{
  "extensions": {
    "live-voice": {
      "transcriptInstructions": "...",
      "spokenReplyInstructions": "...",
      "ttsProfile": "..."
    }
  }
}
```

- 只保留 `extensions` 顶层命名空间；不把任意未知 preset 顶层字段一律吞下，以免拼写错误静默通过。
- `PromptPreset.extensions` 是 namespace → JSON object 的通用映射。loader 对非法顶层 `extensions` 容器或非对象 namespace 追加 `warning` 并只忽略对应容器/namespace，不使整个 preset 加载失败；其他有效 namespace 与其中未知字段原样保留。每个插件自行验证自己的子结构。此字段只承载扩展私有元数据，不参与核心 prompt 渲染。
- 在 `ExtensionContext` 增加通用只读接口（**NEW**）：

```ts
getActivePresetExtensionData(
  namespace: string,
): Readonly<Record<string, unknown>> | undefined;
```

- 返回当前 session 经全局/项目覆盖规则解析后真正生效 preset 中的 namespace 数据；缺 preset/缺 namespace 时返回 `undefined`。不得要求扩展再次扫描目录或复制 preset 优先级逻辑。项目 preset 同 ID 覆盖全局 preset，依据 `packages/coding-agent/docs/prompt-presets.md:7-12`。
- 每个逻辑 user turn 在接受输入时快照活动 preset 的 `extensions.live-voice`：语音输入在 transcript pipeline 开始时快照；键入输入在 Pi `input` 分发/入队前快照（包括 followUp）。该 user turn 引起的 transcript/assistant reply/TTS 一律复用同一快照；preset 在 turn 中途切换只影响之后接受的 user turn。多条 assistant final reply 属同一 user turn 时共用快照。
- `preset_activated` 当前只携带 `presetId`（`packages/coding-agent/src/core/extensions/types.ts:764-768`）；不把 voice-specific 字段塞入公共事件。扩展通过通用 getter 读取具体 metadata。
- 没有活动 preset 或无效/缺少 `extensions.live-voice` 时，使用扩展内置通用 transcript/spoken-reply 指令和全局 default TTS profile，不阻止 `/live`。

### §6.2 用户设置

- Extension ID / namespace：`live-voice`。
- 使用现有 `ctx.getExtensionSetting` / `ctx.setExtensionSetting` 保存全局 `idleToStandbyMs`、`utteranceEndSilenceMs` 及以后 provider mapping；不另建重复 settings 文件。

## §7 远程 API 接口边界与未决项

必须有且只有四个远程动作边界：

```ts
transcribeAudio(audio: AudioSegment, signal: AbortSignal): Promise<AsrText>;
rewriteTranscript(input: TranscriptRewriteInput, signal: AbortSignal): Promise<string>;
rewriteSpokenReply(input: SpokenReplyInput, signal: AbortSignal): Promise<string>;
synthesizeSpeech(input: SpeechSynthesisInput, signal: AbortSignal): Promise<AudioData>;
```

以上符号均为设计名，落地时按模块文档定型。用户明确把 API 请求接线留到最后；现在没有服务商、模型、认证配置或 request/response schema。设计代理不得编造端点、payload、key 名、服务商特性或响应格式。未提供真实接线前，不得声称语音 API 闭环已运行。

## §8 跨文档强制验收项

1. `/live` 默认 off；非 TUI 调用拒绝启动；状态 footer 与真实状态一致。
2. live on 立即主动听；30 秒活动静默只关闭远程 ASR/对话捕获，转为本地 KWS；live off 才彻底关麦。
3. 待机无云端音频请求；`话说` 触发 cue，cue 前后音频不混入 user clip。
4. 活跃态 1.5 秒人声静默提交单句；空/失败文本不发给 Pi；有效转写恰好以 user role 显示和入会话。
5. 每条合格的 assistant `turn_end` 答复立即且最多一次触发 FIFO TTS；不读 tool call/result/intermediate，Pi 原文不变。
6. TTS 项播完后若 Pi 仍 busy 或语音队列非空，不恢复录音；仅在 Pi settled 且队列/worker 空时恢复 ASR 并重置 30 秒。TTS 期间不收音、不接受 voice barge-in。
7. preset project/global 覆盖对 `extensions.live-voice` 与 preset 其他字段完全一致；preset 切换只影响之后的任务。
8. API 错误不重试、不伪造 fallback；关闭 live 后没有迟到消息、播放或残留进程。
9. API provider 接线未完成时，验收必须明确标出该外部依赖，不用 mocks/回声实现冒充真正 ASR、LLM 或 TTS。
