## 2. 效果清单（注释，非原文）

| 编号 | 用户要的效果 | 可观察验收口径 |
|---|---|---|
| E1 | 全局 Pi 扩展通过 `/live` 明确启停 | `/live` 在关闭与开启间切换；新进程/恢复会话默认关闭；仅交互式 TUI 使用。 |
| E2 | 两级监听：活跃 ASR 与待机唤醒 | 开启 live 立即进入 ASR 监听；30 秒无人声后停止远程 ASR，转为本地关键词待机；待机仍属于 live，不等于退出。 |
| E3 | 语音唤醒后有轻提示，再收新请求 | 待机检测到“话说”后播放短提示音；提示音结束后才开始新语句录制，唤醒词本身不进 ASR。 |
| E4 | 语音输入自然进入 Pi 当前会话 | 本地 VAD 以约 1.5 秒无人声结束单句；远程 ASR 粗转写、上下文 LLM 自然改写后，直接发送并在 TUI 显示实际 user 文本。空/不可用转写不发送。 |
| E5 | Pi 原有 assistant 回答同时保留屏幕文本与语音体验 | assistant 原回复不被替换；每个最终回复在 live 开启时另生成 TTS 口语稿并播放，包括文字输入触发的回复。 |
| E6 | 语音稿更适合角色对话与听觉接收 | 长回复按内容压缩为约 2–4 句；结构化内容以口头概括为主、细节留在屏幕；可加入少量角色语气，但不添加新事实、决定或承诺。 |
| E7 | 连续对话不必每轮重新唤醒 | 每条 assistant 答复完成即开始播报，但播报间隙不重新开麦；只有 Pi 完成所有 queued follow-up 且 TTS 队列清空后，ASR 才恢复并重新给完整 30 秒接话窗口。只有再经过 30 秒无人声才回到唤醒待机。 |
| E8 | 状态与取消结果明确 | footer 区显示 ASR 监听、唤醒待机、处理中、播报中；关闭 live 立即停止录音/播报并丢弃未提交语音，已发给 Pi 的轮次继续保留文字结果。 |
| E9 | 角色切换影响后处理风格与声音 | 当前活动 preset 的 `extensions` 命名空间配置供扩展读取；切换 preset 后下一轮应用新配置；缺配置使用通用默认。 |
| E10 | API 慢速不纳入当前优化，失败仍有出口 | ASR/两个 LLM 后处理/TTS 均走远程 API；当前阶段不臆造服务商请求。请求失败不自动重试，保持 live 并提示重说/查看屏幕。 |

## 3. 解法清单（提议方案及其能力前提，注释，非原文）

| 编号 | 解法提议 | 依赖前提 | 核查结果与证据 |
|---|---|---|---|
| S1 | 在 `~/.pi/agent/extensions/` 放全局 TypeScript 扩展，用 `/live` 命令控制 | Pi 提供全局扩展自动发现与命令注册 | ✅ `packages/coding-agent/docs/extensions.md:7,93-99,109-120` 明确支持全局目录与 `registerCommand`。 |
| S2 | 让待机期“闭麦”但仍可听唤醒词 | 物理麦克风关闭时仍能检测声音 | ❌ 前提不成立。完全关闭麦克风就无法听到唤醒词；必须在待机保留本地音频采样。裁定：待机停止对话录音与云端上传，但麦克风维持本地 KWS/VAD 监听；`/live` 关闭时才停止采样。 |
| S3 | 用本地模型实现中文唤醒词与语音活动检测 | Node 运行时有可用的中文关键词检测与 VAD；全局 WSL 环境能提供输入/输出设备 | ✅ Sherpa-ONNX 官方 JavaScript API 提供流式 KeywordSpotter、中文 WenetSpeech KWS 模型及自定义关键词格式（https://k2-fsa.github.io/sherpa/onnx/javascript-api/examples/keyword_spotter.html 与 https://k2-fsa.github.io/sherpa/onnx/kws/）；官方也提供 Node VAD 示例（https://k2-fsa.github.io/sherpa/onnx/javascript-api/examples/vad_microphone.html）。本机 `pactl list short sources/sinks` 实测见 `RDPSource` 与 `RDPSink`，`parec`/`paplay`/`ffplay` 可用。实际识别质量仍需真机验证。 |
| S4 | 把角色语音指令放进当前 preset，并让扩展读取 | loader 保留扩展元数据，扩展可取得“当前生效 preset”的数据 | ⚠️ 当前能力不完整。preset 目录及覆盖优先级已存在（`packages/coding-agent/docs/prompt-presets.md:7-12`），但 `PromptPreset` 没有扩展元数据字段（`packages/coding-agent/src/core/prompt-preset/types.ts:251-280`），loader 逐字段构造对象（`loader.ts:229-283`），未知字段会丢；`preset_activated` 事件只含 `presetId`（`extensions/types.ts:764-768`）。裁定：通用保留 `extensions` 命名空间，并加通用只读读取通道；不加 live-voice 专属核心字段。 |
| S5 | 把语音识别文本送到 Pi，播报完成的 assistant 答复 | Pi 扩展提供真正 user 消息 API 与稳定的最终答复事件 | ✅ `pi.sendUserMessage` 会创建正常 user 消息并触发回合（`packages/coding-agent/docs/extensions.md:1424-1452`）；实现需等整轮工具执行结束后只处理最终面向用户的 assistant 文本。 |
| S6 | 把计时参数保存为全局可调设置 | Pi 扩展提供持久化的扩展设置 API | ✅ `ExtensionContext.getExtensionSetting`/`setExtensionSetting` 会读取、写入全局扩展设置（`packages/coding-agent/src/core/extensions/types.ts:343-352`）。默认值：30 秒待机、1.5 秒句尾静默。 |
| S7 | 暂不连接服务商 API | 已有端点、凭证和各服务请求格式 | ❌ 尚未指定服务商/端点/凭证格式。按原话把真实网络接线留到最后；本设计只冻结四种调用契约，不虚构协议。 |

## 5. 仍不能冒充已知的事项（注释，非原文）

1. ASR、输入后处理 LLM、回复后处理 LLM、TTS 的服务商、模型名、认证方式、请求/响应 schema 均未指定；检查 `~/.pi/agent/models.json` 与 `settings.json`，未发现 speech/tts/transcription/audio/whisper/asr 服务配置。当前 `ARK_BASE_URL` 与 `BAIDU_BASE_URL` 指向路径分别为 `/api/coding/v3` 与 `/v2/coding` 的 coding endpoints，不是已有语音 API 规格；现有通用模型配置不能证明语音服务能力，实现阶段不得虚构。
2. Sherpa-ONNX 中文 KWS/VAD 在当前 RDPSource 麦克风上的实时识别率、CPU 占用、阈值仍需本机验证；官方文档只证明接口与模型能力，不证明“话说”的实际误唤醒率。
3. 本设计对 WSL2/Linux PulseAudio 的 `parec`/`paplay` 作当前目标；若要求 Windows 原生、macOS 或远程 RPC 音频支持，需另行设计，不能暗中声称已覆盖。
4. E9 的 `ttsProfile` 能否改变真实合成声音取决于尚未指定的 TTS provider 是否提供对应能力和映射；没有 provider/真实 smoke 前不得声称角色音色切换已验证。
