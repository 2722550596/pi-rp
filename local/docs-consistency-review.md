## Findings (severity: location — doc_claims → actual → suggested_fix)

F1 [medium] docs/rpc.md "### Session" section (no `#### navigate_tree` heading; between `reroll` L712-737 and `get_fork_messages` L739)
- doc_claims: rpc.md documents no navigate_tree command; the RPC dialect as documented ends session commands at reroll/get_entries/get_tree/get_last_assistant_text/set_session_name.
- actual: rpc-types.ts:69 declares `{ id?: string; type: "navigate_tree"; targetId: string }` and rpc-mode.ts:763-768 handles it, returning `{cancelled}` (cancellable by session_before_tree). Doc gap for an implemented, shipped RPC command.
- suggested_fix: add `#### navigate_tree` subsection: request `{"type":"navigate_tree","targetId":"<entryId>"}`, response `{"type":"response","command":"navigate_tree","success":true,"data":{"cancelled":false}}`, note it may be cancelled by a `session_before_tree` extension handler and that with `summarize` it attaches a branch summary.

F2 [medium] docs/rpc.md "### Event Types" table (L906-928)
- doc_claims: table lists 20 event types; none of the three new AgentSessionEvent members appear (only the reroll prose at L714 mentions leaf_changed inline).
- actual: rpc-mode.ts:381-382 subscribes to ALL session events and streams them via toJsonEvent (modes/json-event.ts:28-31 passes everything through except message_update). So RPC clients DO receive `leaf_changed` {newLeafId,oldLeafId}, `entry_edited` {entryId}, `preset_activated` {presetId} on stdout — undocumented streamed events.
- suggested_fix: add three table rows with payload notes; cross-link from reroll.

F3 [low] docs/rpc.md "#### get_commands" (L859-900)
- doc_claims: example item `{"name","description","source","path","location"}`; prose documents top-level `location` ("user"/"project"/"path") and top-level `path`.
- actual: RpcSlashCommand = `{name, description?, source, sourceInfo}` (rpc-types.ts:78-84); rpc-mode.ts:797-827 fills `sourceInfo: command.sourceInfo`; SourceInfo = `{path, source, scope: "user"|"project"|"temporary", origin: "package"|"top-level"}` (core/source-info.ts:6-11). Wire format has nested `sourceInfo`, `scope` values are "user"/"project"/"temporary" (no "path"), and no top-level `location`.
- suggested_fix: rewrite example + field list to the actual shape: `{name, description, source, sourceInfo: {path, source, scope, origin}}`.

F4 [low] docs/extensions.md "### Session Events" (L388-502)
- doc_claims: section documents session_start, session_info_changed, session_before_switch, session_before_fork, session_before_compact/session_compact, session_before_tree/session_tree, session_shutdown — no leaf_changed / entry_edited / preset_activated.
- actual: extensions/types.ts:673-689 defines LeafChangedEvent/EntryEditedEvent/PresetActivatedEvent and on() overloads at types.ts:1273-1275; agent-session.ts:698-704 mirrors them to the extension runner via _emitSessionEvent. Extensions CAN subscribe; zero doc coverage.
- suggested_fix: add three short subsections under Session Events documenting payloads and firing points (reroll/navigateTree → leaf_changed after state/schema restore; editMessage → entry_edited; setActivePreset → preset_activated).

F5 [info] docs/extensions.md "#### session_before_tree / session_tree" (L483-497)
- doc_claims: presents session_tree as the /tree navigation event with no transitional note.
- actual: navigateTree now emits leaf_changed (agent-session.ts:4077-4081) and then session_tree (extension-only); session_tree remains in ExtensionEvent (types.ts:664-669). CONTEXT.md carries the transitional wording ("session_tree stays during the transition"); extensions.md does not.
- suggested_fix: optionally note session_tree is extension-only and the session event stream (and TUI rebuild) uses leaf_changed. Not wrong as written — info level.
